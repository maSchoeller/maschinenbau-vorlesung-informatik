Werkzeugkasten

Heute neu in Python: Dateien und Ordner der Fertigungszelle FZ-3 suchen und lesen. Dafür gibt es das Modul pathlib mit Path, glob und rglob, dazu stat().st_size für die Dateigröße, read_text, das ältere Modul os (zum Lesen, denn es steckt in viel KI-Code) und time.perf_counter zum Messen der Laufzeit. Alle Karten arbeiten mit demselben Ordner zelle/: Er wird vor jedem Lauf frisch aus zelle.zip in den Arbeitsordner gelegt. Das Labor läuft in einer Sandbox im Browser: Es ist ein Linux-System, und der Ordner ist ein Übungsordner, nicht dein Rechner. Auf deinem eigenen Rechner zeigt der Task-Manager und der Explorer die echte Umgebung.

Merke

Diese sechs Syntax-Karten sind dein Spickzettel, bis es sitzt. Du erreichst sie in jeder Aufgabe über den Knopf „Werkzeugkasten“ oben. Alle Befehle des Kurses stehen außerdem rechts in der Befehls-Bibliothek. Führe jede Karte aus und lies die Ausgabe. Jede Karte hat ihren eigenen frischen Arbeitsordner mit zelle/.

Syntax-Karte 1

Pfade bauen und zerlegen

from pathlib import Path

zelle = Path("zelle")                                          # relativer Pfad: ab dem Arbeitsordner
log = zelle / "maschinen" / "D2" / "logs" / "2026-11-16.log"   # Teile mit / verbinden

print(log)                      # der ganze Pfad
print(log.name)                 # Dateiname mit Endung: 2026-11-16.log
print(log.stem)                 # Dateiname ohne Endung: 2026-11-16
print(log.suffix)               # die Endung mit Punkt: .log
print(log.parent)               # der Ordner darüber: .../D2/logs
print(log.parent.parent.name)   # zwei Ebenen höher, nur der Name: D2
  • Path("zelle") macht aus einem Text einen Pfad. Der Schrägstrich / verbindet Teile, auf jedem Betriebssystem. Rechnen mit Text ("zelle" / "maschinen") geht nicht: Mindestens ein Teil muss ein Path sein.
  • .name, .stem, .suffix und .parent sind keine Funktionen (keine Klammern). .parent liefert wieder einen Pfad, deshalb geht .parent.parent.
  • Ausgegeben wird unter Windows mit \, hier im Browser (Linux) mit /. Im Programm schreibst du trotzdem immer /.
Syntax-Karte 2

Ordner durchsuchen: iterdir, glob, rglob, sorted

from pathlib import Path

zelle = Path("zelle")

for eintrag in sorted(zelle.iterdir()):          # alles direkt in zelle/
    print(eintrag.name, eintrag.is_dir())

logs = sorted(zelle.glob("maschinen/*/logs/*.log"))     # * = beliebiger Text, genau eine Ebene
print(len(logs), "Log-Dateien, die erste:", logs[0].name)

nc = [p.name for p in sorted(zelle.rglob("*.nc"))]      # rglob = in allen Unterordnern
print(nc)
  • iterdir() liefert den Inhalt eines Ordners. glob("muster") liefert Treffer nach einem Muster: * steht für beliebigen Text innerhalb eines Namens, der Schrägstrich im Muster trennt Ordnerebenen. rglob("*.nc") sucht in allen Unterordnern (wie glob("**/*.nc")).
  • Die Ergebnisse kommen in keiner festgelegten Reihenfolge. Wer eine feste Reihenfolge braucht, schreibt sorted(...) davor: Es ordnet alphabetisch (Groß- und Kleinbuchstaben zählen auf Linux getrennt, Großbuchstaben zuerst; Windows ignoriert den Unterschied).
  • Wie in V09 sagt for … in „für jeden Treffer“. Möchtest du die Zahl der Treffer, zähle in der Schleife oder nimm len(list(...)).
Syntax-Karte 3

Prüfen, Größe, Inhalt lesen

from pathlib import Path

datei = Path("zelle/LIESMICH.txt")
print(datei.exists(), datei.is_file(), datei.is_dir())     # True True False
print(Path("zelle").is_dir(), Path("zelle/gibt-es-nicht.txt").exists())

groesse = datei.stat().st_size          # Größe in Bytes
print(groesse, "Bytes =", round(groesse / 1024, 2), "KiB")

text = datei.read_text(encoding="utf-8")
print(len(text.splitlines()), "Zeilen:")
print(text)
  • exists() fragt: „Gibt es das?“, is_file(): „Ist das eine Datei?“, is_dir(): „Ist das ein Ordner?“ Die Antwort ist True oder False. Prüfe das vor dem Öffnen, dann gibt es kein FileNotFoundError.
  • stat().st_size ist die Größe in Bytes. Durch 1024 teilen ergibt KiB, nicht durch 1000.
  • read_text(encoding="utf-8") liest die ganze Datei als einen Text (Kurzform von with open(…) und read()). Für große Dateien lieber zeilenweise mit with open wie in V09.
Syntax-Karte 4

Das ältere Modul os (zum Lesen)

import os

print(os.getcwd())                                # aktueller Arbeitsordner (hier: der Übungsordner im Browser)
print(sorted(os.listdir("zelle")))                # Namen im Ordner, als Textliste
print(os.path.join("zelle", "maschinen", "D2"))   # Pfadteile zu einem Text verbinden

for ordner, unterordner, dateien in os.walk("zelle/maschinen/D2"):   # läuft durch den ganzen Baum
    print(ordner, "enthält", len(dateien), "Dateien")
  • os ist die ältere Schreibweise. Du findest sie in vielen Beispielen und in KI-Code. os.listdir und os.path.join liefern Text, pathlib liefert Path-Objekte mit Methoden. Du musst os.path.join und os.walk nur lesen können.
  • os.walk(ordner) liefert für jeden Ordner im Baum ein Tripel: Pfad, Liste der Unterordner, Liste der Dateien. Das Entpacken in drei Namen kennst du aus V14.
  • os.getcwd() (englisch current working directory) zeigt den Arbeitsordner. Auf deinem Rechner steht dort ein echter Pfad wie C:\Users\….
Syntax-Karte 5

Laufzeit messen

import time
from pathlib import Path

zeiten = []
for versuch in range(5):                      # mehrmals messen: die Werte schwanken
    start = time.perf_counter()               # Stoppuhr starten (Sekunden als Kommazahl)
    anzahl = len(list(Path("zelle").rglob("*.log")))     # nur das messen, was du messen willst
    ende = time.perf_counter()
    zeiten.append(1000 * (ende - start))      # Sekunden mal 1000 = Millisekunden

print(anzahl, "Dateien gefunden")
print(f"schnellste {min(zeiten):.2f} ms, langsamste {max(zeiten):.2f} ms")
  • time.perf_counter() ist eine Stoppuhr: Der absolute Wert sagt nichts, nur die Differenz zweier Aufrufe ist die Laufzeit in Sekunden. Das ist etwas anderes als die Uhrzeit.
  • Die Werte schwanken von Lauf zu Lauf, weil das Betriebssystem zwischendurch andere Programme bedient. Deshalb mehrmals messen und den schnellsten Wert (min) nehmen. Der erste Lauf ist oft der langsamste.
  • Die Messung muss um genau den Teil stehen, den du vergleichen willst, nicht um die Ausgabe und nicht um das Einlesen von Eingaben.
Syntax-Karte 6

Der Rückstrich in Windows-Pfaden

print("C:\temp\neu")      # \t ist ein Tabulator, \n ein Zeilenumbruch: der Pfad ist kaputt
print(r"C:\temp\neu")     # r vor dem Text: der Rückstrich bleibt ein Rückstrich
print("C:\\temp\\neu")    # oder jeden Rückstrich verdoppeln
print("C:/temp/neu")      # oder besser: / benutzen, das versteht auch Windows
  • In normalen Texten leitet \ eine Sonderzeichen-Folge ein (\n kennst du aus V09). Ein Windows-Pfad aus dem Explorer enthält Rückstriche und bricht deshalb leicht.
  • Der beste Rat: relative Pfade mit / und Path. Dann läuft das Programm auf jedem Rechner. Ein fest eingetippter absoluter Pfad wie C:\Daten\zelle läuft nur auf dem Rechner, auf dem er stimmt.

Vorgerechnetes Beispiel: Logs der Zelle durchsuchen

Aufgabe: Auf dem Zellenrechner der Fertigungszelle FZ-3 liegt für jede Maschine (D2 Drehmaschine, F1 Fräsmaschine, R1 Roboter, M1 Messmaschine) und jeden Tag eine Log-Datei im Ordner zelle/maschinen/<Maschine>/logs/. Das Programm findet alle Logs, zählt je Maschine die Fehler (Stufe ERROR), nennt den ersten Fehler, summiert die Dateigrößen, listet die NC-Programme und misst, wie lange die Suche dauert. Lies den Code Zeile für Zeile, dann führe ihn aus. Drück danach auf „Schritt für Schritt“ und beobachte, wie der Zähler wächst.

Erwartete Ausgabe im Browser: 20 Log-Dateien (4 Maschinen mal 5 Tage), zusammen 47,2 KiB; D2: 5, F1: 4, M1: 11, R1: 7 Fehler; drei NC-Programme; die Dauer der Suche ist bei jedem Lauf anders.

  1. Zeilen 5 und 6: time liefert die Stoppuhr, Path aus pathlib beschreibt Pfade. Beide stehen am Anfang, damit der Rest sie benutzen kann.
  2. Zeilen 8 und 9: Die Stoppuhr startet vor der Arbeit, die gemessen werden soll. Path("zelle") ist der Ausgangspunkt der Suche: ein relativer Pfad, also ab dem Arbeitsordner.
  3. Zeilen 11 bis 13: Ein leeres Wörterbuch für die Fehler (Schlüssel ist die Maschine, Wert eine Liste von Meldungen) und zwei Zähler für Dateien und Bytes (V08).
  4. Zeile 14: glob("maschinen/*/logs/*.log") sucht nach einem Muster: unter maschinen jeder Ordner (* steht für D2, F1, M1, R1), darin logs, darin jede Datei auf .log. sorted bringt die Treffer in eine feste Reihenfolge, denn glob verspricht keine.
  5. Zeilen 15 und 16: Pro Datei einen Treffer mehr zählen und log.stat().st_size (Größe in Bytes) aufaddieren.
  6. Zeile 17: Welche Maschine ist das? Der Pfad endet auf D2/logs/2026-11-16.log. log.parent ist der Ordner logs, log.parent.parent der Ordner D2, .name sein Name "D2".
  7. Zeilen 18 bis 24: Die Datei wird zeilenweise gelesen (V09). zeile.strip().split(";") zerlegt eine Zeile in Zeit, Stufe und Meldung (V08). Ist teile[1] gleich "ERROR", kommt die Meldung in die Liste dieser Maschine; hat die Maschine noch keine Liste, wird sie in Zeile 23 angelegt. log.stem ist das Datum aus dem Dateinamen, teile[0][11:] die Uhrzeit (die Zeichen ab Position 11 der Zeit).
  8. Zeilen 26 bis 28: Die Summe geteilt durch 1024 ergibt KiB, auf eine Nachkommastelle. Dann eine Zeile je Maschine mit Anzahl und erstem Fehler.
  9. Zeilen 30 und 31: rglob("*.nc") sucht in allen Unterordnern, findet also auch das Programm im Ordner alt. Die Schreibweise in Zeile 30 ist eine List Comprehension (V08) mit nur den Namen.
  10. Zeile 32: Die Differenz der Stoppuhr ist die Laufzeit in Sekunden, mal 1000 sind Millisekunden. Führe das Programm mehrmals aus: Die Zahl ändert sich jedes Mal, weil das Betriebssystem zwischendurch andere Dinge erledigt.
  11. Selbsterklärung: Ändere Zeile 14 in zelle.glob("*.log"). Was zeigt das Programm jetzt, und warum gibt es keine Fehlermeldung? Dann stelle "ERROR" auf "WARN" und vergleiche die Zahlen.
Achtung

Die Reihenfolge von sorted hängt vom Betriebssystem ab: Hier im Browser (Linux) steht WELLE_20H6.nc vor WELLE_20H6_v1.nc, und der Ordner alt kommt zuletzt. Windows vergleicht Pfade ohne Rücksicht auf Groß- und Kleinschreibung und liefert eine andere Reihenfolge. Verlass dich bei Pfaden deshalb nie auf eine bestimmte Reihenfolge, wenn du sie nicht selbst festlegst.

Ablauf verfolgen

Bevor du Ordner durchsuchst, musst du Pfadteile lesen können. Führe das Programm im Kopf aus, Zeile für Zeile, so wie Python es tut. Trage ein, was danach in den hervorgehobenen Variablen steht. import-Zeilen und die Zeile mit dem Pfad bekommen keinen eigenen Schritt. Texte schreibst du mit Anführungszeichen ('D2').

Zweiter Ablauf: Dateigrößen aufsummieren und in KiB umrechnen, wie im Beispiel. Drei Logs mit 1536, 3072 und 512 Bytes.

Zeilen ordnen

Alle Zeilen sind da, aber durcheinander. Bring sie in die richtige Reihenfolge und rücke die Zeilen im Schleifenrumpf ein (Pfeil nach rechts oder Mausziehen). Manche Zeilen gehören nicht ins Programm.

Log-Dateien einer Maschine zählen

Das Programm zählt die Log-Dateien im Ordner der Drehmaschine D2. Überlege vorher: Was muss ganz oben stehen, damit Path bekannt ist? Welches Muster findet Log-Dateien? Welche Zeile gehört in die Schleife?

Größe aller Logs der Fräsmaschine in KiB

Die Größen der Log-Dateien von F1 werden aufsummiert und in KiB ausgegeben, auf eine Nachkommastelle. Achte auf die Umrechnung von Bytes in KiB und darauf, was vor der Schleife und was nach der Schleife steht.

Lücken füllen

Jetzt tippst du Teile selbst. Ergänze die vier Lücken, sodass das Programm alle NC-Programme der Zelle mit Namen und Größe in Bytes ausgibt, also auch die im Unterordner alt. Geprüft wird das Verhalten, nicht nur dein Wort: Die Tests legen weitere NC-Programme an und starten dein Programm noch einmal.

from pathlib import Path

nc = Path("zelle") / "@@nc-programme@@"
for p in sorted(nc.@@rglob@@("*.nc")):
    groesse = p.@@stat@@().st_size
    print(p.@@name@@, groesse, "Bytes")
  1. Lücke 1: Der Unterordner der Zelle, in dem die NC-Programme liegen. Schau in die Ausgabe von Syntax-Karte 2 oder in das Beispiel.
  2. Lücke 2: Die Methode, die auch in Unterordnern sucht, beginnt mit r (Syntax-Karte 2). Sonst fehlt das Programm im Ordner alt.
  3. Lücke 3 und 4: Die Größe steht in stat().st_size (Syntax-Karte 3); der Dateiname ohne Ordner ist .name (Syntax-Karte 1).

Erste eigene Aufgabe: Warnungen je Maschine zählen

Jetzt suchst du selbst, mit Tests als Sicherheitsnetz. Die Tests laufen mit der Zelle, wie sie ist, und mit veränderten Daten: Sie legen neue Log-Dateien, eine zusätzliche Maschine und eine Notizdatei an und starten dein Programm noch einmal. Ein Programm, das nur die heutigen Zahlen ausgibt, besteht deshalb nicht.

Gib für jede Maschine unter zelle/maschinen eine Zeile mit der Zahl der Warnungen aus (Stufe WARN), alphabetisch nach dem Maschinennamen, auch wenn die Zahl 0 ist. Gezählt werden nur Dateien mit der Endung .log im Unterordner logs der Maschine. Das Gerüst läuft schon über die Maschinen, du ergänzt die Schleifen darin.

Ausgabe genau so (für die mitgelieferte Zelle):
D2: 13
F1: 14
M1: 20
R1: 15

Gegenprobe von Hand: Die Maschine M1 meldet die meisten Warnungen („Messung n. i. O.“), D2 die wenigsten.

  1. Innerhalb der Maschinen-Schleife brauchst du eine zweite Schleife über die Log-Dateien: (maschine / "logs").glob("*.log"). Der Schrägstrich verbindet Pfadteile (Syntax-Karte 1 und 2).
  2. Für jede Datei: with open(log, encoding="utf-8") as datei: und eine dritte Schleife über die Zeilen, wie im Beispiel (Zeilen 18 bis 21).
  3. Eine Zeile zerlegst du mit zeile.strip().split(";"). Die Stufe steht in teile[1]. Ist sie "WARN" (genau so, in Großbuchstaben), zählst du warnungen hoch.

PAP zeichnen: Speicher-Ampel

Der Arbeitsspeicher (RAM) entscheidet beim CAD, ob das Bauteil flüssig läuft. Du zeichnest den Plan einer Ampel, die aus dem Bedarf der geöffneten Programme eine Aussage macht. Die Prüfung erzeugt aus deinem PAP Python-Code und testet ihn mit Grenzwerten, auch genau auf der Grenze.

Speicher-Ampel

Zeichne einen PAP. Eingaben: der Arbeitsspeicher ram_gb (in GB, Kommazahl) und die Anzahl n der laufenden Programme (ganze Zahl). Dann liest eine Zählschleife über n Durchläufe jeweils den Bedarf bedarf eines Programms (in GB, Kommazahl) ein und addiert ihn auf summe (Start 0). Danach prüfst du die Summe: höchstens 80 % des Arbeitsspeichers: Ausgabe "ok"; höchstens 100 %: Ausgabe "knapp"; sonst Ausgabe "Auslagerung" (das Betriebssystem muss Daten auf die SSD verschieben). Schreibe die Ausgabetexte mit Anführungszeichen.

  1. Nach den zwei Eingaben setzt eine Operation summe = 0 den Anfang. Die Zählschleife hat die Bedingung i in range(n), im Rumpf stehen die Eingabe bedarf (Kommazahl) und die Operation summe = summe + bedarf.
  2. Nach der Schleife kommt eine Raute mit summe <= 0.8 * ram_gb. Ja: Ausgabe "ok". Nein: eine zweite Raute mit summe <= ram_gb.
  3. Das Gleichheitszeichen gehört zu beiden Vergleichen (<=), denn auf der Grenze selbst gilt noch die bessere Stufe. Die dritte Ausgabe "Auslagerung" steht im Nein-Zweig der zweiten Raute.

Code-Review: KI-Skript für die Logs prüfen

Eine KI hat ein Skript geliefert, das die Logs der Zelle auswertet und alte NC-Programme aufräumt. Auf dem Rechner der Autorin lief es ohne Fehlermeldung. Würdest du es freigeben? Klick die Zeilen an, die du für fehlerhaft hältst, dann lass auflösen.

Szenario: Logs der Zelle auswerten und aufräumen

Prompt einer Kollegin

Schreib mir ein Python-Skript für die Fertigungszelle. Die Logs liegen im Ordner zelle/maschinen/<Maschine>/logs/ als .log-Dateien, jede Zeile heißt Zeit;Stufe;Meldung. Zähle alle Zeilen der Stufe ERROR, gib die Gesamtgröße der Log-Dateien in KiB aus und miss die Laufzeit der Suche. Lösche außerdem die alten NC-Programme im Ordner zelle/nc-programme/alt.

KI-Antwort (Python)

Tipp: Es sind sechs Fehler eingebaut. Auf dem Rechner der Autorin gibt es keine Fehlermeldung. Nicht jede Zeile ist falsch.

Würdest du das freigeben? Markiere die fehlerhaften Zeilen, dann lass auflösen.

Die sechs Fehler

Fehler 1: fester absoluter Pfad mit Rückstrichen (Zeile 4)

Der Pfad C:\Daten\FZ3\zelle gibt es nur auf dem Rechner der Autorin. Auf jedem anderen Rechner (und hier im Browser) existiert er nicht, das Programm findet keine Datei und meldet trotzdem nichts: Es wird nur 0 gezählt. Dazu steht der Pfad in einem normalen Text mit Rückstrichen: \D und \F sind keine bekannten Sonderzeichen und bleiben zufällig erhalten, bei C:\Users\… bricht Python mit einem SyntaxError ab (\U), bei \new wird ein Zeilenumbruch daraus. Lösung: ein relativer Pfad mit /, Path("zelle"), und das Programm im richtigen Arbeitsordner starten.

Fehler 2: das Muster findet nichts (Zeile 8)

zelle.glob("*.log") sucht nur direkt im Ordner zelle. Die Logs liegen aber zwei Ebenen tiefer in maschinen/D2/logs/. Die Schleife läuft null Mal, es gibt keine Fehlermeldung, das Ergebnis ist 0 Fehler in 0.0 KiB. Lösung: zelle.glob("maschinen/*/logs/*.log") oder zelle.rglob("*.log"), dazu sorted(…) für eine feste Reihenfolge. Prüfe immer, ob die Zahl der gefundenen Dateien zu deiner Erwartung passt (hier 20).

Fehler 3: Groß- und Kleinschreibung der Stufe (Zeile 13)

Die Logs schreiben ERROR in Großbuchstaben. "Error" ist ein anderer Text, der Vergleich ist nie wahr, der Zähler bleibt 0. Wieder ohne Meldung. Lösung: teile[1] == "ERROR", oder robuster teile[1].upper() == "ERROR".

Fehler 4: Zeitmessung um den falschen Teil (Zeile 16)

Die Stoppuhr startet erst, nachdem die Suche fertig ist, und stoppt nach dem print. Gemessen wird nur das Ausgeben, vielleicht 0.1 ms. Das Programm nennt es trotzdem „Suche dauerte“. Lösung: start = time.perf_counter() vor die Schleife (Zeile 8), ende direkt nach der Schleife.

Fehler 5: Bytes durch 1000 geteilt, aber „KiB“ geschrieben (Zeile 17)

Ein KiB sind 1024 Bytes. Wer durch 1000 teilt, bekommt kB, und die Zahl ist rund 2,4 % zu groß. Bei den 20 Logs wären das 48.4 statt 47.2. Lösung: groesse / 1024, oder die Einheit in „kB“ ändern. Wichtig ist, dass Zahl und Einheit zusammenpassen.

Fehler 6: gefährliches Löschen (Zeilen 21 und 22)

Die Aufgabe lautete: alte NC-Programme im Ordner alt löschen. Das Muster zelle.rglob("*.nc") trifft aber alle NC-Programme der Zelle, auch WELLE_20H6.nc und FLANSCH_80.nc, die gerade in der Fertigung laufen. unlink() löscht endgültig, ohne Papierkorb. Das Skript würde die aktuellen Programme vernichten. Regeln: Lösch-Code liest du besonders genau. Den Ordner ganz eng fassen (zelle / "nc-programme" / "alt"), erst nur anzeigen, was gelöscht würde, dann nach Rückfrage löschen, und vorher eine Sicherung ziehen.

Die Fehler einzeln zum Ausprobieren

Alles läuft hier harmlos: Gezählt und angezeigt wird, gelöscht wird nichts. Jeder Block hat seinen eigenen frischen Ordner zelle/.

print(len(list(zelle.glob("*.log"))))        # 0: ohne Meldung

Merke

Bei KI-Code mit Dateien prüfst du: Ist der Pfad relativ und mit / geschrieben? Findet das Muster wirklich die erwartete Zahl an Dateien? Stimmen Schreibweise der Stufen und Einheiten (KiB gleich 1024)? Misst die Stoppuhr den richtigen Teil? Und: Alles, was löscht, verschiebt oder überschreibt, liest du dreimal und lässt es zuerst nur anzeigen.

Typische Fehlermeldungen

Mit Dateien und Ordnern siehst du neue Fehlermeldungen. Dazu gibt es einen Fehler, der keine Meldung auslöst. Diese sechs siehst du garantiert. Jedes Beispiel lässt sich ausführen: Schau dir die echte Meldung an und lies sie von unten nach oben (zuerst die letzte Zeile).

FileNotFoundError: falscher relativer Pfad

Meldung: FileNotFoundError: [Errno 44] No such file or directory: 'zelle/maschinen/D2/log/2026-11-16.log' (die Zahl in eckigen Klammern hängt vom System ab, unter Windows steht Errno 2). Der Ordner heißt logs, nicht log. Die Meldung nennt den Pfad, der wirklich gesucht wurde: Vergleiche ihn Zeichen für Zeichen mit dem Ordnerbaum. Häufig steckt auch ein falscher Arbeitsordner dahinter: Das Programm wurde in einem anderen Ordner gestartet, als du denkst. Dann hilft print(Path.cwd()), und exists() vor dem Öffnen.

SyntaxError: Rückstriche im Windows-Pfad

Meldung: SyntaxError: (unicode error) 'unicodeescape' codec can't decode bytes in position 2-3: truncated \UXXXXXXXX escape. In einem normalen Text beginnt \U eine Unicode-Zeichenfolge. Der Fehler tritt schon beim Lesen des Programms auf, nichts davon läuft. Lösung: Path("C:/Users/marvin/zelle") mit Schrägstrichen oder r"C:\Users\marvin\zelle" mit r vor dem Text (Syntax-Karte 6). Besser noch: ein relativer Pfad.

TypeError: len() auf einem Suchergebnis

Meldung: TypeError: object of type 'generator' has no len(). glob und rglob liefern einen Generator, keine Liste. Lösung: len(list(treffer)), oder gleich sorted(...) (das liefert eine Liste) oder eine Schleife, die mitzählt.

TypeError: Text geteilt durch Text

Meldung: TypeError: unsupported operand type(s) for /: 'str' and 'str'. Der Schrägstrich verbindet nur dann Pfadteile, wenn mindestens ein Teil ein Path ist. Lösung: ordner = Path("zelle"). Oder mit Text rechnen und "zelle/LIESMICH.txt" schreiben.

IsADirectoryError: einen Ordner wie eine Datei öffnen

Meldung: IsADirectoryError: [Errno 31] Is a directory: 'zelle/maschinen' (die Zahl hängt vom System ab; unter Windows meldet Python stattdessen PermissionError). open öffnet Dateien. Ein Ordner hat keinen Textinhalt. Meist stammt der Pfad aus einer Suche, die auch Ordner liefert: Prüfe mit p.is_file() vor dem Öffnen.

Falsches Ergebnis ohne Meldung: die Suche findet nichts

Hier gibt es keine Fehlermeldung, aber das Ergebnis ist falsch: 0 statt 27. Das Muster *.log sucht nur direkt in zelle/, dort liegt keine Log-Datei. Die Schleife läuft null Mal, und eine Schleife, die nicht läuft, ist für Python kein Fehler. Gegenmittel: die Zahl der gefundenen Dateien ausgeben und mit der Erwartung vergleichen (hier 20). Ein Ergebnis von 0 ist bei einer Suche immer verdächtig.

Ausgabe genau so (für die mitgelieferte Zelle):

Gegenprobe: Die Datei hat 3158 Bytes, 3158 / 1024 sind 3,08 KiB.

Wiederholung: Messprotokoll der Messmaschine auswerten

Zurück zu Dateien lesen und Zahlen auswerten (V09 mit csv oder V15 mit pandas, du darfst wählen). Die Messmaschine M1 hat die Wellen von D2 gemessen. Die Datei liegt in zelle/messprotokolle/M1_D2_KW47.csv: Semikolon als Trennzeichen, Dezimalpunkt, die Spalten teil, durchmesser_mm und ergebnis (iO oder niO, in Ordnung oder nicht in Ordnung).

Lies die Datei und gib drei Zeilen aus: die Zahl der Teile, den Anteil der Teile mit Ergebnis niO in Prozent (eine Nachkommastelle) und den Mittelwert des Durchmessers in mm (vier Nachkommastellen).

Ausgabe genau so (für die mitgelieferte Datei):
Teile: 20
Anteil niO: 0.0 %
Mittelwert: 20.0023 mm

Die Tests starten dein Programm auch mit anderen Messprotokollen am selben Pfad.

  1. Mit csv: csv.reader(f, delimiter=";"), die Kopfzeile mit next(leser) überspringen, zeile[1] ist der Durchmesser (mit float), zeile[2] das Ergebnis. Mit pandas: pd.read_csv(datei, sep=";"), dann df["durchmesser_mm"].mean() und (df["ergebnis"] == "niO").mean().
  2. Der Anteil in Prozent ist 100 * nio / n. In einem f-String schreibst du ein Prozentzeichen einfach als Text: f"... {anteil:.1f} %".
  3. Der Mittelwert ist die Summe der Durchmesser geteilt durch ihre Anzahl, ausgegeben mit :.4f.

Funktion: Fehlermeldungen einer Log-Datei

Aus einer Auswertung wird ein wiederverwendbares Werkzeug: eine Funktion, die den Pfad selbst baut und mit fehlenden Dateien klarkommt. Die Tests rufen deine Funktion direkt auf, mit Maschinen und Tagen, die es gibt und die es nicht gibt.

Schreibe die Funktion fehlermeldungen(maschine, datum). Sie liest die Datei zelle/maschinen/<maschine>/logs/<datum>.log und gibt die Meldungen (dritter Teil der Zeile) aller Zeilen der Stufe ERROR als Liste zurück, in der Reihenfolge der Datei. Gibt es keine Datei dieses Namens (auch ein Ordner mit diesem Namen ist keine Datei), ist das Ergebnis die leere Liste [], ohne Fehlermeldung.

Beispiel
fehlermeldungen("D2", "2026-11-16")   ergibt   ['Kuehlmitteldruck zu niedrig']
fehlermeldungen("D2", "2030-01-01")   ergibt   []
  1. Baue den Pfad mit /: Path("zelle") / "maschinen" / maschine / "logs" / (datum + ".log"). Die Klammer ist nötig, weil der Dateiname erst aus zwei Teilen entsteht.
  2. Prüfe vor dem Öffnen mit pfad.is_file(). exists() reicht nicht, denn ein Ordner dieses Namens besteht auch.
  3. In der Datei: wie im Beispiel Zeile für Zeile zerlegen, bei teile[1] == "ERROR" die Meldung teile[2] an die Liste hängen. Die Liste gibst du am Ende der Funktion mit return zurück, auch wenn sie leer ist.

Zeitmessung: welche Suche ist schneller?

Zwei Funktionen zählen die Log-Dateien, die eine mit einem Muster, das den Aufbau kennt, die andere mit Durchsuchen aller Einträge. Welche ist schneller? Das sagt dir kein Test mit einer festen Zahl, denn die Zeit hängt vom Rechner und vom Betriebssystem ab. Die Tests prüfen, ob deine Messung sinnvoll gebaut ist: Zeit in Millisekunden, mehrmals gemessen, der schnellste Wert zählt.

Schreibe die Funktion messe(funktion, wiederholungen=5). Sie ruft funktion() genau wiederholungen-mal auf, misst jeden Aufruf mit time.perf_counter() und gibt die kürzeste Dauer in Millisekunden zurück. Danach gibt das Programm aus, welche Variante schneller war: eine Zeile Schneller: A oder Schneller: B. Das Gerüst misst und gibt schon A und B aus.

Ausgabe (die Zahlen sind bei dir anders)
Variante A: 1.23 ms
Variante B: 4.56 ms
Schneller: A
  1. Gerüst der Funktion: eine leere Liste zeiten, dann for versuch in range(wiederholungen):. Im Rumpf: Stoppuhr starten, funktion() aufrufen (Klammern, sonst passiert nichts), Stoppuhr lesen (Syntax-Karte 5).
  2. Die Differenz ist in Sekunden. Mal 1000 sind Millisekunden. Hänge sie an zeiten an. Am Ende return min(zeiten).
  3. Das Programm unter der Funktion: if zeit_a <= zeit_b: gibt Schneller: A aus, sonst Schneller: B.

Die Schichtleitung möchte eine Tabelle: Wie viele Fehler gab es je Maschine und Tag? Dein Programm schreibt sie als CSV-Datei (V09), die sich in Excel öffnen lässt. Nach „Ausführen“ erscheint die Datei unter der Ausgabe bei „Erzeugte Dateien“.
