Werkzeugkasten

Heute neu in Python: bool-Werte, Vergleiche, die Verknüpfungen and, or, not und die Verzweigung mit if, elif und else. Aus V01 bis V03 setzen wir print, Variablen, input, float(), f-Strings und math.isclose voraus. Das Video zeigt dir die Schreibweise, die Karten unten dienen dir als Spickzettel. Jeder Code ist ausführbar: Drück auf „Schritt für Schritt“, vor allem bei der Verzweigung (Karte 4).

Merke

Diese fünf Syntax-Karten sind dein Spickzettel, bis es sitzt. Du erreichst sie in jeder Aufgabe über den Knopf „Werkzeugkasten“ oben. Alle Befehle des Kurses stehen außerdem rechts in der Befehls-Bibliothek.

Syntax-Karte 1

Wahrheitswerte und Vergleiche

x = 180
ok = x > 150            # True
print(ok, type(ok))
print(x == 180, x != 180)
print(x < 150, x <= 180, x >= 200)
== / !=gleich / ungleich
< / >kleiner / größer (Grenze gehört nicht dazu)
<= / >=kleiner oder gleich / größer oder gleich (Grenze gehört dazu)
  • Das Ergebnis eines Vergleichs ist ein bool: nur True oder False, immer mit großem Anfangsbuchstaben und ohne Anführungszeichen.
  • = speichert einen Wert, == fragt, ob zwei Werte gleich sind.
  • Einen Text vergleichst du nicht mit einer Zahl: "180" == 180 ist False, und "180" > 150 ist ein TypeError.
Syntax-Karte 2

Bereich prüfen und Kommazahlen

import math

druck = 180.0
print(150 <= druck <= 210)    # Grenzen gehören dazu
print(150 < druck < 210)      # Grenzen gehören nicht dazu
print(0.1 + 0.2 == 0.3)       # Falle aus V03
print(math.isclose(0.1 + 0.2, 0.3))
  • Ein Bereich lässt sich wie in der Mathematik in einem Zug schreiben: 150 <= druck <= 210.
  • Wähle <= oder < bewusst: Steht in der Vorgabe „von 150 bis 210“, gehören die Grenzen dazu.
  • Kommazahlen vergleichst du nicht mit == (V03): Nimm math.isclose oder prüfe gegen feste Grenzen.
Syntax-Karte 3

and, or, not

a = True
b = False
print(a and b)            # False: beide müssen wahr sein
print(a or b)             # True: einer genügt
print(not a)              # False: dreht um
print(a or b and not a)   # not vor and vor or
print((a or b) and not a) # Klammern ändern das
  • Es sind Wörter, keine Zeichen: and, or, not, klein geschrieben.
  • Reihenfolge: zuerst Vergleiche, dann not, dann and, zuletzt or. Im Zweifel Klammern setzen.
  • Jede Seite von and und or ist eine vollständige Bedingung: x > 3 and x < 9, nicht x > 3 and < 9.
  • De Morgan: not (a and b) ist dasselbe wie (not a) or (not b).
Syntax-Karte 4

if, elif, else und Einrückung

druck = 230.0
if druck < 150:
    print("zu niedrig")
elif druck <= 210:
    print("im Bereich")
else:
    print("zu hoch")
print("fertig")          # nicht eingerückt: läuft immer
  • Hinter if, elif und else steht ein Doppelpunkt. Die Zeilen darunter sind vier Leerzeichen eingerückt (die Tab-Taste im Editor macht das für dich). Die Einrückung ist Teil der Syntax: Sie sagt Python, was zum Zweig gehört.
  • Es läuft genau ein Zweig: der erste mit wahrer Bedingung. elif und else sind optional; else hat keine Bedingung.
  • Eine Zeile, die wieder ganz links beginnt, beendet den Block und läuft in jedem Fall.
  • Drück auf „Schritt für Schritt“: Du siehst, welche Zeilen übersprungen werden.
Syntax-Karte 5

Ja/Nein und Zahl einlesen

tuer_zu = input("Schutztür geschlossen? (j/n): ") == "j"
druck = float(input("Druck in bar: "))
print(tuer_zu, type(tuer_zu))
print(druck > 150)
  • input(...) == "j" ist ein Vergleich: Das Ergebnis ist True, wenn der Benutzer „j“ tippt, sonst False. So wird aus Text ein bool.
  • Der Vergleich ist genau: „J“ (großes J) ist nicht „j“.
  • Zahlen immer sofort mit float() umwandeln (V03), sonst gibt es beim Vergleich einen TypeError.

Vorgerechnetes Beispiel: Zweihandschaltung

Aufgabe: Ein Programm steuert die Freigabe einer Presse. Der Hub wird nur freigegeben, wenn beide Taster gedrückt sind, die Schutztür zu ist und der Hydraulikdruck von 150 bis 210 bar liegt. Sonst nennt das Programm den Grund. Lies den Code Zeile für Zeile, dann führe ihn aus. Die Eingaben stehen im Feld darunter (alles in Ordnung, Druck 180 bar). Drück danach auf „Schritt für Schritt“: Bei der Verzweigung ab Zeile 16 siehst du, wie das Programm Zeilen überspringt.

# Zweihandschaltung einer Presse: Hub nur, wenn beide Taster gedrückt,
# die Schutztür zu und der Hydraulikdruck im zulässigen Bereich ist.
# (V04: bool, Vergleiche, and/or/not, if/elif/else)

taster_links = input("Taster links gedrückt? (j/n): ") == "j"
taster_rechts = input("Taster rechts gedrückt? (j/n): ") == "j"
tuer_zu = input("Schutztür geschlossen? (j/n): ") == "j"
druck_bar = float(input("Hydraulikdruck in bar: "))

druck_ok = 150 <= druck_bar <= 210
freigabe = taster_links and taster_rechts and tuer_zu and druck_ok

print("Beide Taster:", taster_links and taster_rechts)
print("Druck im Bereich:", druck_ok)

if freigabe:
    print("Hub freigegeben")
elif not tuer_zu:
    print("Stopp: Schutztür offen")
elif not druck_ok:
    print(f"Stopp: Druck {druck_bar:.1f} bar außerhalb von 150 bis 210 bar")
else:
    print("Warten: bitte beide Taster drücken")
  1. Zeilen 5 bis 7: input(...) == "j" ist ein Vergleich. Der Benutzer tippt „j“ oder „n“, der Vergleich macht daraus True oder False. Die drei Variablen sind also bool, kein Text.
  2. Zeile 8: Der Druck ist eine Kommazahl: float(input(...)) (V03). Ohne float() gäbe Zeile 10 einen TypeError, denn Text lässt sich nicht mit 150 vergleichen.
  3. Zeile 10: 150 <= druck_bar <= 210 prüft den Bereich in einem Zug. Wegen <= gehören 150 und 210 dazu. Das Ergebnis ist druck_ok, ein bool.
  4. Zeile 11: Vier Wahrheitswerte mit and verknüpft: freigabe ist nur dann True, wenn alle vier True sind. Mit or statt and wäre die Sicherung wirkungslos.
  5. Zeilen 13 und 14: print zeigt auch Wahrheitswerte an, hier als Zwischenergebnisse. Das ist ein guter Weg, eine Bedingung zu prüfen, bevor man sie in if einsetzt.
  6. Zeilen 16 bis 23: Die Verzweigung. Hinter jeder Bedingung steht ein Doppelpunkt, darunter vier Leerzeichen Einrückung. Es läuft genau ein Zweig: erst die Freigabe, dann „Tür offen“, dann „Druck falsch“, sonst „Warten“. Zeile 21 ist ein f-String mit :.1f (V03).
  7. Selbsterklärung: Ändere die Eingaben und sag vorher die Meldung voraus. Probiere: j, j, n, 230 (Tür offen und Druck zu hoch: Welche Meldung kommt, und warum nur eine?), j, n, j, 180, und j, j, j, 210 (Grenzfall). Was passiert bei Druck 210.5?

Ablauf verfolgen

Bei einer Verzweigung werden Zeilen übersprungen. Führe das Programm im Kopf aus und trage ein, was danach in den hervorgehobenen Variablen steht. Achte auf die Spalte „Zeile“: Sie springt, weil Python nur den Zweig ausführt, dessen Bedingung stimmt. Ein bool schreibst du mit großem Anfangsbuchstaben und ohne Anführungszeichen: True. Text steht in Anführungszeichen. Wenn du unsicher bist, lass den Code vorher im „Vorgerechneten Beispiel“ mit „Schritt für Schritt“ laufen.

Zeilen ordnen

Alle Zeilen sind da, aber durcheinander. Bring sie in die richtige Reihenfolge und rücke sie richtig ein: Zeilen, die zu einem if-, elif- oder else-Zweig gehören, werden eingerückt (die Pfeile an der Zeile rücken ein und aus). Manche Zeilen sind Ablenker: Sie gehören nicht ins Programm.

Drucküberwachung

Das Programm liest den Druck in bar ein und meldet, ob er zu niedrig (unter 150), im Bereich (150 bis 210) oder zu hoch ist.

Hub nur mit beiden Tastern

Das Programm fragt beide Taster ab (Eingabe „j“ heißt gedrückt) und gibt den Hub nur frei, wenn beide gedrückt sind.

Lücken füllen

Jetzt tippst du Teile selbst. Ergänze die fünf Lücken, sodass das Programm eine Spindel nur freigibt, wenn die Schutzhaube geschlossen ist und die Drehzahl höchstens 3000 beträgt (3000 selbst ist erlaubt). Geprüft wird nicht nur dein Wortlaut, sondern ob das Programm das Richtige tut.

n = @@float@@(input("Drehzahl in 1/min: "))
haube_zu = input("Schutzhaube geschlossen? (j/n): ") @@==@@ "j"
if n @@<=@@ 3000 @@and@@ haube_zu:
    print("Spindel frei")
@@else@@:
    print("Spindel gesperrt")
  1. Die Eingabe ist Text, die Drehzahl soll eine Zahl sein. Welche Umwandlung hast du in V03 gelernt (Syntax-Karte 5)?
  2. Ob der Benutzer „j“ getippt hat, fragst du mit einem Vergleich: Welches Zeichen steht für „ist gleich“ (nicht =!)?
  3. „Höchstens 3000“ heißt: 3000 gehört dazu. Beide Bedingungen müssen gleichzeitig gelten: Welches Wort verknüpft sie? Und wie heißt der Zweig ohne Bedingung?

Code-Review: KI-Code prüfen

Eine KI hat Code geliefert. Er sieht sauber aus und läuft los. Würdest du ihn freigeben? Klick die Zeilen an, die du für fehlerhaft hältst, dann lass auflösen.

Szenario: Freigabelogik einer Presse

Prompt eines Studierenden

Schreib mir ein kleines Python-Programm für die Pressensteuerung. (1) Der Hub wird nur freigegeben, wenn beide Taster gedrückt sind, die Schutztür zu ist und der Hydraulikdruck von 150 bis 210 bar liegt; die Grenzen 150 und 210 gehören dazu. (2) Sonst soll die Ursache gemeldet werden: erst die Tür, dann den Druck, sonst „Warten“. (3) Frag die Hubzahl seit der letzten Wartung ab und melde „Wartung fällig“, wenn sie 10000 oder mehr beträgt.

KI-Antwort (Python)

Tipp: Es sind drei Fehler eingebaut, einer je Teilaufgabe. Nicht jede Zeile ist falsch.

Würdest du das freigeben? Markiere die fehlerhaften Zeilen, dann lass auflösen.

Die drei Fehler

Fehler 1: Grenzen fallen heraus (Zeile 6)

Der verkettete Vergleich ist erlaubt und liest sich richtig. Aber < schließt die Grenzen aus: Bei genau 150 oder 210 bar ist druck_ok False, obwohl die Vorgabe sagt, dass beide Grenzen dazugehören. Lösung: 150 <= druck_bar <= 210. Grenzwerte sind die klassische Stelle für Fehler.

Fehler 2: Der Hub wird zu früh freigegeben (Zeile 9)

Die erste Bedingung prüft nur die Taster. Ist die Tür offen oder der Druck falsch, läuft trotzdem der Zweig „Hub freigegeben“, und die elif-Zweige darunter werden nie erreicht, weil es genau einen Zweig gibt. Die Sicherheitsbedingung muss alle vier Teile mit and verknüpfen: taster_links and taster_rechts and tuer_zu and druck_ok.

Fehler 3: Text statt Zahl (Zeile 19)

input() liefert Text. hubzahl >= 10000 vergleicht einen Text mit einer Zahl und bricht mit einem TypeError ab. Lösung: hubzahl = int(input(...)). Dieser Fehler zeigt sich erst, wenn jemand etwas eintippt.

Die KI-Version zum Ausprobieren

Die ersten beiden Ausgaben sind falsch (die Tür ist offen, und 150 bar gehören zum zulässigen Bereich). Danach bricht das Programm mit dem TypeError ab. Die Eingaben (j, j, n, 150 und 12000) stehen im Feld unter dem Code. Drück auf „Schritt für Schritt“, um jede Zeile einzeln zu sehen.

taster_links = input("Taster links gedrückt? (j/n): ") == "j"
taster_rechts = input("Taster rechts gedrückt? (j/n): ") == "j"
tuer_zu = input("Schutztür geschlossen? (j/n): ") == "j"
druck_bar = float(input("Hydraulikdruck in bar: "))

druck_ok = 150 < druck_bar < 210
print("Druck im Bereich:", druck_ok)

if taster_links and taster_rechts:
    print("Hub freigegeben")
elif not tuer_zu:

elif not druck_ok:

else:
    print("Warten: bitte beide Taster drücken")

hubzahl = input("Hubzahl seit der Wartung: ")

Merke

Die KI hat nicht „falsch gedacht“, sie hat das Muster geliefert, das am häufigsten vorkommt. Ob Grenzen dazugehören und welche Bedingungen zur Freigabe zählen, steht nur in deiner Spezifikation. Teste deshalb jede Bedingung einzeln (Tür offen, ein Taster, Druck genau 150 und 210) und lies bei jeder Verzweigung die Reihenfolge der Zweige.

Typische Fehlermeldungen

Fehlermeldungen sind keine Strafe, sondern ein Wegweiser. Diese vier siehst du bei Verzweigungen garantiert. Jedes Beispiel lässt sich ausführen: Schau dir die echte Meldung an und lies sie von unten nach oben (zuerst die letzte Zeile). Die gefährlichsten Fehler melden sich allerdings gar nicht: ein or statt and, ein < statt <=, ein == bei Kommazahlen (V03). Dagegen helfen nur Tests mit Grenzwerten.

SyntaxError: = statt ==

Meldung: SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?. Ein einzelnes = speichert einen Wert, in einer Bedingung willst du aber vergleichen: if druck == 180:. Python merkt das zum Glück sofort.

SyntaxError: Doppelpunkt fehlt

Meldung: SyntaxError: expected ':'. Hinter if, elif und else gehört ein Doppelpunkt. Er sagt Python: „Jetzt beginnt der Block, der dazugehört.“ Schau in die angezeigte Zeile: Die Stelle ist meist genau dort, wo der Pfeil hinzeigt.

IndentationError: Einrückung fehlt

Meldung: IndentationError: expected an indented block after 'if' statement on line 2. Die Zeile nach dem Doppelpunkt muss eingerückt sein, sonst weiß Python nicht, was zum Zweig gehört. Rücke sie um vier Leerzeichen ein (Tab-Taste). Die Gegenprobe: Rückst du eine Zeile zu weit ein, lautet die Meldung unexpected indent.

TypeError: Text mit Zahl vergleichen

Meldung: TypeError: '>' not supported between instances of 'str' and 'int'. Gemeint: "180" ist Text, 150 ist eine Zahl, und Text lässt sich nicht der Größe nach mit einer Zahl vergleichen. Meistens fehlt ein float() um ein input() (Typumwandlung, V03). Tückisch: "180" == 150 meldet keinen Fehler, sondern einfach False.

Leistung aus Spannung und Strom

Programmieren lernst du mit den Fingern, nicht mit den Augen. Das Training ist ein fester Teil jedes Termins und gehört zum Selbststudium. Du musst nicht alles an einem Stück machen, aber alles bis zum nächsten Termin. Die Aufgaben laufen komplett im Browser und werden automatisch geprüft.

Achtung

Phase 1: Copilot nur als Erklärer. Erlaubt: „Erkläre mir diese Fehlermeldung“, „Was macht Zeile 3?“, „Warum läuft der elif nie?“. Nicht erlaubt: „Schreib mir die Verzweigung“. Du tippst den Code selbst, denn nur dann lernst du, ihn zu prüfen. Ab V10 darf die KI Code erzeugen, und du prüfst.

Wiederholung aus V03: Eingaben umwandeln und formatiert ausgeben. Lies die Spannung U in V und den Strom I in A als Kommazahlen ein (in dieser Reihenfolge), berechne die Leistung P = U · I und gib zwei Zeilen aus: die Leistung mit einer Nachkommastelle und den Datentyp von P.

Ausgabe genau so (Beispiel U = 230, I = 5):
Leistung: 1150.0 W
Typ: <class 'float'>
  1. Beide Eingaben mit float(input(...)) umwandeln, sonst lässt sich Text nicht multiplizieren (V03).
  2. Formatierte Ausgabe: print(f"Leistung: {p:.1f} W").
  3. Der Typ kommt von type(p): print("Typ:", type(p)).

Messwert gegen Toleranzgrenzen

Ein Wellendurchmesser hat das Untermaß 24.95 mm und das Obermaß 25.05 mm. Lies den gemessenen Durchmesser in mm ein und speichere drei Wahrheitswerte: in_toleranz (zwischen den Grenzen, die Grenzen gehören dazu), zu_klein (unter dem Untermaß) und zu_gross (über dem Obermaß). Gib die drei Werte aus. None in der Vorgabe ersetzt du jeweils durch deinen Ausdruck.

Ausgabe genau so (Beispiel 24.97):
In Toleranz: True
Zu klein: False
Zu groß: False
  1. Ein Vergleich liefert direkt True oder False: zu_klein = durchmesser < 24.95.
  2. Beide Grenzen gehören dazu, also <=. Den Bereich schreibst du in einem Zug: 24.95 <= durchmesser <= 25.05 (Syntax-Karte 2).
  3. Das Untermaß 24.95 und das Obermaß 25.05 stehen als feste Zahlen im Vergleich. Das ist hier in Ordnung: Der Messwert wird gegen dieselbe Zahl verglichen, nichts wird vorher gerechnet.

Förderband-Freigabe

Ein Förderband läuft, wenn (der Start-Taster gedrückt ist oder die Automatik aktiv ist), und der Not-Halt nicht ausgelöst ist und die Schutzhaube geschlossen ist. Lies vier Ja/Nein-Eingaben ein (Antwort „j“ heißt ja), in dieser Reihenfolge: Start-Taster gedrückt, Automatik aktiv, Not-Halt ausgelöst, Schutzhaube geschlossen. Gib den Wahrheitswert aus.

Ausgabe genau so (Beispiel j, n, n, j):
Band läuft: True

Tipp: Zeichne zuerst die Wahrheitstabelle für ein paar Zeilen und achte auf die Klammern beim ODER. Der Not-Halt braucht ein not.

  1. Vier Eingaben, jede mit input(...) == "j" in einen bool verwandeln (Syntax-Karte 5).
  2. Die Bedingung in Worten: (Start oder Automatik) und nicht Not-Halt und Haube zu. Ohne Klammern würde and vor or rechnen.
  3. laeuft = (start or automatik) and not nothalt and haube_zu, dann print(f"Band läuft: {laeuft}").

Strömungsart nach Reynolds-Zahl

Bei einer Rohrströmung entscheidet die Reynolds-Zahl Re über die Strömungsart: unter 2300 laminar, von 2300 bis 4000 (beide Grenzen gehören dazu) Übergang, über 4000 turbulent. Lies Re als Kommazahl ein und gib die Strömungsart aus.

Ausgabe genau so (Beispiel 3000):
Strömung: Übergang
  1. Drei Fälle, ein if-elif-else. Beginne mit „laminar“: re < 2300.
  2. Im elif ist „unter 2300“ schon ausgeschlossen. Du musst nur noch die obere Grenze prüfen, und 4000 gehört noch dazu: re <= 4000.
  3. Du kannst in jedem Zweig direkt print("Strömung: laminar") schreiben. Oder du merkst dir die Art in einer Variable und gibst sie am Ende einmal aus.

Messteil bewerten: Gutteil, Nacharbeit, Ausschuss

Eine Welle hat das Nennmaß 25.00 mm mit der Toleranz ± 0.05 mm. Lies den Messwert in mm ein und bewerte ihn: Gutteil, wenn er von 24.95 bis 25.05 mm liegt (beide Grenzen gehören dazu). Nacharbeit, wenn er über 25.05, aber höchstens 25.15 mm liegt (zu viel Material lässt sich abtragen). Sonst Ausschuss (auch zu kleine Wellen: Material lässt sich nicht ansetzen).

Ausgabe genau so (Beispiel 25.05):
Ergebnis: Gutteil

Rückgriff auf V03: abs(24.95 - 25.0) ist 0.05000000000000071 und damit knapp größer als 0.05. Wer die Grenze als Abstand zum Nennmaß rechnet, fällt an der Grenze durch. Vergleiche besser direkt mit den festen Grenzen 24.95, 25.05 und 25.15.

  1. Drei Zweige: Gutteil, Nacharbeit, sonst Ausschuss. Für „Gutteil“ brauchst du einen Bereich mit beiden Grenzen: 24.95 <= messwert <= 25.05.
  2. Achtung beim elif: Prüfst du nur messwert <= 25.15, landen auch zu kleine Messwerte (24.9) dort. Schreibe den Bereich mit beiden Seiten: 25.05 < messwert <= 25.15.
  3. Alles andere ist else: Ausschuss. Ausgabe: print(f"Ergebnis: {ergebnis}").

Sperrbedingung mit De Morgan

Eine Anlage ist freigegeben, wenn die Schutztür zu ist, der Not-Halt entriegelt ist und der Druck passt. Lies drei Ja/Nein-Eingaben ein (j heißt ja), in dieser Reihenfolge: Schutztür zu, Not-Halt entriegelt, Druck ok. Berechne die Sperre auf zwei Arten und gib beide aus: (1) die Verneinung der ganzen UND-Kette (not (...)), (2) die Umformung nach De Morgan: jeder Teil einzeln verneint, mit or verknüpft. Beide Zeilen müssen immer dasselbe zeigen.

Ausgabe genau so (Beispiel j, j, n):
Sperre (NICHT UND): True
Sperre (De Morgan): True
  1. Drei Eingaben, jede mit input(...) == "j" (Syntax-Karte 5).
  2. Variante 1: not (tuer_zu and nothalt_frei and druck_ok), das not steht vor der Klammer.
  3. Variante 2 nach De Morgan: das not springt in die Klammer, and wird zu or: (not tuer_zu) or (not nothalt_frei) or (not druck_ok).

Knobelaufgabe: Zwei aus drei

Sicherheitsrelevante Größen werden oft von drei Sensoren gleichzeitig überwacht („zwei aus drei“): Ein einzelner defekter Sensor soll weder einen Fehlalarm auslösen noch einen echten Alarm verhindern. Lies drei Ja/Nein-Eingaben ein (Sensor 1, 2, 3 meldet Grenzwert überschritten, j heißt ja) und gib zwei Zeilen aus: Alarm ist True, wenn mindestens zwei Sensoren melden. Sensoren uneinig ist True, wenn die drei Sensoren nicht alle dasselbe melden (dann sollte jemand einen Sensor prüfen). Nur and, or, not und Vergleiche, keine Verzweigung nötig.

Ausgabe genau so (Beispiel j, j, n):
Alarm: True
Sensoren uneinig: True
  1. Mindestens zwei von drei heißt: Es gibt ein Paar, das beide meldet. Wie viele Paare gibt es? Verknüpfe jedes Paar mit and und die Paare mit or.
  2. alarm = (s1 and s2) or (s1 and s3) or (s2 and s3).
  3. „Alle gleich“ schreibt sich s1 == s2 == s3 (verketteter Vergleich, auch für bool). Uneinig ist das Gegenteil: not (...).

Klausur-Modus: Behälterüberwachung

So wie in der Klausur: Schreibe den Code ohne Ausführen und ohne Auto-Vervollständigung, wenn möglich zuerst auf Papier. Erst danach „Abgeben und prüfen“, dann bewertest du dich selbst.

Ein Druckbehälter wird überwacht. Nacheinander werden eingelesen: der Druck p in bar (Kommazahl), die Temperatur T in °C (Kommazahl) und „Füllstand in Ordnung?“ (j oder n). Gib genau eine Zeile Status: … aus, nach diesen Regeln (die erste zutreffende gilt):

  • Füllstand nicht in Ordnung: Abschaltung: Füllstand,
  • sonst p über 10 bar oder T über 120 °C: Abschaltung: Grenzwert,
  • sonst p über 8 bar oder T über 100 °C: Warnung,
  • sonst: Normal.
Ausgabe genau so (Beispiel p = 8.5, T = 90, Füllstand j):
Status: Warnung
