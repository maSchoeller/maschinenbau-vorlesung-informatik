Werkzeugkasten

Heute neu in Python: Bytes und encode, das Modul hashlib mit der Prüfsumme SHA-256, Dateien blockweise lesen und zwei Prüfsummen vergleichen. Das ist das Handwerkszeug, mit dem ein Programm in der Fertigungszelle FZ-3 prüft, ob eine Firmware unverändert ist.

Merke

Diese sechs Karten sind dein Spickzettel, bis es sitzt. Du erreichst sie in jeder Aufgabe über den Knopf „Werkzeugkasten“ oben. Führe jede Karte aus und ändere etwas daran. Alle Befehle des Kurses stehen außerdem in der Befehls-Bibliothek rechts. Die Firmware-Dateien für die Karten 3 und 4 sind schon eingebaut.

Syntax-Karte 1

Bytes und Text: b"...", encode, len

text = "Drehzahl 1450"
daten = text.encode("utf-8")             # Text -> Bytes
print(daten)
print(type(text), type(daten))           # str und bytes
print(len(text), len(daten))             # 13 13: ein Zeichen = ein Byte (reines ASCII)

print(len("Ä"), len("Ä".encode("utf-8")))   # 1 2: Umlaute brauchen zwei Bytes

b = b"Ab"                                # Bytes-Literal: ein b vor den Anführungszeichen
print(b[0], list(b))                     # 65 [65, 98]: Bytes sind Zahlen von 0 bis 255
print(daten.decode("utf-8") == text)     # der Rückweg: Bytes -> Text
  • str ist Text (eine Folge von Zeichen), bytes ist eine Folge von Bytes. Einen Bytes-Wert schreibst du mit einem b vor den Anführungszeichen: b"Ab".
  • Hash-Funktionen und Dateien arbeiten mit Bytes, nicht mit Text. "text".encode("utf-8") macht aus Text Bytes, .decode("utf-8") den Rückweg. In UTF-8 (V09) braucht ein ASCII-Zeichen ein Byte, ein Umlaut zwei.
  • len(text) zählt Zeichen, len(daten) zählt Bytes. Bei „Ä“ ist das 1 gegen 2. Das ist der Grund, warum man erst kodiert und dann den Hash bildet.
  • Ein Element eines Bytes-Werts ist eine Zahl (b[0] ist 65), kein Buchstabe.
Syntax-Karte 2

Prüfsumme mit hashlib: sha256 und hexdigest

import hashlib

h = hashlib.sha256("Drehzahl 1450".encode("utf-8"))
print(h.hexdigest())                     # 64 Hex-Zeichen = 256 Bit
print(len(h.hexdigest()))                # 64
print(len(h.digest()), type(h.digest())) # 32 <class 'bytes'>: dieselbe Zahl als rohe Bytes

print(hashlib.sha256(b"").hexdigest())   # auch "nichts" hat eine Prüfsumme
print(hashlib.sha256(b"Drehzahl 1450").hexdigest() == h.hexdigest())   # gleiche Daten, gleicher Hash
  • Ein Hash ist ein Fingerabdruck der Daten: Egal wie lang die Daten sind, bei SHA-256 kommen immer 256 Bit heraus, als Hex geschrieben 64 Zeichen (V02: ein Hex-Zeichen sind 4 Bit).
  • hashlib.sha256(daten) verlangt Bytes. .hexdigest() liefert den Hash als Text mit 64 Zeichen, .digest() als 32 rohe Bytes. Zum Vergleichen und Anzeigen nimmst du hexdigest().
  • Dieselben Daten ergeben immer denselben Hash, auf jedem Rechner. Das macht ihn als Fingerabdruck brauchbar.
  • Gibst du einen Text statt Bytes an, kommt ein TypeError (Abschnitt „Typische Fehlermeldungen“).
Syntax-Karte 3

Datei binär und blockweise lesen

import hashlib

h = hashlib.sha256()                              # leerer "Fingerabdruck-Automat"
anzahl = 0
with open("R1_fw_3.2.1.bin", "rb") as datei:      # "rb" = read binary: Bytes statt Text
    while True:
        block = datei.read(4096)                  # höchstens 4096 Bytes
        if not block:                             # leer (b"") = Dateiende
            break
        h.update(block)                           # Block einmischen
        anzahl = anzahl + 1
print(anzahl, "Blöcke")
print(h.hexdigest())
import hashlib

# Kurzfassung für kleine Dateien: alles auf einmal lesen
daten = open("R1_fw_3.2.1.bin", "rb").read()
print(len(daten), "Bytes")
print(hashlib.sha256(daten).hexdigest()[:16])
  • open(pfad, "rb") öffnet die Datei binär: Du bekommst die Bytes, wie sie sind. Im Textmodus würde Python versuchen, sie als UTF-8-Text zu lesen, und bei einer Firmware abbrechen (UnicodeDecodeError).
  • datei.read(4096) liefert höchstens einen Block von 4096 Bytes. Am Dateiende kommt ein leerer Wert b"", und if not block: break beendet die Schleife (V06).
  • h = hashlib.sha256() legt den Hash leer an, h.update(block) mischt jeden Block ein. Das Ergebnis ist dasselbe wie bei einer Prüfsumme über die ganze Datei, aber der Speicherbedarf bleibt klein: Ein Firmware-Abbild kann mehrere Gigabyte groß sein.
  • Die Kurzfassung (.read() ohne Zahl) lädt alles auf einmal und ist nur für kleine Dateien gut.
  • Mit with schließt Python die Datei von selbst (V09).
Syntax-Karte 4

Prüfsummen-Datei lesen und vergleichen

import hashlib

with open("R1_fw_3.2.1.bin.sha256", encoding="utf-8") as f:
    inhalt = f.read()
print(repr(inhalt[-24:]))             # Ende der Datei: Name und Zeilenumbruch \n
teile = inhalt.split()                # an Leerraum zerlegen
print(len(teile), teile[1])           # 2 Teile: Prüfsumme und Dateiname

soll = teile[0].strip().lower()       # nur die Prüfsumme, klein, ohne Leerraum
ist = hashlib.sha256(open("R1_fw_3.2.1.bin", "rb").read()).hexdigest()
print(ist == soll)                    # True: gleich
print(ist == inhalt)                  # False: der ganze Inhalt ist mehr als die Prüfsumme
print("ABC" == "abc", "ABC".lower() == "abc")   # Groß/Klein zählt beim Vergleich
  • Eine .sha256-Datei hat das Format <Hex> <Dateiname>, mit zwei Leerzeichen dazwischen und einem Zeilenumbruch am Ende. inhalt.split() ohne Argument zerlegt an jedem Leerraum, [0] ist die Prüfsumme (V09).
  • Vergleiche nie den ganzen Dateiinhalt mit der berechneten Prüfsumme: Dateiname und Zeilenumbruch gehören nicht dazu, der Vergleich wäre immer falsch.
  • .strip() entfernt Leerraum am Rand, .lower() macht alles klein. Hex darf groß oder klein geschrieben sein (A1 ist a1), ein Text-Vergleich unterscheidet das aber.
  • Beide Seiten des Vergleichs müssen Text sein: hexdigest() gegen Text. Mit digest() (Bytes) bekommst du keinen Fehler, sondern still False.
  • Ist die Datei leer, liefert split() eine leere Liste, und [0] gibt einen IndexError.
Syntax-Karte 5

Lawineneffekt: ein Zeichen, ein ganz anderer Hash

import hashlib

a = hashlib.sha256(b"Drehzahl 1450").hexdigest()
b = hashlib.sha256(b"Drehzahl 1451").hexdigest()
print(a)
print(b)

gleich = 0
for i in range(64):                    # Stelle für Stelle vergleichen
    if a[i] == b[i]:
        gleich = gleich + 1
print(gleich, "von 64 Stellen sind gleich")
  • Ein einziges geändertes Zeichen im Text (oder ein einziges Bit in einer Datei) ändert etwa die Hälfte der Bits des Hashs. Das nennt man Lawineneffekt.
  • Dadurch fällt jede Manipulation auf, auch eine winzige. Umgekehrt kann man vom Hash nicht auf eine „ähnliche“ Datei schließen: Ähnliche Daten haben völlig unähnliche Hashes.
  • Bei 64 Hex-Zeichen sind rein zufällig etwa 4 Stellen gleich (1 von 16 pro Stelle). Mehr Übereinstimmung wäre ein Alarmzeichen.
Syntax-Karte 6

md5 und sha1: gibt es, aber nicht für Sicherheit

import hashlib

daten = b"Drehzahl 1450"
print(hashlib.md5(daten).hexdigest())      # 32 Zeichen = 128 Bit
print(hashlib.sha1(daten).hexdigest())     # 40 Zeichen = 160 Bit
print(hashlib.sha256(daten).hexdigest())   # 64 Zeichen = 256 Bit
  • hashlib.md5 und hashlib.sha1 gibt es in jeder Python-Installation, und man sieht sie noch oft (alte Skripte, alte Download-Seiten, KI-Code).
  • Beide gelten als gebrochen: Für MD5 (seit 2004) und SHA-1 (seit 2017) sind Verfahren bekannt, mit denen sich zwei verschiedene Dateien mit demselben Hash bauen lassen. Ein Angreifer kann so eine manipulierte Datei mit derselben Prüfsumme herstellen.
  • Zum Erkennen zufälliger Übertragungsfehler reichen sie noch. Für Sicherheit nimmst du SHA-256. Und die Prüfsumme des Herstellers muss zu dem Verfahren passen: Ein MD5 vergleicht man nicht mit einem SHA-256.

Vorgerechnetes Beispiel: Firmware R1 prüfen

Aufgabe: Nach der Störung an R1 kommt ein Servicetechniker mit der neuen Firmware 3.2.1 auf einem USB-Stick. Der Hersteller veröffentlicht die Prüfsumme der Datei auf seiner Download-Seite. Das Programm berechnet die Prüfsumme der Original-Datei und der Datei vom Stick und vergleicht beide mit dem Wert des Herstellers. Lies den Code Zeile für Zeile, dann führe ihn aus.

Beim Ausführen siehst du: Die ersten 16 Zeichen der Herstellerprüfsumme, dann „OK“ für die Original-Datei und „ABWEICHUNG“ für die Datei vom Stick, zuletzt die Anfänge zweier Prüfsummen, die sich nur durch ein Zeichen im Text unterscheiden.

Soll (Hersteller): f457673f9e3b31fd ...
R1_fw_3.2.1.bin: OK - darf eingespielt werden
R1_fw_3.2.1_usb.bin: ABWEICHUNG - nicht einspielen! (c01a88afebff47f1 ...)
23f2ab28ad6cc6b5
2318b47cd742ca40
  1. Zeilen 1 bis 3: Kommentare erklären, worum es geht und welche Dateien gebraucht werden. Die Datei .sha256 kommt vom Hersteller, die _usb.bin vom Stick des Servicetechnikers.
  2. Zeile 5: import hashlib holt das Modul mit den Hash-Funktionen (Standardbibliothek, nichts zu installieren).
  3. Zeilen 8 bis 17: Die Funktion sha256_datei(pfad) (V07) berechnet die Prüfsumme einer Datei. Zeile 10 legt den Hash leer an. Zeile 11 öffnet die Datei mit "rb", also binär. Die Schleife in den Zeilen 12 bis 16 liest 4096 Bytes (Zeile 13), hört bei einem leeren Block auf (Zeilen 14 und 15) und mischt sonst den Block ein (Zeile 16). Zeile 17 gibt die Prüfsumme als Hex-Text zurück. Weil die Datei Stück für Stück gelesen wird, geht das auch für sehr große Dateien.
  4. Zeilen 20 und 21: Die Prüfsumme des Herstellers steht in einer Textdatei. f.read().split()[0] liest den Inhalt, zerlegt ihn an Leerraum und nimmt das erste Stück: die Prüfsumme ohne Dateinamen und ohne Zeilenumbruch.
  5. Zeile 22: Ausgegeben werden nur die ersten 16 der 64 Zeichen (soll[:16], Ausschnitt wie bei Listen in V08). Das reicht zum Wiedererkennen.
  6. Zeilen 24 bis 29: Eine Schleife über die zwei Dateinamen. Für jede Datei wird die Prüfsumme berechnet (Zeile 25) und mit dem Soll-Wert verglichen (Zeile 26). Gleich: „OK“. Verschieden: „ABWEICHUNG - nicht einspielen!“ mit dem Anfang der berechneten Prüfsumme.
  7. Das Ergebnis: Die Datei vom Stick hat eine völlig andere Prüfsumme als die Original-Datei, obwohl in 65 536 Bytes nur ein einziges Bit gekippt ist. Das Programm hat ein Bit unter 524 288 Bit gefunden. Die Firmware wird nicht eingespielt, der Fund wird gemeldet.
  8. Zeilen 31 bis 33: Der Lawineneffekt im Kleinen: Zwei Texte, die sich in einer Ziffer unterscheiden, haben völlig verschiedene Prüfsummen (dass beide mit „23“ beginnen, ist Zufall, schon die dritte Stelle ist anders). Genau deshalb fällt das eine gekippte Bit auf.
  9. Was die Prüfsumme nicht kann: Sie sagt nur, dass die Datei zu dem Soll-Wert passt. Stammt der Soll-Wert vom selben Stick wie die Datei, kann ein Angreifer beides tauschen. Der Soll-Wert muss über einen zweiten, vertrauenswürdigen Weg kommen (Download-Seite des Herstellers). Dazu mehr in der Lerneinheit.
  10. Selbsterklärung: Ändere 4096 in Zeile 13 in 100: Ändert sich das Ergebnis? Warum nicht? Dann ändere b"Drehzahl 1450" in b"Drehzahl 1450 " (mit Leerzeichen): Wie viel ändert sich? Zuletzt schreibe in Zeile 24 den Namen "R1_fw_3.2.1.bn": Welche Fehlermeldung kommt?

Zwei Dateien gegen den Soll-Wert prüfen

Das Programm liest die Prüfsumme des Herstellers und prüft dann in einer Schleife zwei Dateien. Die Funktion sha256_datei aus der vorigen Aufgabe steht schon über dem Programm. Die Prüfsumme wird vor der Schleife gelesen, nicht in jedem Durchlauf neu. Zwei Zeilen sind Ablenker.

Lücken füllen

Jetzt tippst du Teile selbst. Ergänze die fünf Lücken, sodass das Programm einen Text in Bytes umwandelt, den ersten Block der Firmware einliest und dessen Prüfsumme ausgibt.

import hashlib

text = "Drehzahl 1450"
daten = text.@@encode@@("utf-8")             # Text -> Bytes
print(len(daten))

print(h.@@hexdigest@@()[:16])

  3. Lücke 3: Der Modus zum binären Lesen. Zwei Buchstaben, in Anführungszeichen (Syntax-Karte 3).
  4. Lücke 4: Die Methode des Hash-Objekts, die einen Block einmischt.

PAP: Firmware-Freigabe

Bevor du die Prüfung programmierst, zeichnest du den Plan. Das ist die Entscheidung am Ende des Beispiels, ohne Dateien: Zwei Texte kommen herein (der Soll-Wert des Herstellers und die berechnete Prüfsumme), ein Urteil kommt heraus. Die Prüfung erzeugt aus deinem PAP Python-Code und testet ihn mit gültigen und ungültigen Prüfsummen, einmal richtig, einmal falsch.

Firmware-Freigabe

Zeichne einen PAP für die Freigabe. Die zwei Eingaben stehen schon da: soll (die Prüfsumme vom Hersteller, als Text) und ist (die selbst berechnete Prüfsumme, schon klein geschrieben). Der Soll-Wert kann Leerzeichen am Rand und Großbuchstaben haben, mach ihn zuerst mit einer Operation soll = soll.strip().lower() vergleichbar. Dann prüfst du, ob er überhaupt eine SHA-256-Prüfsumme sein kann: Hat soll nicht genau 64 Zeichen, gibst du "Prüfsumme ungültig" aus. Sonst vergleichst du ist == soll: gleich gibt "einspielen" aus, verschieden "nicht einspielen". Texte stehen in Anführungszeichen, die Bedingungen schreibst du als Python-Ausdruck.

  1. Nach den zwei Eingaben kommt eine Operation: soll = soll.strip().lower(). Sie macht den Soll-Wert vergleichbar (Leerzeichen am Rand weg, alles klein).
  2. Die erste Raute prüft die Länge: len(soll) == 64. Im „nein“-Zweig steht die Ausgabe "Prüfsumme ungültig".
  3. Im „ja“-Zweig kommt die zweite Raute ist == soll: „ja“ gibt "einspielen" aus, „nein“ gibt "nicht einspielen" aus.

Erste eigene Aufgabe: Datei prüfen

Jetzt schreibst du selbst, mit Tests als Sicherheitsnetz. Du setzt aus dem Beispiel eine Funktion zusammen, die ein einziges Urteil liefert: Stimmt die Datei, ja oder nein? Gib das Ergebnis mit return zurück.

Schreibe die Funktion pruefe_datei(pfad, soll). Sie liest die Datei blockweise (4096 Bytes, binär), berechnet die SHA-256-Prüfsumme und gibt True zurück, wenn sie gleich dem Soll-Wert ist, sonst False. Der Soll-Wert darf Großbuchstaben haben und Leerzeichen oder einen Zeilenumbruch am Rand: Mach ihn vor dem Vergleich vergleichbar. Die Tests prüfen die beiden Firmware-Dateien und eigene Dateien, die sie selbst schreiben.

Erwartet
pruefe_datei("R1_fw_3.2.1.bin", soll)      -> True   (Original)
pruefe_datei("R1_fw_3.2.1_usb.bin", soll)  -> False  (ein Bit anders)
  1. Das Gerüst kennst du aus dem vorgerechneten Beispiel: h = hashlib.sha256(), dann with open(pfad, "rb") as datei: und while True: mit block = datei.read(4096).
  2. In der Schleife: if not block: break, sonst h.update(block). Nach der Schleife kennt h.hexdigest() die Prüfsumme der ganzen Datei.
  3. Vergleiche am Ende mit dem bereinigten Soll-Wert: return h.hexdigest() == soll.strip().lower(). Der Vergleich liefert schon True oder False.

Code-Review: KI-Firmware-Prüfung

Eine KI hat ein Programm geliefert, das die Firmware vor dem Einspielen prüft. Es sieht aufgeräumt aus. Würdest du es freigeben? Klick die Zeilen an, die du für fehlerhaft hältst, dann lass auflösen.

Szenario: Firmware-Prüfung für den Roboter R1

Prompt eines Studierenden

Schreib mir ein Python-Skript: Auf dem USB-Stick des Servicetechnikers (Laufwerk E:) liegen die Firmware R1_fw_3.2.1.bin und die Datei R1_fw_3.2.1.bin.sha256 mit der SHA-256-Prüfsumme des Herstellers. Prüfe, ob die Firmware zur Prüfsumme passt, und sag, ob ich sie einspielen darf. Die Datei kann groß sein.

KI-Antwort (Python)

Tipp: Es sind vier Fehler eingebaut, in vier verschiedenen Zeilen. Einer bringt das Programm zum Absturz, die anderen nicht. Nicht jede Zeile ist falsch.

Würdest du das freigeben? Markiere die fehlerhaften Zeilen, dann lass auflösen.

Die vier Fehler

Fehler 1: Datei im Textmodus geöffnet (Zeile 8)

open(pfad) ohne "rb" liest Text. Eine Firmware ist aber kein Text: Python findet ungültige UTF-8-Folgen und bricht mit einem UnicodeDecodeError ab. Selbst bei einer Datei, die zufällig durchgeht, würden Zeilenenden umgewandelt und Bytes verändert, die Prüfsumme wäre falsch. Lösung: open(pfad, "rb") und die Bytes direkt einmischen, ohne encode. Ein Programm, das abstürzt, ist hier noch der harmloseste Fehler.

Fehler 2: Soll-Wert ungekürzt verglichen (Zeile 13)

.read() liefert den ganzen Dateiinhalt: die 64 Zeichen, zwei Leerzeichen, den Dateinamen und den Zeilenumbruch. Der Vergleich ist == soll ist deshalb nie wahr: Das Programm meldet bei jeder, auch bei der richtigen Datei „ABWEICHUNG“. Kein Absturz, nur eine Warnung, die niemand mehr ernst nimmt. Lösung: soll = open(...).read().split()[0].lower().

Fehler 3: MD5 statt SHA-256 (Zeile 7)

Der Hersteller veröffentlicht eine SHA-256-Prüfsumme, die KI nimmt hashlib.md5. Die Werte haben nicht einmal dieselbe Länge (32 statt 64 Zeichen), selbst mit allen anderen Korrekturen würde nie etwas übereinstimmen. Dazu ist MD5 gebrochen: Ein Angreifer kann gezielt Dateien mit demselben MD5 bauen. Lösung: hashlib.sha256(), und zwar das Verfahren, das der Hersteller nennt.

Fehler 4: Prüfsumme vom selben Stick (Zeile 4)

Der Fachfehler: Die Prüfsumme liegt auf demselben Stick wie die Firmware. Wer die Firmware austauschen kann, tauscht auch die .sha256-Datei aus, und das Programm meldet „OK“ für Schadcode. Die Prüfsumme hilft nur, wenn der Soll-Wert über einen zweiten, vertrauenswürdigen Weg kommt, etwa von der Download-Seite des Herstellers über HTTPS. Noch besser prüft das Gerät eine digitale Signatur (Lerneinheit). Die KI konnte das nicht wissen, denn der Prompt hat es ihr so beschrieben: Die Spezifikation war der Fehler.

Die Fehler einzeln zum Ausprobieren

Je ein Aufruf, damit du siehst, was passiert: der Textmodus, der ungekürzte Soll-Wert, MD5 und der getauschte Stick. Probiere dann die Korrektur.

# Fehler 1: Datei im Textmodus öffnen
with open("R1_fw_3.2.1.bin") as datei:
    inhalt = datei.read()
print(len(inhalt))
# Fehler 2: der ganze Inhalt der .sha256-Datei ist mehr als die Prüfsumme
inhalt = open("R1_fw_3.2.1.bin.sha256").read()
print(repr(inhalt[-24:]))                  # Dateiname und Zeilenumbruch hängen dran
print(len(inhalt), "Zeichen statt 64")
print(inhalt.split()[0] == inhalt)         # False: so ist ein Vergleich nie wahr
print(len(inhalt.split()[0]))              # 64: nur die erste Spalte ist die Prüfsumme
# Fehler 3: MD5 ist kürzer und gebrochen, passt auch nicht zur Prüfsumme des Herstellers
import hashlib

daten = open("R1_fw_3.2.1.bin", "rb").read()
print(len(hashlib.md5(daten).hexdigest()), "Zeichen bei md5")
print(len(hashlib.sha256(daten).hexdigest()), "Zeichen bei sha256")
# Fehler 4: Datei UND Prüfsumme vom selben Stick - ein Angreifer tauscht beides
import hashlib

schadcode = b"R1-FW 3.2.1 mit Schadcode"
pruefsumme_auf_dem_stick = hashlib.sha256(schadcode).hexdigest()   # vom Angreifer passend gemacht
print(hashlib.sha256(schadcode).hexdigest() == pruefsumme_auf_dem_stick)   # True: das Programm sagt OK

Korrigierte Version (die vier Stellen)

# Fehler 4: den Soll-Wert nicht vom Stick, sondern von der Hersteller-Seite (HTTPS) nehmen
# und in eine Textdatei oder Variable legen, bevor der Stick eingesteckt wird
PRUEFSUMME = "hersteller/R1_fw_3.2.1.bin.sha256"

def pruefsumme(pfad):
    h = hashlib.sha256()                       # Fehler 3
    with open(pfad, "rb") as datei:            # Fehler 1
        while True:
            block = datei.read(4096)
            if not block:
                break
            h.update(block)
    return h.hexdigest()

soll = open(PRUEFSUMME).read().split()[0].lower()   # Fehler 2
Merke

Bei KI-Code, der Dateien prüft, fragst du: Wird binär gelesen ("rb")? Ist der Soll-Wert wirklich nur die Prüfsumme? Ist das Verfahren SHA-256 und passt es zur Angabe des Herstellers? Und die wichtigste Frage: Woher kommt der Soll-Wert? Ein Programm, das beim ersten Test läuft, ist noch nicht sicher.

Typische Fehlermeldungen

Mit Bytes und Dateien kommen neue Fehlermeldungen. Diese sechs siehst du garantiert. Jedes Beispiel lässt sich ausführen: Schau dir die echte Meldung an und lies sie von unten nach oben (zuerst die letzte Zeile). Eine davon ist gar keine Meldung, sondern ein stiller Fehler.

TypeError: Text statt Bytes

Meldung: TypeError: Strings must be encoded before hashing. Der Hash arbeitet mit Bytes, du hast Text übergeben. Erst kodieren: hashlib.sha256("Drehzahl 1450".encode("utf-8")), oder gleich Bytes schreiben: b"Drehzahl 1450".

UnicodeDecodeError: Firmware im Textmodus gelesen

Meldung: UnicodeDecodeError: 'utf-8' codec can't decode byte 0xa9 in position 14: invalid start byte. Ohne "rb" versucht Python, die Bytes als UTF-8-Text zu lesen. Eine Firmware ist kein Text, also gibt es irgendwo ein Byte, das kein gültiges Zeichen ergibt. Lösung: open(pfad, "rb").

AttributeError: hexdigest auf Text

Meldung: AttributeError: 'str' object has no attribute 'hexdigest'. hexdigest() ist eine Methode des Hash-Objekts. Hier ist h bereits ihr Ergebnis, ein Text, und Text kennt kein hexdigest. Entweder das Objekt behalten (h = hashlib.sha256(...), später h.hexdigest()) oder den Text direkt verwenden. Dasselbe passiert mit h.update(...) nach hexdigest().

Stiller Fehler: digest() statt hexdigest()

Hier gibt es keine Meldung, nur ein falsches Ergebnis: False, obwohl die Datei stimmt. digest() liefert 32 rohe Bytes, soll ist ein Text mit 64 Zeichen. Bytes und Text sind nie gleich, auch wenn sie „dasselbe“ meinen. Das ist gefährlich, weil ein Programm so immer „ABWEICHUNG“ meldet (oder, mit umgekehrter Logik, immer „OK“). Vergleiche immer hexdigest() mit Text, und teste dein Programm einmal mit der richtigen Datei, damit du das „OK“ siehst.

FileNotFoundError: Datei nicht gefunden

Meldung: FileNotFoundError: [Errno 44] No such file or directory: 'R1_fw_3.2.1.bn'. Python findet keine Datei mit genau diesem Namen im Arbeitsordner. Prüfe Schreibweise, Endung und Ordner. Im Browser-Labor müssen die Dateien in der Aufgabe eingebaut sein; im Codespace muss die Datei neben dem Programm liegen oder der Pfad stimmen. Für Prüfprogramme gilt: Eine fehlende Datei ist ein Prüfergebnis („FEHLT“), kein Grund für einen Absturz (Training 3).

IndexError: leere .sha256-Datei

Meldung: IndexError: list index out of range. Bei einer leeren Datei liefert split() eine leere Liste, und [0] greift ins Leere. Das passiert bei einem abgebrochenen Download oder einer falschen Datei. Prüfe vorher: teile = ...split(), if len(teile) == 0: mit einer verständlichen Meldung (Training 2).

Lawineneffekt messen: verschiedene Bits zählen

Wie viel ändert sich beim Lawineneffekt wirklich? Du zählst die verschiedenen Bits. Dafür gibt es einen neuen Operator: ^ (XOR) vergleicht zwei ganze Zahlen Bit für Bit. Wo die Bits verschieden sind, steht im Ergebnis eine 1. Mit bin(...) (V02) siehst du das Ergebnis binär, und .count("1") zählt die Einsen.

a = 0b1100
b = 0b1010
print(bin(a ^ b))                    # 0b110: nur an Stellen mit verschiedenen Bits steht eine 1
print(bin(a ^ b).count("1"))         # 2 Bits sind verschieden

h = "ff"                             # ein Hex-Text
print(int(h, 16), bin(int(h, 16)))   # 255 0b11111111

Schreibe bits_unterschied(h1, h2): Die Funktion bekommt zwei Hex-Prüfsummen als Text und gibt zurück, in wie vielen Bits sie sich unterscheiden (bei SHA-256 von 256). Wandle die Hex-Texte mit int(h, 16) in Zahlen um. Das Programm misst den Lawineneffekt für „Drehzahl 1450“ gegen „Drehzahl 1451“: Etwa die Hälfte der 256 Bits sollte verschieden sein. Die Tests prüfen einfache Fälle von Hand und diesen Messwert.

Erwartet
bits_unterschied("01", "00") -> 1
bits_unterschied("a5", "5a") -> 8
Drehzahl 1450 gegen 1451 -> 116 von 256 Bit verschieden
  1. Ein Hex-Text wird mit int(h, 16) zur Zahl (V02). Zwei Zahlen vergleichst du bitweise mit ^: Wo die Bits verschieden sind, steht im Ergebnis eine 1.
  2. bin(zahl) liefert den Binärtext ('0b101...'), und .count("1") zählt darin die Einsen. Kombiniert: bin(int(h1, 16) ^ int(h2, 16)).count("1").
  3. Ohne ^: Gehe beide Hex-Texte Stelle für Stelle durch, wandle jede Ziffer mit int(ziffer, 16) zu einer Zahl 0 bis 15, mache daraus mit bin(...) vier Bits und zähle, wo sie verschieden sind. Das ist länger, aber es geht.

Firmware-Stand der Zelle prüfen

Wiederholung aus V16 und V17: JSON-Text lesen, Dictionaries, Schleife und Vergleich. Der Leitrechner der Zelle liefert den Firmware-Stand aller Geräte als JSON-Text (geraete: Liste von Dictionaries mit id, firmware und sha256). Der Hersteller liefert ein Dictionary ID zu Version und Prüfsumme. Schreibe firmware_pruefen(stand_text, hersteller): Sie gibt ein Dictionary mit zwei Listen zurück, in der Reihenfolge der Geräte. In "update" stehen die IDs, deren Version nicht der des Herstellers entspricht. In "hash_falsch" stehen die IDs, deren Version stimmt, deren Prüfsumme aber nicht (vergleiche nach strip() und lower()). Ein Gerät kommt höchstens in eine der beiden Listen. Geräte, die der Hersteller nicht kennt, werden übersprungen.

Erwartet

  1. Der Stand ist JSON-Text: stand = json.loads(stand_text) (V17). Die Geräte stehen in stand["geraete"], eine Liste von Dictionaries, durch die du mit for g in ... läufst.
  2. Zum Gerät passt der Eintrag des Herstellers: soll = hersteller.get(g["id"]). Ist das None, kennt der Hersteller das Gerät nicht: continue.
  3. Erst die Version vergleichen (g["firmware"] != soll["version"], dann nach update), nur sonst die Prüfsumme (elif, beide Seiten mit strip().lower(), dann nach hash_falsch). Am Ende ein Dictionary mit beiden Listen zurückgeben.

Manipulationssicheres Protokoll: die Hash-Kette

Ein Protokoll, das jemand nachträglich ändern kann, ist wenig wert. Ein Trick: Jede Zeile bekommt einen Hash, in den der Hash der vorigen Zeile eingeht (sha256(vorheriger_hash + zeile)). Ändert jemand eine Zeile, stimmt ihr Hash nicht mehr, und weil der nächste Hash auf diesem aufbaut, reißt die Kette. Das nennt man Hash-Kette (die Idee hinter vielen manipulationssicheren Logs). Die Anforderungen des Cyber Resilience Act nennen die Protokollierung sicherheitsrelevanter Ereignisse und den Schutz von Daten vor Manipulation (Lerneinheit).

Das Programm baut aus den Logzeilen des Roboters R1 eine Kette (baue_protokoll ist schon da). Schreibe erste_manipulation(protokoll): Das Protokoll ist eine Liste von Paaren (zeile, gespeicherter_hash). Die Funktion prüft die Kette von vorn und gibt den Index (0, 1, 2 …) der ersten Zeile zurück, deren gespeicherter Hash nicht zur Kette passt, sonst None. Die Tests ändern Zeilen, Hashes, löschen eine Zeile und berechnen sogar den Hash einer geänderten Zeile neu.

Erwartet
unverändert -> None
Zeile 2 nachträglich geändert -> 2
  1. Die Prüfung läuft wie das Bauen der Kette, nur mit Vergleich: Starte mit vorher = START und gehe die Einträge der Reihe nach durch.
  2. Für jeden Eintrag zeile, gespeichert = protokoll[i]: Stimmt kettenhash(vorher, zeile) nicht mit gespeichert überein, ist i die erste manipulierte Stelle: return i.
  3. Passt der Eintrag, wird sein gespeicherter Hash zum vorher des nächsten: vorher = gespeichert. Nach der Schleife (nichts gefunden) gibst du None zurück.
