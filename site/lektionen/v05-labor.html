Werkzeugkasten

Heute neu in Python: kein neuer Befehl, sondern eine neue Arbeitsweise. Du übersetzt ein Struktogramm in Code, schreibst verschachtelte Verzweigungen lesbar, prüfst Eingaben mit if und leitest Testfälle aus dem Struktogramm ab. Voraus gesetzt werden print, input, float, Variablen, math, Vergleiche, and/or/not und if/elif/else aus V01 bis V04. Die Klausur verlangt, dass du Code von Hand schreibst. Darum gehen wir in kleinen Schritten vom Vormachen zum Selberschreiben, und die Hilfen werden dabei weniger.

Syntax-Karte 2

Verzweigung: if und else

x = float(input("x: "))
if x < 0:
    betrag = -x
else:
    betrag = x
print("Betrag:", betrag)
  • Nach der Bedingung steht ein Doppelpunkt. Ohne ihn: SyntaxError.
  • Der Zweig darunter ist 4 Leerzeichen eingerückt. Die Einrückung ist der Rahmen des Zweigs.
  • else: hat keine Bedingung und steht genau unter seinem if.
  • Einfache Verzweigung (nur Ja-Zweig): else einfach weglassen.
  • Das print ganz links läuft immer, nach der Verzweigung.
Syntax-Karte 3

Mehrfachverzweigung: elif

s = float(input("Sicherheitsfaktor S: "))
if s >= 1.5:
    print("sicher")
elif s >= 1.0:
    print("knapp")
else:
    print("Versagen")
  • Von oben nach unten: Der erste Treffer gewinnt, danach wird nichts mehr geprüft.
  • Die Reihenfolge zählt. Bei s = 1.6 würde die Frage „≥ 1.0“ zuerst auch passen: Dann kämen die Fälle durcheinander.
  • Drei einzelne if sind keine Mehrfachverzweigung: Jedes wird für sich geprüft.

  • Jeder Zweig legt alle Variablen fest, die danach gebraucht werden (sonst NameError).

Aufgabe: Ein Programm schlägt für eine Welle einen Werkstoff vor. Erst steht das Struktogramm, dann der Code, der es Zeile für Zeile umsetzt. Lies beides nebeneinander, dann führe den Code aus. Die Eingaben stehen im Feld darunter (Beispiel: 180 MPa bei 20 °C). Drück danach auf „Schritt für Schritt“: Dann siehst du, welche Zeilen Python überspringt.

Das Struktogramm

Der Code dazu

  1. Zeilen 5 und 6: Die beiden Anweisungen oben im Struktogramm. input() liefert Text, float() macht daraus eine Zahl (V03).
  2. Zeile 8: Die erste Verzweigung ist die Plausibilitätsprüfung. or verknüpft die drei Fälle: Es genügt, dass eine Bedingung zutrifft. Die Prüfung steht ganz oben, damit nie mit unsinnigen Werten gerechnet wird.

Szenario: Passungsart aus dem Spiel bestimmen

Prompt eines Studierenden (mit Struktogramm)

Schreib mir ein Python-Programm nach diesem Struktogramm. Eingaben in µm: Höchstspiel pmax und Mindestspiel pmin. Ist pmax kleiner als pmin, ist die Eingabe unplausibel. Sonst: Mindestspiel ≥ 0 ist eine Spielpassung, Höchstspiel ≤ 0 eine Übermaßpassung, alles andere eine Übergangspassung. Die Grenzwerte 0 gehören zur Spielpassung beziehungsweise zur Übermaßpassung.

KI-Antwort (Python, vorab erzeugtes Beispiel)

Tipp: Es sind drei Fehler eingebaut, in drei verschiedenen Zeilen. Nicht jede Zeile ist falsch.

Würdest du das freigeben? Markiere die fehlerhaften Zeilen, dann lass auflösen.

Die drei Fehler

Fehler 1: Grenzwert falsch (Zeile 7)

Das Struktogramm sagt „pmin ≥ 0“, der Code schreibt pmin > 0. Bei genau 0 µm Mindestspiel (zum Beispiel Höchstspiel 30, Mindestspiel 0) wird die erste Frage mit „Nein“ beantwortet, und der Fall landet bei einer der anderen Passungsarten. Richtig ist >=: Das Mindestspiel 0 gehört zur Spielpassung. Ein Grenzwert-Testfall hätte es gezeigt.

Fehler 2: Vergleich in die falsche Richtung (Zeile 9)

Das Struktogramm sagt „pmax ≤ 0“, der Code schreibt pmax >= 0. Zusammen mit Fehler 1 ergibt das für Höchstspiel 30 und Mindestspiel 0 die Antwort „Übermaßpassung“, obwohl es eine Spielpassung ist. Umgekehrt bekommt eine echte Übermaßpassung (Höchstspiel −10, Mindestspiel −30) die Antwort „Übergangspassung“. Solche Richtungsfehler übersieht man beim Lesen leicht, ein Testfall pro Zweig fängt sie.

Fehler 3: Ausgabe außerhalb des Zweigs (Zeile 13)

Die letzte Zeile steht ganz links, also nach der gesamten Verzweigung. Bei unplausibler Eingabe wird art nie festgelegt, und print bricht mit einem NameError ab. Im Struktogramm steht das Ausgabe-Kästchen im Nein-Zweig. Richtig: eine Stufe eingerückt unter dem else: von Zeile 6.

Die KI-Version zum Ausprobieren

Mit Höchstspiel 30 und Mindestspiel 0 kommt eine falsche Passungsart heraus („Übermaßpassung“ statt Spielpassung). Ändere die Eingaben auf −10 und −30 (wieder falsch: „Übergangspassung“ statt Übermaßpassung) und auf 10 und 20 (NameError). Drück auf „Schritt für Schritt“, um jede Zeile einzeln zu sehen.

pmax = float(input("Höchstspiel in µm: "))
pmin = float(input("Mindestspiel in µm: "))

if pmax < pmin:
    print("Eingabe unplausibel")
else:
    if pmin > 0:
        art = "Spielpassung"
    elif pmax >= 0:
        art = "Übermaßpassung"
    else:
        art = "Übergangspassung"
print("Passungsart:", art)

Merke

Das Programm hat keinen Syntaxfehler und läuft bei den meisten Eingaben „irgendwie“. Gefunden hättest du die Fehler mit deiner Testtabelle aus dem Struktogramm: ein Fall pro Zweig und die Grenzwerte. Prüfe KI-Code immer gegen die Zweige und die Grenzen, nicht nur gegen die Formel.

Typische Fehlermeldungen

Fehlermeldungen sind keine Strafe, sondern ein Wegweiser. Diese vier siehst du bei Verzweigungen garantiert. Jedes Beispiel lässt sich ausführen: Schau dir die echte Meldung an und lies sie von unten nach oben (zuerst die letzte Zeile).

SyntaxError: Doppelpunkt vergessen

Meldung: SyntaxError: expected ':'. Gemeint: Hinter der Bedingung fehlt der Doppelpunkt. Python zeigt mit einem Pfeil an die Stelle. Der Doppelpunkt steht auch hinter else und elif ….

IndentationError: Einrückung fehlt

Meldung: IndentationError: expected an indented block after 'if' statement on line 2. Gemeint: Nach dem Doppelpunkt muss der Zweig eingerückt sein (4 Leerzeichen). Genauso, wenn die Zeilen eines Zweigs verschieden weit eingerückt sind (unindent does not match any outer indentation level).

SyntaxError: = statt ==

Meldung: SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?. Ein einzelnes = speichert einen Wert, ein doppeltes == fragt „gleich?“. In einer Bedingung brauchst du die Frage.

NameError: Ein Zweig legt die Variable nicht fest

Meldung: NameError: name 'werkstoff' is not defined. Bei 20 °C läuft der Ja-Zweig nicht, also gibt es werkstoff nie. Im Struktogramm fehlt ein Kästchen im Nein-Zweig. Lösung: ein else: ergänzen, das die Variable auch dort festlegt.
