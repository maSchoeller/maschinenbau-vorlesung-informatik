Heute neu in Python: kein neuer Befehl, sondern eine neue Arbeitsweise. Syntax-Karte 3

Verzweigung: if und else

x = float(input("x: "))
if x < 0:
    betrag = -x
else:
    betrag = x
print("Betrag:", betrag)
  • Nach der Bedingung steht ein Doppelpunkt. Ohne ihn: SyntaxError.
  • Der Zweig darunter ist 4 Leerzeichen eingerückt. Die Einrückung ist der Rahmen des Zweigs.
  • else: hat keine Bedingung und steht genau unter seinem if.
  • Einfache Verzweigung (der Weg „nein“ führt direkt weiter): else einfach weglassen.
  • Das print ganz links läuft immer, nach der Verzweigung.
Syntax-Karte 4

Mehrfachverzweigung: elif

s = float(input("Sicherheitsfaktor S: "))
if s >= 1.5:
    print("sicher")
elif s >= 1.0:
    print("knapp")
else:
    print("Versagen")
  • Von oben nach unten: Der erste Treffer gewinnt, danach wird nichts mehr geprüft.
  • Die Reihenfolge zählt. Bei s = 1.6 würde die Frage „≥ 1.0“ zuerst auch passen: Dann kämen die Fälle durcheinander.
  • Drei einzelne if sind keine Mehrfachverzweigung: Jedes wird für sich geprüft.

  • Jeder Zweig legt alle Variablen fest, die danach gebraucht werden (sonst NameError).

Vorgerechnetes Beispiel: Werkstoffvorschlag

Aufgabe: Ein Programm schlägt für eine Welle einen Werkstoff vor. Erst steht der Programmablaufplan (PAP), dann der Code, der ihn Zeile für Zeile umsetzt. Folge im PAP den Linien von oben nach unten und finde im Code die passende Zeile, dann führe den Code aus. Die Eingaben stehen im Feld darunter (Beispiel: 180 MPa bei 20 °C). Drück danach auf „Schritt für Schritt“: Dann siehst du, welche Zeilen Python überspringt.

Der Programmablaufplan

Der Code dazu

  1. Zeilen 5 und 6: Die beiden Parallelogramme oben im PAP („spannung einlesen“, „temperatur einlesen“). input() liefert Text, float() macht daraus eine Zahl (V03).
  2. Zeile 8: Die erste Verzweigung ist die Plausibilitätsprüfung. or verknüpft die drei Fälle: Es genügt, dass eine Bedingung zutrifft. Die Prüfung steht ganz oben, damit nie mit unsinnigen Werten gerechnet wird.
  3. Zeilen 9 und 10: Der Weg „ja“ (ein Parallelogramm, eingerückt) und das else: für den Weg „nein“. Alles, was im PAP rechts vom „nein“ steht, ist ab Zeile 11 um eine Stufe eingerückt.
  4. Zeilen 11 bis 15: Eine verschachtelte Verzweigung. Erst fragt der Code die Temperatur, nur im warmen Bereich dann die Spannung (Grenze 200). Die zweite Frage hat nur im Weg „ja“ der Temperatur-Raute Sinn, darum Verschachtelung: eine Raute innerhalb eines Zweigs.
  5. Zeilen 17 bis 22: Die Mehrfachverzweigung als if/elif/else. Hier sind die Fälle gleichrangig (immer dieselbe Größe, die Spannung), also elif statt Verschachtelung. Die Reihenfolge ≤ 140, dann ≤ 220 ist wichtig.
  6. Zeile 23: Das letzte Parallelogramm im PAP hängt hinter dem Zusammenlauf der Linien aus allen fünf Werkstoff-Rechtecken, aber noch im Weg „nein“ der Plausibilitätsprüfung. Im Code steht print deshalb eine Stufe tief (unter dem else: von Zeile 10) und hinter beiden Temperaturzweigen: Es läuft nur bei plausibler Eingabe, dann aber immer.
  7. Selbsterklärung: Tippe diese Testfälle in die Eingabefelder und prüfe die Ausgabe: 250 / 400 (Sonderwerkstoff), −5 / 20 (unplausibel), 140 / 20 (Grenzwert), 100 / 300 (Grenzwert Temperatur). Was ändert sich bei 100 / 300.1?

Ablauf verfolgen

Bevor du Code schreibst, musst du den Weg durch eine Verzweigung lesen können. Führe das Programm im Kopf aus und trage ein, was nach der jeweiligen Zeile in den Variablen steht. Wahrheitswerte schreibst du als True oder False, Text mit Anführungszeichen.

Zeilen ordnen

Alle Zeilen sind da, aber durcheinander. Bring sie in die richtige Reihenfolge und in die richtige Einrückung: Mit den Pfeilen links und rechts an der Zeile rückst du sie ein. Die Einrückung ist der Rahmen eines Zweigs. Im PAP entspricht ein Zweig dem Weg „ja“ oder „nein“ hinter einer Raute. Manche Zeilen sind Ablenker: Sie gehören nicht ins Programm.

Setze diesen PAP um. Achte darauf, welche Zeilen im Weg „ja“ der ersten Raute stehen. pumpe_an ist ein Wahrheitswert (V04): Der Vergleich == 'j' in der ersten Zeile macht aus der Eingabe True oder False.

Lücken füllen

Jetzt tippst du Teile selbst. Ergänze die vier Lücken so, dass das Programm den PAP umsetzt. Geprüft wird nicht nur dein Wortlaut, sondern ob das Programm auf jedem Pfad das Richtige tut.

streckgrenze = float(input("Streckgrenze Re in MPa: "))
spannung = float(input("Spannung in MPa: "))
if streckgrenze <= 0 @@or@@ spannung <= 0:
    print("Eingabe unplausibel")
@@else@@:
    s = streckgrenze / spannung
    if s @@>=@@ 1.5:
        print("sicher")
    elif s >= 1.0:
        print("knapp")
    else:
        print(@@"Versagen"@@)
  1. Lücke 1: Die Eingabe ist unplausibel, wenn mindestens eine der beiden Größen unsinnig ist. Welches Wort verknüpft „oder“?
  2. Lücke 2: Das Schlüsselwort für „sonst“, ohne Bedingung (mit Doppelpunkt dahinter).
  3. Lücke 3: Der Grenzwert 1.5 gehört laut PAP („s ≥ 1,5?“) zu „sicher“. Welcher Vergleich schließt ihn ein?
  4. Lücke 4: Text steht in Anführungszeichen, auch hier.

Jetzt in die andere Richtung: Der Python-Code ist gegeben, im Programmablaufplan fehlen Symbole. Im PAP schreibst du „oder“ und „≤“, du darfst aber auch or und <= tippen. Wer einen Code in einen PAP zurückübersetzen kann, versteht ihn wirklich, zum Beispiel den Code einer KI.

Eine KI hat nach einem PAP Code geliefert. Er sieht sauber aus und läuft los. Würdest du ihn freigeben? Vergleiche ihn Pfad für Pfad mit dem PAP, klick die Zeilen an, die du für fehlerhaft hältst, dann lass auflösen.

Szenario: Passungsart aus dem Spiel bestimmen

Prompt eines Studierenden (mit PAP)

Schreib mir ein Python-Programm nach diesem Programmablaufplan (Bild im Anhang). Eingaben in µm: Höchstspiel pmax und Mindestspiel pmin. Ist pmax kleiner als pmin, ist die Eingabe unplausibel. Sonst: Mindestspiel ≥ 0 ist eine Spielpassung, Höchstspiel ≤ 0 eine Übermaßpassung, alles andere eine Übergangspassung. Die Grenzwerte 0 gehören zur Spielpassung beziehungsweise zur Übermaßpassung.

KI-Antwort (Python, vorab erzeugtes Beispiel)

Tipp: Es sind drei Fehler eingebaut, in drei verschiedenen Zeilen. Nicht jede Zeile ist falsch.

Würdest du das freigeben? Markiere die fehlerhaften Zeilen, dann lass auflösen.

Die drei Fehler

Fehler 1: Grenzwert falsch (Zeile 7)

Der PAP fragt „pmin ≥ 0?“, der Code schreibt pmin > 0. Bei genau 0 µm Mindestspiel (zum Beispiel Höchstspiel 30, Mindestspiel 0) wird die erste Frage mit „nein“ beantwortet, und der Fall landet bei einer der anderen Passungsarten. Richtig ist >=: Das Mindestspiel 0 gehört zur Spielpassung. Ein Grenzwert-Testfall hätte es gezeigt.

Fehler 2: Vergleich in die falsche Richtung (Zeile 9)

Der PAP fragt „pmax ≤ 0?“, der Code schreibt pmax >= 0. Zusammen mit Fehler 1 ergibt das für Höchstspiel 30 und Mindestspiel 0 die Antwort „Übermaßpassung“, obwohl es eine Spielpassung ist. Umgekehrt bekommt eine echte Übermaßpassung (Höchstspiel −10, Mindestspiel −30) die Antwort „Übergangspassung“. Solche Richtungsfehler übersieht man beim Lesen leicht, ein Testfall pro Zweig fängt sie.

Fehler 3: Ausgabe außerhalb des Zweigs (Zeile 13)

Die letzte Zeile steht ganz links, also nach der gesamten Verzweigung. Bei unplausibler Eingabe wird art nie festgelegt, und print bricht mit einem NameError ab. Im PAP hängt das Ausgabe-Parallelogramm im Weg „nein“ der ersten Raute, die Linie vom „ja“ geht an ihm vorbei zum Ende. Richtig: eine Stufe eingerückt unter dem else: von Zeile 6.

Die KI-Version zum Ausprobieren

Mit Höchstspiel 30 und Mindestspiel 0 kommt eine falsche Passungsart heraus („Übermaßpassung“ statt Spielpassung). Ändere die Eingaben auf −10 und −30 (wieder falsch: „Übergangspassung“ statt Übermaßpassung) und auf 10 und 20 (NameError). Drück auf „Schritt für Schritt“, um jede Zeile einzeln zu sehen.

pmax = float(input("Höchstspiel in µm: "))
pmin = float(input("Mindestspiel in µm: "))

if pmax < pmin:
    print("Eingabe unplausibel")
else:
    if pmin > 0:
        art = "Spielpassung"
    elif pmax >= 0:
        art = "Übermaßpassung"
    else:
        art = "Übergangspassung"
print("Passungsart:", art)

Korrigierte Version

pmax = float(input("Höchstspiel in µm: "))
pmin = float(input("Mindestspiel in µm: "))

if pmax < pmin:
    print("Eingabe unplausibel")
else:
    if pmin >= 0:
        art = "Spielpassung"
    elif pmax <= 0:
        art = "Übermaßpassung"
    else:

Merke

Das Programm hat keinen Syntaxfehler und läuft bei den meisten Eingaben „irgendwie“. Gefunden hättest du die Fehler mit deiner Testtabelle aus dem PAP: ein Fall pro Pfad und die Grenzwerte. Prüfe KI-Code immer gegen die Pfade und die Grenzen, nicht nur gegen die Formel.

Typische Fehlermeldungen

Fehlermeldungen sind keine Strafe, sondern ein Wegweiser. Diese vier siehst du bei Verzweigungen garantiert. Jedes Beispiel lässt sich ausführen: Schau dir die echte Meldung an und lies sie von unten nach oben (zuerst die letzte Zeile).

SyntaxError: Doppelpunkt vergessen

Meldung: SyntaxError: expected ':'. Gemeint: Hinter der Bedingung fehlt der Doppelpunkt. Python zeigt mit einem Pfeil an die Stelle. Der Doppelpunkt steht auch hinter else und elif ….

IndentationError: Einrückung fehlt

Meldung: IndentationError: expected an indented block after 'if' statement on line 2. Gemeint: Nach dem Doppelpunkt muss der Zweig eingerückt sein (4 Leerzeichen). Genauso, wenn die Zeilen eines Zweigs verschieden weit eingerückt sind (unindent does not match any outer indentation level).

SyntaxError: = statt ==

Meldung: SyntaxError: invalid syntax. Maybe you meant '==' or ':=' instead of '='?. Ein einzelnes = speichert einen Wert, ein doppeltes == fragt „gleich?“. In einer Bedingung brauchst du die Frage.

NameError: Ein Zweig legt die Variable nicht fest

Meldung: NameError: name 'werkstoff' is not defined. Bei 20 °C läuft der Weg „ja“ nicht, also gibt es werkstoff nie. Im PAP fehlt im Weg „nein“ ein Rechteck. Lösung: ein else: ergänzen, das die Variable auch dort festlegt.

Messwert: gut oder Ausschuss

Eine Welle hat das Nennmaß 25,00 mm mit ±0,05 mm Toleranz. Setze den PAP um. Die Grenzmaße 24,95 und 25,05 gehören noch zu „Gut“. Denke an V03: Kommazahlen vergleichst du an der Grenze mit einer winzigen Rechentoleranz (zum Beispiel + 1e-9).

Ausgabe genau so:
Gut
Ausschuss
  1. Einlesen mit float(input(...)). Die Raute im PAP fragt „|messwert − 25,00| ≤ 0,05?“, also „Abstand zum Nennmaß ≤ Abmaß“: Der Abstand ist abs(messwert - 25.0).
  2. Direkt abs(messwert - 25.0) <= 0.05 fällt bei 25.05 durch (0.05000000000000071). Addiere rechts 1e-9.
  3. Dann if ...: mit print("Gut") und else: mit print("Ausschuss").

Schnittgeschwindigkeit mit Eingabeprüfung

Beim Drehen gilt vc = π · d · n / 1000 (Durchmesser d in mm, Drehzahl n in 1/min, vc in m/min). Setze den PAP um: erst die Eingabe prüfen, dann rechnen. Lies zuerst d, dann n ein.

Ausgaben genau so (Beispiel d = 60, n = 1000):
vc = 188.5 m/min
Eingabe unplausibel
  1. Zuerst beide Werte einlesen und mit float() umwandeln, dann erst prüfen.
  2. Die Prüfung hat vier Teile, die mit or verbunden sind: „d zu klein“, „d zu groß“, „n zu klein“, „n zu groß“. Die Grenzen 1000 und 20000 selbst sind noch erlaubt.
  3. Im else-Zweig stehen beide Anweisungen: vc = math.pi * d * n / 1000 und print(f"vc = {vc:.1f} m/min").

Hydraulikdruck bewerten

Der Druck einer Hydraulikanlage in bar wird bewertet. Der PAP enthält eine Kette von Rauten, jede im Weg „nein“ der vorigen: Schreibe sie mit elif, nicht mit drei einzelnen if. Die Grenzen 250 und 350 gehören jeweils zur niedrigeren Stufe.

Ausgaben genau so:
Eingabe unplausibel
Zustand: Normalbetrieb
Zustand: Warnung
Zustand: Abschaltung
  1. Die Prüfung der Eingabe ist das if. Alle weiteren Fälle sind elif, das Ende ist else. Alles zusammen ist eine Kette.
  2. Die Reihenfolge ist wichtig: erst „≤ 250“, dann „≤ 350“. Dann musst du bei der zweiten Frage nicht mehr „größer als 250“ prüfen: Wer hier ankommt, ist es schon.
  3. Grenzen mit <=, nicht <. Teste 250 und 350 selbst.

Heizungsregelung: verschachtelt

Eine Heizungsregelung vergleicht die Ist-Temperatur mit der Soll-Temperatur (beides in °C). Zuerst fragt sie, ob es zu kalt ist; nur dann ist die zweite Frage „sehr kalt?“ sinnvoll. Im Weg „nein“ ist es die Frage, ob es zu warm ist. Setze den PAP mit verschachtelten Verzweigungen um. Lies erst soll, dann ist ein.

Ausgaben genau so (Beispiel soll 60, ist 55):
Heizen: volle Leistung
Heizen: halbe Leistung
Kühlen
Temperatur halten
  1. Zwei äußere Zweige: „ist < soll − 2“ (Ja) und sonst. In jedem davon steckt eine eigene, zweiseitige Verzweigung.
  2. Jede Stufe in der Einrückung entspricht einer Raute, in deren Zweig du dich befindest. Vier Leerzeichen mehr pro Ebene.
  3. Probiere die Grenzen: ist = soll − 2 ist nicht „zu kalt“ (kein <=), ist = soll − 10 ist noch „halbe Leistung“.

Testfälle je Pfad: Werkstoff-PAP

Hier schreibst du keinen Programmcode, sondern Testdaten. Lies den Werkstoff-PAP aus dem Vorgerechneten Beispiel und lege sechs Testfälle fest, sodass jeder der sechs Pfade von Start bis Ende genau einmal durchlaufen wird (Spannung in MPa, Temperatur in °C, die Reihenfolge ist egal). Dazu zwei Grenzwerte. Ersetze jedes None durch eine Zahl.

  • Die sechs Zweige: unplausibel, warm (≤ 200 und > 200), kühl (≤ 140, ≤ 220, darüber).
  • grenze_spannung: größte Spannung bei 20 °C, die noch zu S235JR gehört.
  • grenze_temperatur: größte Temperatur bei Spannung 150, bei der noch nicht der warmfeste Bereich gilt.
  1. Folge dem PAP von Start aus: Welche Antworten („ja“/„nein“) an den Rauten führen zu Pfad 1, 2, …? Den Pfad „unplausibel“ erreichst du zum Beispiel mit einer negativen Spannung.
  2. Für die kühlen Zweige: Temperatur z. B. 20, Spannung unter 140, zwischen 140 und 220, über 220. Für die warmen: Temperatur über 300 mit Spannung bis 200 und über 200.
  3. Die Grenzwerte sind die Zahlen, die noch gerade zu „≤ 140“ beziehungsweise „nicht > 300“ gehören.

PAP zeichnen und vergleichen

Öltemperatur überwachen

In der Klausur zeichnest du PAPs von Hand. Nimm Papier und Stift (oder ein Tablet) und zeichne den Programmablaufplan zu diesem Code. Erst danach klappst du die Musterlösung auf und vergleichst. Dein PAP muss nicht gleich aussehen, aber dieselben Pfade, Fragen und Texte haben.

temperatur = float(input("Öltemperatur in °C: "))
if temperatur < 0 or temperatur > 150:
    print("Eingabe unplausibel")
elif temperatur > 110:
    print("Alarm: Öl zu heiß")
elif temperatur >= 90:
    print("Warnung")
else:
    print("Betrieb normal")
  1. Zeichne zuerst Start, das Einlesen und die erste Raute. Beschrifte beide Ausgänge.
  2. Jedes elif ist eine neue Raute im Weg „nein“. Das letzte else ist der letzte Weg „nein“ ohne eigene Raute.
  3. Lass alle Wege am Ende zusammenlaufen: ein Ende, Pfeile in die Linie.
Musterlösung aufklappen (erst nach deinem Versuch)

Vier Pfade, also vier Testfälle: zum Beispiel −5 (unplausibel), 120 (Alarm), 100 (Warnung), 50 (normal), dazu die Grenzen 110 (noch Warnung) und 90 (schon Warnung).

Prüfliste: Genau ein Start? Jede Raute mit „ja“ und „nein“ beschriftet? Eingabe und Ausgaben als Parallelogramme? Alle Pfeile mit Spitze? Kein Weg endet im Nichts?

Knobelaufgabe: Quadratische Gleichung mit Randfällen

Die Gleichung a·x² + b·x + c = 0 sieht einfach aus, hat aber viele Randfälle: Ist a gleich 0, ist es gar keine quadratische Gleichung mehr, und dann kann sogar b gleich 0 sein. Setze diesen PAP um. Lies a, b, c in dieser Reihenfolge ein (float), nutze math.sqrt und gib Kommazahlen mit zwei Nachkommastellen aus.

Ausgaben genau so (Beispiel a = 1, b = −4, c = 3):
x1 = 3.00, x2 = 1.00
x = 2.50
x = -1.00 (doppelt)
keine reelle Lösung
unendlich viele Lösungen
keine Lösung

Die Zeilen oben sind alle sechs möglichen Ausgaben, jeweils mit Beispielwerten.

  1. Die erste Raute fragt a == 0. Ihr Weg „ja“ enthält zwei weitere Rauten (b == 0, dann c == 0), der Weg „nein“ die Diskriminante.
  2. Der Weg „nein“ beginnt mit d = b ** 2 - 4 * a * c (Rechteck), dann folgt die Raute-Kette („D < 0?“, „D = 0?“) mit if, elif, else.
  3. Die Formel für zwei Lösungen: (-b + math.sqrt(d)) / (2 * a) und mit Minus. Vergiss die Klammern um 2 * a nicht.
