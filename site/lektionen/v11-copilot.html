V11 · Phase 2 Werkzeug · Lerneinheit

Programmieren mit Copilot: spezifizieren, generieren, prüfen

Ab jetzt darf die KI Code erzeugen. Deine Arbeit verschiebt sich: Du beschreibst den Auftrag so genau, dass die KI wenig raten muss, du schreibst die Testfälle vorher von Hand, und du prüfst, bevor du etwas übernimmst. Ein Programmablaufplan ist dafür ein sehr guter Prompt.

Nach dieser Lerneinheit kannst du:

  • einen Auftrag als PAP und als Prompt formulieren und mit den fünf Kriterien Eingaben, Ausgaben, Einheiten, Grenzfälle und Beispiele bewerten,
  • Testfälle vor dem Generieren von Hand aufschreiben und damit KI-Code prüfen (auch an der Grenze: >= oder >?),
  • import in drei Schreibweisen lesen, Module der Standardbibliothek und ein eigenes Modul benutzen,
  • erklären, was pip tut und warum ein erfundenes Paket in KI-Code gefährlich ist,
  • GitHub Copilot über den Studierendenzugang einrichten und in Codespaces benutzen.

Das Schreiben der Python-Bausteine übst du im Programmierlabor. Vorausgesetzt sind V01 bis V10, auch Funktionen (V07), Listen (V08) und List Comprehension (V10).

Heute schon beantragen

Der Studierendenstatus bei GitHub kann Stunden bis mehrere Wochen dauern. Wenn du Copilot im Kurs selbst nutzen willst, stell den Antrag am besten noch heute: Die Anleitung steht in Abschnitt 3. Alle Aufgaben lassen sich auch ohne Copilot lösen.

1 Warum?

Eine Konstrukteurin braucht ein kleines Programm, das für eine Welle-Bohrung-Paarung sagt, ob eine Passung Spiel, Übermaß oder Übergang ergibt. Sie fragt die KI, einmal mit einem Satz und einmal mit ihrem Programmablaufplan. Beide Antworten sehen professionell aus. Eine davon hat einen Fehler, der erst an der Grenze auffällt.

Derselbe Auftrag, zwei Prompts

Hinweis: Die beiden Antworten unten sind Beispiel-Antworten. Sie sind nicht aus einer echten Anfrage kopiert, sondern so formuliert, wie ein Code-Assistent typischerweise antwortet, und mit den Fehlern versehen, die in der Praxis oft vorkommen. Wie echte Antworten aussehen, sieht jede Anfrage anders aus. Die Testfälle, mit denen beide Antworten geprüft werden, stehen vorab fest: vier Paarungen mit Nennmaß 25 mm, darunter die Grenze, an der das Spiel genau 0 ist.

Prompt A: ein Satz

Beispiel-Antwort, nicht aus einer echten Anfrage

Schreib mir was für Passungen

# Beispiel-Antwort auf Prompt A
# Abmaße in mm für Nennmaß 25 (von der KI genannt)
ABMASSE = {
    "H7": (0.000, 0.021),
    "g6": (-0.005, -0.018),
    "h6": (-0.013, 0.000),
    "k6": (0.002, 0.015),
    "r6": (0.023, 0.036),
}


def passungsart(bohrung, welle, nennmass=25.0):
    b_min = nennmass + ABMASSE[bohrung][0]
    b_max = nennmass + ABMASSE[bohrung][1]
    w_min = nennmass + min(ABMASSE[welle])
    w_max = nennmass + max(ABMASSE[welle])
    if b_min > w_max:
        return "Spielpassung"
    elif b_max < w_min:
        return "Übermaßpassung"
    else:
        return "Übergangspassung"


def hoechstspiel(bohrung, welle, nennmass=25.0):
    return round(nennmass + ABMASSE[bohrung][1] - (nennmass + min(ABMASSE[welle])), 3)


# meine Testfälle (vorher festgelegt)
testfaelle = [("g6", "Spielpassung"), ("r6", "Übermaßpassung"),
              ("k6", "Übergangspassung"), ("h6", "Spielpassung")]
for welle, soll in testfaelle:
    ergebnis = passungsart("H7", welle)
    if ergebnis == soll:
        print("ok    ", "H7/" + welle, ergebnis)
    else:
        print("FEHLER", "H7/" + welle, ergebnis, "(erwartet:", soll + ")")
print("Höchstspiel H7/g6:", hoechstspiel("H7", "g6"), "mm")

Prompt B: der PAP als Prompt

Beispiel-Antwort, nicht aus einer echten Anfrage

Schreibe eine Python-Funktion passungsart(bohrung_min, bohrung_max, welle_min, welle_max). Alle Maße sind Kommazahlen in mm. Die Funktion gibt einen Text zurück und druckt nichts. Ablauf: 1. Wenn bohrung_min >= welle_max: "Spielpassung". 2. Sonst, wenn bohrung_max <= welle_min: "Übermaßpassung". 3. Sonst: "Übergangspassung". Grenzfall: Ist das Spiel genau 0 (bohrung_min gleich welle_max), ist es eine Spielpassung. Beispiel: passungsart(25.000, 25.021, 24.987, 25.000) -> "Spielpassung". Keine Toleranztabellen, keine Eingabe.

# Beispiel-Antwort auf Prompt B
def passungsart(bohrung_min, bohrung_max, welle_min, welle_max):
    """Liefert 'Spielpassung', 'Übermaßpassung' oder 'Übergangspassung' (Maße in mm)."""
    if bohrung_min >= welle_max:
        return "Spielpassung"
    elif bohrung_max <= welle_min:
        return "Übermaßpassung"
    else:
        return "Übergangspassung"


# meine Testfälle (vorher festgelegt)
testfaelle = [
    (25.000, 25.021, 24.980, 24.993, "Spielpassung"),       # 25 H7/g6
    (25.000, 25.021, 25.028, 25.041, "Übermaßpassung"),     # 25 H7/r6
    (25.000, 25.021, 25.002, 25.015, "Übergangspassung"),   # 25 H7/k6
    (25.000, 25.021, 24.987, 25.000, "Spielpassung"),       # 25 H7/h6: Spiel genau 0
]
for fall in testfaelle:
    ergebnis = passungsart(fall[0], fall[1], fall[2], fall[3])
    if ergebnis == fall[4]:
        print("ok    ", ergebnis)
    else:
        print("FEHLER", ergebnis, "(erwartet:", fall[4] + ")")
print("Höchstspiel H7/g6:", round(25.021 - 24.980, 3), "mm")

Selbst sehen: Was bestehen die Antworten?

Beide Programme laufen mit den vier Testfällen. Sag erst voraus, dann führe beide aus (beim ersten Mal lädt Python einmalig nach). Der Visualisierer „Schritt für Schritt“ zeigt bei Prompt A, welcher Zweig an der Grenze genommen wird.

Wie viele der vier Testfälle besteht die Antwort auf den vagen Prompt A?

Drei von vier. Die Antwort auf Prompt A besteht g6, r6 und k6 und scheitert an h6: Dort ist das Spiel genau 0, und ihr Vergleich b_min > w_max verlangt „größer“ statt „größer oder gleich“. Außerdem hat die KI sich Abmaße ausgedacht: Nach ISO 286 hat 25 g6 die Abmaße −7 und −20 Mikrometer, die Antwort nimmt −5 und −18. Das Höchstspiel stimmt deshalb nicht (0,039 statt 0,041 mm). Das sieht man nur, wenn man die Zahlen nachschlägt. Die Antwort auf Prompt B hat weder Tabelle noch Rate-Anteil: Alles Nötige stand im Prompt.

Wissens-Ampel für V11

  • Im KopfDer Auftrag gehört vor den Prompt: Eingaben, Ausgaben, Einheiten, Grenzfälle, Beispiele. Testfälle schreibst du vor dem Generieren von Hand. An der Grenze entscheidet >= oder >. import math, from math import sqrt und import math as m legen verschiedene Namen an. Was nicht im Prompt steht, ergänzt die KI nach Wahrscheinlichkeit.
  • Lesen & erkennenFunktionen der Standardbibliothek in der Dokumentation nachschlagen (math, statistics, random), pip-Befehle und eine Datei requirements.txt lesen, die Oberfläche von Copilot und Codespaces bedienen.
  • Delegierenpip install ausführen, passende Paketversionen auswählen, die Entwicklungsumgebung aufbauen (das übernimmt die vorbereitete Codespace-Umgebung), Routinecode und Standardfunktionen schreiben lassen. Du musst nur wissen, dass es das gibt, und das Ergebnis prüfen.
Warum muss ich das wissen?

Im Beruf wirst du Code von KI-Assistenten bekommen, und du bist es, der ihn freigibt. Die Haftung liegt nicht beim Assistenten. Wer nur „funktioniert“ prüft, übersieht die stillen Fehler an der Grenze, die erfundenen Werte und die erfundenen Bibliotheken. In der Klausur kommt das als „Würdest du diesen Code freigeben?“, als Code mit import und als PAP, den du in Code übersetzt.

2 Theorie

Erklärvideo (ca. 3 Min)

Der Arbeitsablauf: spezifizieren, testen, generieren, prüfen, verantworten

Mit einem Code-Assistenten wie GitHub Copilot arbeitest du nicht weniger, sondern an anderen Stellen. Das Tippen übernimmt die KI. Du übernimmst, was nur ein Mensch kann: genau sagen, was gebraucht wird, und prüfen, ob das Ergebnis stimmt. Der Ablauf hat fünf Schritte.

  1. Spezifizieren: Aufgabe als PAP und Text festhalten (Eingaben, Ausgaben, Einheiten, Grenzfälle).
  2. Testfälle von Hand: Mindestens ein Fall je Zweig und die Grenzen, bevor du die KI fragst. Sonst richtest du die Tests unbewusst nach dem Code, den du gerade siehst.
  3. Generieren: Den Prompt abschicken, den Code ansehen, nicht blind übernehmen.
  4. Prüfen: Testfälle laufen lassen, den Code Zeile für Zeile lesen (V01 bis V10), Werte und Namen nachschlagen.
  5. Verantworten: Freigeben oder zurück zu Schritt 1. Sind die Tests rot, verbesserst du Prompt und Spezifikation, statt den Code planlos umzubauen.

Der PAP als Prompt

Ein Programmablaufplan (V05) legt fest, welche Fragen in welcher Reihenfolge gestellt werden. Genau das braucht die KI, und es lässt sich in Sätze übersetzen: Jede Raute wird zu einem „Wenn …, dann …, sonst …“, jedes Ausgabesymbol zu einem festen Rückgabetext. Der Passungs-PAP hat zwei Rauten. Wähle einen Testfall und sieh, welchen Weg die Werte nehmen.

Passungs-PAP mit Testfällen

Die erste Raute fragt, ob die kleinste Bohrung mindestens so groß ist wie die größte Welle (dann gibt es immer Spiel). Nur wenn nicht, fragt die zweite Raute, ob die größte Bohrung höchstens so groß ist wie die kleinste Welle (dann gibt es immer Übermaß). Alles andere ist Übergang. Probiere den vierten Testfall: Er liegt genau auf der Grenze.

Beobachtung: Die Reihenfolge der Rauten ist Teil der Spezifikation. Und „gleich“ gehört bei beiden Rauten ausdrücklich dazu (>=, <=). Im PAP steht das als Zeichen in der Raute, im Prompt muss es als Satz stehen, sonst muss die KI raten.

Prompt-Qualität: fünf Fragen vor dem Abschicken

Die KI schreibt, was nach deinem Text am wahrscheinlichsten folgt (V10). Fehlt eine Angabe, füllt sie die Lücke mit dem, was in ihren Trainingsdaten am häufigsten vorkam. Das ist oft richtig, aber ausgerechnet an den Grenzen nicht. Mit fünf Fragen schließt du die Lücken:

  • Eingaben: Welche Werte kommen herein, mit welchen Namen und welchem Datentyp?
  • Ausgaben: Was kommt heraus (Rückgabewert oder print), in welchem Typ und Format?
  • Einheiten: In welcher Einheit rechnest du (mm, m, N, MPa, °C, 1/min)? Eine fehlende Einheit ist der klassische Faktor-1000-Fehler.
  • Grenzfälle: Was gilt genau an der Grenze, bei 0, bei leerer oder ungültiger Eingabe?
  • Beispiele: Mindestens ein Beispiel mit Eingabe und erwartetem Ergebnis.

Prompt-Bewerter

Lade den vagen Prompt und den PAP-Prompt und beobachte, welche der fünf Fragen beantwortet sind. Streiche dann im PAP-Prompt Sätze weg und schau, welches Kriterium dabei verschwindet. Das Werkzeug sucht nur Stichwörter: Es kann nicht beurteilen, ob deine Angaben stimmen.

Merke

Ein guter Prompt ist eine kleine Spezifikation: Eingaben, Ausgaben, Einheiten, Grenzfälle, Beispiele. Der PAP liefert den Ablauf dazu fast umsonst. Die Testfälle schreibst du vor dem Prompt, und sie enthalten immer die Grenze („Spiel genau 0“, „Wert genau auf der Toleranzgrenze“).

Module: Werkzeugkisten für dein Programm

Bisher hast du math nur am Rand gesehen (V03). Jetzt wird das Prinzip klar: Ein Modul ist eine Sammlung fertiger Funktionen unter einem Namen. Mit import holst du sie in dein Programm. Es gibt drei Schreibweisen, und sie legen verschiedene Namen an:

import math                 # der Name math gehört jetzt zu deinem Programm
print(math.sqrt(16))        # Funktion aus dem Modul: Modulname, Punkt, Funktionsname
from math import sqrt       # nur die eine Funktion holen
print(sqrt(16))             # ohne Modulname davor
import math as m            # Zweitname (Kurzname) für das Modul
print(m.sqrt(16))           # der Name math existiert hier nicht, nur m

Welche Namen gibt es nach welchem import?

Wähle oben eine import-Zeile. Rechts siehst du, was in der Werkzeugkiste math liegt, links die Namen, die dein Programm dadurch kennt. Probiere dann Ausdrücke aus: math.sqrt(16) nach import math as m ergibt einen NameError. Und math.tolerance(16)? So eine Funktion gibt es nicht.

Beobachtung: Ein NameError bedeutet „diesen Namen hast du nicht angelegt“, ein AttributeError bedeutet „der Name existiert, aber das Modul hat nichts mit diesem Namen“. Das zweite passiert bei KI-Code, die sich Funktionen ausdenkt.

Die Standardbibliothek: math, statistics, random

Die Standardbibliothek kommt mit jedem Python mit. Du brauchst nichts zu installieren, nur zu importieren. Drei Module genügen für den Anfang: math (Wurzel, Winkelfunktionen, pi, isclose aus V03), statistics (Mittelwert, Median, Standardabweichung) und random (Zufallszahlen, zum Beispiel für Simulationen mit Streuung).

import statistics

hoechstspiele = [0.041, -0.007, 0.019, 0.034]     # mm
print("Mittelwert:", round(statistics.mean(hoechstspiele), 4))
print("Median:", round(statistics.median(hoechstspiele), 4))
print("Standardabweichung:", round(statistics.stdev(hoechstspiele), 4))
import random

random.seed(7)               # fester Startwert: bei jedem Lauf dieselbe Folge, gut zum Testen
werte = []
for i in range(5):
    werte.append(round(25.0 + random.uniform(-0.01, 0.01), 4))   # 25 mm mit Streuung +-0,01 mm
print(werte)
print("Ein Wurf mit dem Würfel:", random.randint(1, 6))

statistics.stdev ist die Stichproben-Standardabweichung (geteilt durch n − 1) und braucht mindestens zwei Werte. Eine Funktion, die du nicht kennst, schlägst du in der Dokumentation nach (Python-Dokumentation, Bereich „Library Reference“), statt der KI zu glauben, dass es sie gibt.

Ein eigenes Modul

Jede Python-Datei ist ein Modul. Wenn du Funktionen wiederverwenden willst (V07), legst du sie in eine Datei, zum Beispiel passungen.py, und importierst sie ohne die Endung .py. Die Datei muss im selben Ordner wie dein Programm liegen. Im Labor hier ist passungen.py schon mitgeliefert. Probiere es aus:

import passungen

art = passungen.passungsart(25.000, 25.021, 24.980, 24.993)
print(art)
print("Höchstspiel:", passungen.hoechstspiel(25.021, 24.980), "mm")
print("Mindestspiel:", passungen.mindestspiel(25.000, 24.993), "mm")
Achtung

Nenne eigene Dateien nie wie ein Modul, das du benutzen willst: Eine Datei math.py oder random.py in deinem Ordner verdeckt das echte Modul, und import math holt deine Datei. Das führt zu rätselhaften Fehlern. Und from math import * holt alle Namen auf einmal: Es sieht bequem aus, macht aber unlesbar, woher eine Funktion kommt. Das schreibt man nicht.

pip: Pakete von außerhalb

Was nicht in der Standardbibliothek steckt (zum Beispiel numpy für schnelle Zahlenfelder in V13, pandas in V15, matplotlib in V14), ist ein Paket und muss einmal auf deinen Rechner geholt werden. Das macht das Programm pip. Es fragt den Paketindex PyPI im Internet, welche Version zu deinem Python passt, und legt die Dateien ab. pip tippst du ins Terminal, nicht ins Python-Programm.

Von der Fehlermeldung zum installierten Paket

Gehe die Schritte durch. Achte darauf, wer was tut: Python sucht nur an zwei Orten und gibt dann auf. Das Installieren löst erst du aus, und zwar außerhalb des Programms.

pip install numpy              # neueste passende Version holen
pip install numpy==2.0.0       # genau diese Version (Versionsnummer festnageln)
pip list                       # alle installierten Pakete mit Version
pip freeze > requirements.txt  # Liste der Versionen in eine Datei schreiben
pip install -r requirements.txt  # alles aus dieser Liste auf einem anderen Rechner installieren

Das sind Befehle für das Terminal und kein Python-Code, deshalb gibt es hier keinen „Ausführen“-Knopf. Im Browser-Labor kannst du kein pip aufrufen: Dort sind die nötigen Pakete (NumPy, pandas, matplotlib) schon vorbereitet, und sie werden beim ersten import automatisch geladen. In Codespaces hat die vorbereitete Umgebung numpy, matplotlib und jupyter schon installiert.

Achtung

Installiere nie ein Paket, nur weil KI-Code es importiert. Assistenten erfinden manchmal Paketnamen, die plausibel klingen. Wer einen erfundenen Namen blind installiert, holt sich im schlimmsten Fall ein Schadpaket von jemandem, der genau diesen Namen vorsorglich veröffentlicht hat. Prüfe vorher: Gibt es das Paket auf PyPI, wie alt ist es, wie bekannt, wer pflegt es? Im Zweifel nimmst du ein bekanntes Paket oder gar keines.

Was Copilot ist und was nicht

Copilot kennt zwei Arbeitsweisen. Die Inline-Vorschläge erscheinen beim Tippen als graue Schrift hinter dem Cursor: Mit Tab nimmst du den Vorschlag an, mit Esc lehnst du ihn ab. Der Chat ist ein Seitenfenster, in dem du eine Aufgabe beschreibst, Code erklären oder Fehlermeldungen deuten lässt. In beiden Fällen sieht Copilot die geöffnete Datei und einen Teil des Projekts: Was dort steht, fließt in die Vorschläge ein.

Und es gilt, was du in V10 gelernt hast: Copilot schreibt wahrscheinliche Fortsetzungen, keine geprüften Lösungen. Es kann falsche Werte, falsche Grenzen und erfundene Funktionen liefern, im selben ruhigen Ton wie richtige. Du gibst frei, nicht Copilot.

Achtung: Datenschutz

Alles, was du in Prompt oder Chat schreibst und was im geöffneten Code steht, geht an Server des Anbieters. Schreib deshalb nie Firmen- oder Kundendaten, Zeichnungsdaten, Zugangsdaten, Schlüssel oder personenbezogene Daten in einen Prompt. In vielen Betrieben ist KI-Hilfe im Entwicklungsnetz ganz untersagt oder nur über freigegebene Werkzeuge erlaubt (Fertigungssteuerung, CAD-Daten, Kundenprojekte). Frag vorher nach. Für den Kurs nutzt du nur Übungsdaten.

3 Copilot einrichten: Schritt für Schritt

Diese Anleitung bringt dich von null zu deinem ersten Copilot-Vorschlag. Plane für die Einrichtung etwa 30 Minuten plus die Wartezeit für den Studierendenstatus ein. Die Abbildungen sind schematische Skizzen mit vereinfachter Oberfläche, keine Screenshots: Namen, Menüs und Aussehen ändern sich bei GitHub und in der Entwicklungsumgebung von Zeit zu Zeit. Suche im Zweifel nach den fettgedruckten Begriffen.

Vorab

Du brauchst: deine DHBW-Mailadresse, einen Nachweis, dass du Studierende oder Studierender bist (zum Beispiel die Studienbescheinigung als Foto oder PDF), und einen Browser. Copilot ist freiwillig. Wer keinen Zugang möchte oder bekommt, löst alle Aufgaben ohne KI (das ist die Phase-1-Arbeitsweise) und sieht die Copilot-Schritte in der Vorlesung live.

  1. GitHub-Konto mit DHBW-Mailadresse anlegen

    Wenn du schon ein GitHub-Konto hast, füge deine DHBW-Mailadresse unter Einstellungen, E-Mail hinzu und bestätige sie. Sonst lege ein neues Konto an: mit deiner DHBW-Mailadresse, einem Benutzernamen und einem Passwort, das du nirgends sonst benutzt. Öffne danach den Bestätigungslink in der E-Mail.

    • Schalte die Zwei-Faktor-Anmeldung ein: GitHub verlangt sie für viele Funktionen, und sie schützt dein Konto.
    • Der Benutzername ist öffentlich sichtbar. Wähle nichts, was du später nicht mehr zeigen möchtest.

  2. Studierendenstatus bei GitHub Education beantragen

    Über das Bildungsangebot GitHub Education (Seite education.github.com) beantragst du den Studierendenzugang („Student Developer Pack“). Damit bekommst du Copilot für Studierende ohne eigene Rechnung. Gib deine Hochschule an (Duale Hochschule Baden-Württemberg) und lade den Nachweis hoch.

    • Nachweis: Studienbescheinigung als lesbares Foto oder PDF, mit Namen der Hochschule und gültigem Zeitraum. Die DHBW-Mailadresse allein genügt nicht immer.
    • Wartezeit: Die Prüfung kann Stunden dauern, aber auch mehrere Wochen. Du bekommst eine E-Mail, wenn die Entscheidung gefallen ist. Beantrage deshalb früh.
    • Standort: Erlaube dem Browser die Standortfreigabe nur, wenn der Antrag es verlangt, und nur dafür. Bei Ablehnung kannst du mit besserem Nachweis neu beantragen.
    • Der Status gilt für eine begrenzte Zeit und muss später erneuert werden (zum Beispiel jährlich).

  3. Copilot aktivieren

    Ist der Status genehmigt, öffne Einstellungen, Copilot. Dort steht, dass dein Zugang aktiv ist (über den Studierendenstatus). Prüfe zwei Schalter: die Vorschläge in der Entwicklungsumgebung (an) und, ob Vorschläge blockiert werden sollen, die öffentlichem Code gleichen (empfohlen: blockieren). Falls angeboten, entscheide hier auch, ob deine Eingaben zur Verbesserung des Dienstes verwendet werden dürfen.

    • Steht dort noch nur ein Angebot zum Bezahlen, ist der Status noch nicht freigegeben. Buche nichts, sondern warte auf die E-Mail oder prüfe den Status auf der Bildungsseite.
    • Zusätzlich gibt es eine kostenlose Basisstufe mit stark begrenztem Kontingent. Sie reicht zum Ausprobieren, aber nicht für ein ganzes Semester.

  4. Repository der Vorlesung öffnen

    Ein Repository ist der Projektordner der Vorlesung auf GitHub. Den Link nennt dein Dozent im Kurs. Du siehst eine Dateiliste, darunter notebooks und den Ordner .devcontainer: Er enthält die fertige Beschreibung der Umgebung (Python, Jupyter und die Copilot-Erweiterung).

    • Am besten kopierst du das Repository zuerst mit Fork (Knopf oben rechts) in dein eigenes Konto. Dann gehören die Dateien, die du anlegst, dir, und du kannst sie sichern.
    • Du veränderst damit nichts am Original der Vorlesung.

  5. Codespace starten

    Ein Codespace ist ein kleiner Entwicklungsrechner in der Cloud, den du im Browser bedienst. Klicke auf den grünen Knopf Code, wähle den Reiter Codespaces und dann Codespace auf main erstellen. Warte etwa eine Minute: Die Umgebung wird nach der Vorgabe im Ordner .devcontainer gebaut, mit Python, Jupyter und den Copilot-Erweiterungen.

    • Du arbeitest danach in einem Editor, der wie Visual Studio Code aussieht (links Dateien, in der Mitte Code, unten ein Terminal).
    • Beim zweiten Mal öffnest du denselben Codespace wieder, statt einen neuen anzulegen.

  6. Copilot-Chat und Inline-Vorschläge benutzen

    Im Codespace findest du Copilot an zwei Stellen. Rechts (oder über das Chat-Symbol in der Kopfleiste) öffnet sich der Copilot-Chat: Dort beschreibst du die Aufgabe, am besten mit dem PAP-Prompt aus diesem Kapitel. Im Editor erscheinen beim Tippen graue Inline-Vorschläge.

    • Tab nimmt den grauen Vorschlag an, Esc lehnt ihn ab. Mit Alt + ] und Alt + [ blätterst du durch Alternativen (Standardbelegung, kann abweichen).
    • Im Chat zeigt Copilot Code mit einem Knopf zum Einfügen. Lies den Code, bevor du ihn einfügst.
    • Erscheint nichts: Prüfe das Copilot-Symbol unten rechts (angemeldet? aktiv?) und ob die Erweiterung geladen ist.

  7. Eigene Datei anlegen und ausführen

Namen nach dem import

Welche der vier Zeilen am Ende liefert 7.0, ohne Fehler?

import math as m legt nur den Namen m an. math und sqrt kennt das Programm nicht (NameError), und wurzel wurde nie angelegt. Probiere die falschen Zeilen aus und lies die Meldung von unten nach oben.
import math as m
print(m.sqrt(49))
# Probiere nacheinander: print(math.sqrt(49)), print(sqrt(49)), print(wurzel(49))

Mittelwert und Median mit statistics

Der Mittelwert von 2, 4 und 9 ist 5. Und der Median?

4. Der Median ist der mittlere Wert der sortierten Reihe (2, 4, 9). Er ist weniger empfindlich gegen Ausreißer als der Mittelwert: Ersetze die 9 durch 90, dann springt der Mittelwert auf 32, der Median bleibt 4.
import statistics

werte = [2, 4, 9]
print(statistics.mean(werte))
print(statistics.median(werte))
print(round(statistics.stdev(werte), 3))

Probiere danach eine Liste mit nur einem Element in statistics.stdev (Fehlermeldung lesen) und die Liste [2, 4, 90].

Die Grenze: größer oder größer-gleich?

Was gibt das Programm aus, wenn die kleinste Bohrung gleich der größten Welle ist?

Übergangspassung. Mit > ist „25.000 größer als 25.000“ falsch, der erste Zweig wird übersprungen, und der zweite prüft das Übermaß, das auch nicht stimmt. Das Programm läuft ohne Meldung und gibt für diesen Grenzfall das Falsche aus. Ersetze > durch >=: Dann kommt Spielpassung. Diesen Fehler findet nur ein Testfall auf der Grenze.
def passungsart(bohrung_min, bohrung_max, welle_min, welle_max):
    if bohrung_min > welle_max:
        return "Spielpassung"
    elif bohrung_max <= welle_min:
        return "Übermaßpassung"
    else:
        return "Übergangspassung"


print(passungsart(25.000, 25.021, 24.987, 25.000))

Eigenes Modul benutzen

Das Mindestspiel ist „kleinste Bohrung minus größte Welle“. Welches Vorzeichen hat es bei einer Übermaßpassung?

Negativ. Die kleinste Bohrung ist dann kleiner als die größte Welle: Die Welle ist größer als die Bohrung und muss eingepresst werden. Ein „negatives Spiel“ nennt man Übermaß.
import passungen
from passungen import mindestspiel as spiel_min

g = passungen.GRENZMASSE_25
print(passungen.passungsart(g["H7"][0], g["H7"][1], g["r6"][0], g["r6"][1]))
print("Mindestspiel:", spiel_min(g["H7"][0], g["r6"][1]), "mm")

Erfundene Funktion erkennen

Die KI schreibt math.tolerance(...). Was passiert beim Ausführen?

Es gibt keine Funktion math.tolerance. Das Programm bricht ab, und die Meldung nennt den erfundenen Namen. Das ist noch der günstige Fall: Der Fehler ist laut. Gefährlicher sind erfundene Zahlenwerte und falsche Grenzen, die ohne Meldung durchlaufen.
import math

wert = math.tolerance(25.0, 0.02)
print(wert)

5 Selbstcheck

Acht Quizaufgaben im Stil der Probeklausur (22 Punkte) und eine Code-Schreib-Aufgabe (6 Punkte, T9). Plane etwa 15 Minuten für das Quiz und 10 Minuten für T9 ein, ohne Hilfsmittel. Quiz-Punkte gibt es für den ersten Versuch; danach darfst du es nochmal probieren.

T1 · import mit Zweitnamen2 Punkte
Was gibt das Programm aus?
import math as m
print(m.sqrt(49))
m.sqrt(49) ist die Quadratwurzel von 49. sqrt liefert immer eine Kommazahl (V03), also 7.0 und nicht 7.
T2 · NameError2 Punkte
Was passiert beim Ausführen?
from math import sqrt
print(math.sqrt(4))
  • Es wird 2.0 ausgegeben.
  • Python bricht mit NameError: name 'math' is not defined ab.
  • Python bricht mit einem ImportError ab.
  • Es wird 4 ausgegeben.
from math import sqrt holt nur den Namen sqrt. Der Name math wurde nie angelegt, also kennt das Programm ihn nicht. Richtig wäre print(sqrt(4)) oder import math.
T3 · statistics2 Punkte
Welche Zahl gibt das Programm aus?
import statistics
print(statistics.median([9, 2, 5, 7, 1]))
Sortiert ist die Reihe 1, 2, 5, 7, 9. Der Median ist der mittlere Wert: 5. Wichtig: Der Median sortiert selbst, die Eingabe muss nicht sortiert sein.
T4 · pip3 Punkte
Was tut der Befehl pip install numpy im Terminal?
  • Er startet das Programm numpy.py.
  • Er lädt das Paket numpy aus dem Paketindex PyPI und legt es auf dem Rechner ab, damit import numpy danach funktioniert.
  • Er schreibt import numpy automatisch an den Anfang aller Programme.
  • Er prüft, ob numpy in der Standardbibliothek enthalten ist.
pip installiert Pakete, die nicht zur Standardbibliothek gehören. Es läuft im Terminal, nicht im Programm, und ändert keinen Programmcode. Das import schreibst du selbst.
T5 · Aussagen (mehrere richtig)4 Punkte
Welche Aussagen sind richtig? Alle richtigen ankreuzen.
  • Testfälle schreibt man vor dem Generieren von Hand auf, damit sie nicht vom erzeugten Code beeinflusst werden.
  • Läuft der von Copilot erzeugte Code ohne Fehlermeldung, ist er richtig.
  • Ein Prompt mit Eingaben, Ausgaben, Einheiten, Grenzfällen und einem Beispiel lässt der KI weniger Raum zum Raten.
  • Konstruktionsdaten dürfen in den Prompt, wenn das Ergebnis dadurch besser wird.
Ein Programm ohne Fehlermeldung kann trotzdem falsch rechnen (Grenzfall, erfundener Wert). Und vertrauliche Daten haben in einem Prompt nichts verloren, auch nicht für ein besseres Ergebnis.
T6 · Grenzfall3 Punkte
Was gibt das Programm aus?
def spiel(bohrung_min, welle_max):
    if bohrung_min > welle_max:
        return "Spiel"
    return "kein Spiel"

print(spiel(25.000, 25.000))
25.000 ist nicht größer als 25.000, die Bedingung ist falsch, also läuft die letzte Zeile: „kein Spiel“. Bei einem Spiel von genau 0 ist das fachlich falsch (Spielpassung, wenn >= gilt). Genau solche Fälle fängt ein Testfall auf der Grenze ab.
T7 · ModuleNotFoundError3 Punkte
KI-Code beginnt mit import passungsrechner, und Python meldet ModuleNotFoundError: No module named 'passungsrechner'. Was tust du zuerst?
  • Sofort pip install passungsrechner, damit es läuft.
  • Prüfen, ob es das Paket wirklich gibt (PyPI, Alter, Pflege). Ist der Name erfunden, den Code ändern, statt etwas zu installieren.
  • Die Zeile import löschen und hoffen, dass der Rest läuft.
  • Eine Datei passungsrechner.py mit beliebigem Inhalt anlegen.
KI-Assistenten erfinden Paketnamen, und wer sie blind installiert, riskiert ein Schadpaket. Erst prüfen, dann entscheiden. Die anderen Wege lassen den Fehler verschwinden, ohne ihn zu lösen.
T8 · KI-Code freigeben?3 Punkte
Die KI soll prüfen, ob ein Messwert in der Toleranz liegt, und liefert:
import math

def in_toleranz(wert, nenn, tol):
    return math.tolerance(wert, nenn) <= tol
Würdest du das freigeben?
  • Ja, die Funktion hat einen sprechenden Namen und einen Rückgabewert.
  • Nein, math.tolerance gibt es nicht: Beim Aufruf bricht das Programm mit einem AttributeError ab. Richtig wäre zum Beispiel abs(wert - nenn) <= tol.
  • Nein, import math darf nicht in einer Datei mit einer Funktion stehen.
  • Nein, das Ergebnis ist ein Text, kein Wahrheitswert.
Der Code sieht ordentlich aus, aber die Funktion ist erfunden. Fremde Funktionen prüfst du in der Dokumentation. Die Toleranzprüfung ist in Wahrheit eine Betragsrechnung (V03).

T9 · Passung bestimmen6 Punkte

Schreibe ein Programm, das vier Maße in mm einliest (Kommazahlen, jeweils mit eigenem input()): die kleinste und die größte Bohrung, die kleinste und die größte Welle, in dieser Reihenfolge. Es bestimmt die Passungsart nach diesem Ablauf: Ist die kleinste Bohrung größer oder gleich der größten Welle, ist es eine Spielpassung. Sonst: Ist die größte Bohrung kleiner oder gleich der kleinsten Welle, ist es eine Übermaßpassung. Sonst ist es eine Übergangspassung. Danach gibt es das Höchstspiel (größte Bohrung minus kleinste Welle) mit drei Nachkommastellen aus.

Ausgabe genau so (Beispiel 25.000, 25.021, 24.980, 24.993):
Passungsart: Spielpassung
Höchstspiel: 0.041 mm

Virtuelle Umgebungen und requirements.txt

Jedes Projekt braucht oft andere Paketversionen. Damit sie sich nicht stören, legt man pro Projekt eine virtuelle Umgebung an: einen eigenen Ordner mit eigener Python-Installation und eigenen Paketen. Im Terminal:

python -m venv .venv              # Umgebung anlegen
source .venv/bin/activate         # aktivieren (Windows: .venv\Scripts\activate)
pip install numpy==2.0.0          # nur in dieser Umgebung
pip freeze > requirements.txt     # Stand festhalten

Die Datei requirements.txt ist die Einkaufsliste des Projekts: Wer sie bekommt, installiert mit pip install -r requirements.txt dieselben Versionen. Die Codespace-Umgebung der Vorlesung macht Ähnliches in der Datei .devcontainer/devcontainer.json: Dort steht, welche Python-Version und welche Erweiterungen beim Start eingerichtet werden. Wenn die KI dir ein neues Paket vorschlägt, gehört es mit Version in diese Liste, nicht „irgendwie“ auf den Rechner.

Erfundene Pakete als Einfallstor: die Lieferkette

Code-Assistenten erfinden gelegentlich Paketnamen, die so plausibel klingen, dass sie existieren könnten. Angreifer haben das erkannt: Sie veröffentlichen unter solchen häufig erfundenen Namen echte Pakete mit Schadcode und warten, dass jemand den Vorschlag der KI blind installiert. Diese Art Angriff nennt man Lieferkettenangriff (englisch supply chain attack). Dein Schutz sind einfache Gewohnheiten: Nur Pakete installieren, die du kennst oder geprüft hast; in der Projektliste Versionen festnageln; Pakete mit sehr jungem Alter und fast ohne Downloads misstrauisch betrachten. In V18 (IT-Sicherheit) und dem Cyber Resilience Act kommt das Thema wieder.

Copilot-Chat, Bearbeiten und Agenten: wie viel darf die KI selbst ändern?

Der Chat kennt mehrere Betriebsarten, die sich in der Oberfläche von Version zu Version etwas ändern: Fragen (die KI antwortet nur), Bearbeiten (die KI schlägt Änderungen an Dateien vor, die du annimmst oder ablehnst) und Agent (die KI plant mehrere Schritte, ändert Dateien und führt Befehle im Terminal aus). Je selbstständiger die Betriebsart, desto wichtiger werden deine Testfälle: Sie sind die einzige Stelle, an der du sicher siehst, ob nach vielen automatischen Änderungen noch dasselbe herauskommt. Du liest jede vorgeschlagene Änderung (der Vergleich „Diff“ zeigt alte und neue Zeilen) und gibst Befehle im Terminal nur frei, wenn du verstehst, was sie tun.

Rechte und Pflichten bei KI-Code, kurz

Keine Rechtsberatung, nur Denkanstöße: Wer KI-Code in einem Produkt einsetzt, bleibt für das Produkt verantwortlich. Die Frage, wem erzeugter Code gehört und ob er fremde Lizenzen berührt, ist nicht abschließend geklärt. Deshalb gibt es die Einstellung, Vorschläge zu blockieren, die öffentlichem Code gleichen. Betriebe regeln das meist mit Richtlinien: welche Werkzeuge erlaubt sind, welche Daten hinein dürfen, ob KI-Code gekennzeichnet werden muss. Frag danach, bevor du im Betrieb zum ersten Mal Copilot öffnest.
