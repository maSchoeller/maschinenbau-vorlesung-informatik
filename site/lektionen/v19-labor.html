Werkzeugkasten

Heute neu in Python: das Modul sqlite3, mit dem dein Programm eine Datenbank abfragt, und die Sprache SQL, die du als Text an die Datenbank schickst. SQLite ist ein Datenbankmanagementsystem, das in Python schon eingebaut ist und die ganze Datenbank in einer einzigen Datei hält. In V17 kamen die Maschinendaten als JSON von der API, heute liegen die Aufträge der Fertigungszelle FZ-3 in einer Datenbank: wer fertigt was, wie viel, mit welchem Status.

Merke

Diese acht Karten sind dein Spickzettel, bis es sitzt. Du erreichst sie in jeder Aufgabe über den Knopf „Werkzeugkasten“ oben. Führe jede Karte aus und ändere etwas daran. Die Datenbank fz3.db liegt vor jedem Lauf frisch bereit: Was du darin änderst oder löschst, ist beim nächsten Lauf wieder da. Alle Befehle des Kurses stehen außerdem in der Befehls-Bibliothek rechts (Eintrag sqlite3).

Syntax-Karte 1

Verbindung, Cursor, execute, fetchall, close

import sqlite3

db = sqlite3.connect("fz3.db")          # Verbindung zur Datenbankdatei öffnen
cur = db.cursor()                       # Cursor: damit schickst du Befehle

cur.execute("SELECT nr, teil, menge FROM auftraege WHERE nr = 4711")
print(cur.fetchall())                   # Liste von Tupeln

cur.execute("SELECT name FROM sqlite_master WHERE type = 'table'")
print(cur.fetchall())                   # welche Tabellen gibt es?

db.close()                              # Verbindung schließen
  • Der Ablauf hat fünf Schritte: connect (Datei öffnen), cursor (Zeiger holen), execute (Befehl schicken), fetchall (Antwort abholen), close (Verbindung schließen). Der Cursor ist das Objekt, an dem execute und fetchall hängen, so wie read an einer geöffneten Datei (V09).
  • connect("fz3.db") öffnet die Datei; gibt es sie nicht, legt SQLite sie neu an. Mit ":memory:" entsteht eine Datenbank nur im Arbeitsspeicher: ideal zum Üben, weg beim Programmende.
  • execute schickt einen SQL-Text. Die Antwort kommt nicht als Rückgabewert, sondern wird mit fetchall() abgeholt: eine Liste von Tupeln, ein Tupel je Zeile. Auch bei nur einer Zeile bleibt es eine Liste mit einem Tupel.
  • SQL-Schlüsselwörter schreibt man üblicherweise groß (SELECT, FROM), Tabellen und Spalten klein. Python stört das nicht, es hilft beim Lesen.
Syntax-Karte 2

Tabelle anlegen: CREATE TABLE

import sqlite3

db = sqlite3.connect(":memory:")        # Übungs-Datenbank im Arbeitsspeicher
cur = db.cursor()

cur.execute("""CREATE TABLE maschinen (
    id TEXT PRIMARY KEY,
    typ TEXT,
    ip TEXT
)""")
cur.execute("INSERT INTO maschinen VALUES ('D2', 'Drehmaschine', '192.168.30.11')")

cur.execute("SELECT * FROM maschinen")  # * heißt: alle Spalten
print(cur.fetchall())
  • Eine Tabelle hat Spalten mit Namen und Datentyp (INTEGER, REAL, TEXT). Jede Spalte ist eine Angabe, jede Zeile ein Datensatz.
  • PRIMARY KEY macht die Spalte zum Primärschlüssel: Hier gibt es jede Maschinen-ID nur einmal. Ein zweiter Eintrag 'D2' wird abgelehnt (siehe „Typische Fehlermeldungen“).
  • Der Befehl steht in dreifachen Anführungszeichen, damit er über mehrere Zeilen gehen darf. CREATE TABLE musst du lesen können; angelegt hat die Tabellen meist jemand anders. Die Datei fz3.db hat zwei Tabellen: maschinen und auftraege.
Syntax-Karte 3

Zeilen einfügen: INSERT, executemany und das Fragezeichen

import sqlite3

db = sqlite3.connect(":memory:")
cur = db.cursor()
cur.execute("CREATE TABLE auftraege (nr INTEGER PRIMARY KEY, teil TEXT, maschine TEXT, menge INTEGER, status TEXT)")

# eine Zeile: fünf Fragezeichen, fünf Werte im Tupel
cur.execute("INSERT INTO auftraege VALUES (?, ?, ?, ?, ?)", (4801, "WELLE_20H6", "D2", 100, "offen"))

# mehrere Zeilen: executemany mit einer Liste von Tupeln
neue = [(4802, "FLANSCH_80", "F1", 40, "offen"), (4803, "BUCHSE_30", "D2", 250, "offen")]
cur.executemany("INSERT INTO auftraege VALUES (?, ?, ?, ?, ?)", neue)
db.commit()                             # Änderung festschreiben

cur.execute("SELECT COUNT(*) FROM auftraege")
print(cur.fetchone())                   # ein Tupel mit einem Element
  • INSERT INTO tabelle VALUES (...) fügt eine Zeile hinzu. Für jede Spalte steht ein Fragezeichen im Text, die Werte folgen als Tupel in derselben Reihenfolge wie die Spalten.
  • executemany schickt denselben Befehl mit jedem Tupel der Liste: eine Zeile je Tupel, eine einzige Zeile Code. Das kennst du als Muster aus V08: Liste von Tupeln.
  • Das Fragezeichen ist ein Platzhalter. Er ist der Kern dieser Lektion: Du klebst Werte nie in den SQL-Text, du schickst sie mit.
  • fetchone() liefert genau ein Tupel. Hier (3,): ein Tupel mit einem Element, darum das Komma.
Syntax-Karte 4

Abfragen: SELECT, WHERE und Platzhalter mit Tupel-Komma

import sqlite3

db = sqlite3.connect("fz3.db")
cur = db.cursor()

maschine = "F1"
cur.execute("SELECT nr, teil, menge FROM auftraege WHERE maschine = ? AND status = ?",
            (maschine, "offen"))
for nr, teil, menge in cur.fetchall():  # Tupel entpacken wie in V08
    print(nr, teil, menge)

# Ein einzelner Wert: erst das Komma macht ("D2",) zu einem Tupel
cur.execute("SELECT COUNT(*) FROM auftraege WHERE maschine = ?", ("D2",))
print(cur.fetchone())
db.close()
  • SELECT spalten FROM tabelle WHERE bedingung ist eine Abfrage. Zuerst kommt, welche Spalten du willst, dann aus welcher Tabelle, dann welche Zeilen. SQL ist deklarativ: Du sagst, was du willst, nicht, wie die Datenbank es findet.
  • In SQL schreibt man = (ein Gleichheitszeichen), != für „ungleich“, dazu <, >, AND und OR. Text als Wert kommt über den Platzhalter, ohne Anführungszeichen im SQL.
  • Die Werte stehen immer im Tupel. Bei einem Wert musst du das Komma schreiben: (maschine,). Ohne Komma ist ("D2") nur der Text „D2“, und Python meldet „Incorrect number of bindings“ (siehe Fehlermeldungen).
  • Merke dir den Satz aus der Lerneinheit: Daten nie in den SQL-Text kleben. Immer ? und ein Tupel. Den Grund, die SQL-Injection, siehst du im vorgerechneten Beispiel.
Syntax-Karte 5

Sortieren und begrenzen: ORDER BY und LIMIT

import sqlite3

db = sqlite3.connect("fz3.db")
cur = db.cursor()

# die drei größten Aufträge
cur.execute("SELECT nr, teil, menge FROM auftraege ORDER BY menge DESC LIMIT 3")
print(cur.fetchall())

# alle Aufträge von F1, kleinste Menge zuerst (ASC ist der Standard)
cur.execute("SELECT nr, menge FROM auftraege WHERE maschine = ? ORDER BY menge", ("F1",))
print(cur.fetchall())
db.close()
  • ORDER BY spalte sortiert aufsteigend, DESC dahinter absteigend. LIMIT 3 liefert höchstens drei Zeilen.
  • Ohne ORDER BY ist die Reihenfolge nicht garantiert. Meist kommen die Zeilen so, wie sie gespeichert sind, aber darauf verlässt du dich nicht. Wenn die Reihenfolge wichtig ist, schreibst du ORDER BY.
  • Die Reihenfolge der Teile ist fest: SELECT … FROM … WHERE … ORDER BY … LIMIT ….
Syntax-Karte 6

Zusammenfassen: GROUP BY mit SUM und COUNT

import sqlite3

db = sqlite3.connect("fz3.db")
cur = db.cursor()

cur.execute("SELECT maschine, SUM(menge), COUNT(*) FROM auftraege GROUP BY maschine ORDER BY maschine")
for maschine, summe, anzahl in cur.fetchall():
    print(f"{maschine}: {anzahl} Aufträge, {summe} Stück")

cur.execute("SELECT status, COUNT(*) FROM auftraege GROUP BY status ORDER BY status")
print(cur.fetchall())
db.close()
  • GROUP BY maschine bildet je Maschine eine Gruppe; die Aggregatfunktion SUM(menge) rechnet dann je Gruppe eine Summe, COUNT(*) zählt die Zeilen der Gruppe. Das Ergebnis hat eine Zeile je Gruppe.
  • Das ist die Schleife mit Zähler aus V06, nur dass die Datenbank sie für dich macht. Dazu SUM, COUNT, MIN, MAX, AVG.
  • Auch ohne GROUP BY geht COUNT(*): SELECT COUNT(*) FROM auftraege WHERE status = ? zählt die passenden Zeilen. Das Ergebnis ist ein Tupel mit einer Zahl: fetchone()[0] holt sie heraus.
  • Ein WHERE filtert die Zeilen vor dem Gruppieren; die Reihenfolge der Gruppen legst du mit ORDER BY fest.
Syntax-Karte 7

Ändern und löschen: UPDATE und DELETE immer mit WHERE, dann commit

import sqlite3

db = sqlite3.connect("fz3.db")
cur = db.cursor()

cur.execute("UPDATE auftraege SET status = ? WHERE nr = ?", ("fertig", 4713))
print(cur.rowcount, "Zeile geändert")       # rowcount: betroffene Zeilen

cur.execute("DELETE FROM auftraege WHERE status = ?", ("fertig",))
print(cur.rowcount, "Zeilen gelöscht")
db.commit()                                 # erst jetzt ist beides festgeschrieben

cur.execute("SELECT COUNT(*) FROM auftraege")
print(cur.fetchone())
db.close()
Achtung

Ohne WHERE trifft UPDATE und DELETE alle Zeilen. DELETE FROM auftraege leert die ganze Tabelle, ohne Rückfrage. Schreib zuerst das WHERE, dann den Rest. Hier im Labor ist alles halb so schlimm, weil fz3.db bei jedem Lauf frisch da liegt. In der Fabrik gibt es kein „frisch“.

  • UPDATE tabelle SET spalte = ? WHERE ... ändert Zeilen, DELETE FROM tabelle WHERE ... löscht Zeilen. Beide gehören zu den vier Grundbefehlen: INSERT, SELECT, UPDATE, DELETE.
  • commit() schreibt die Änderungen fest. Ohne commit sind sie bei einer Datei-Datenbank nach close() weg: Sie liegen in einer Transaktion, die nie abgeschlossen wurde. Fürs bloße Lesen brauchst du kein commit.
  • cur.rowcount sagt dir nach UPDATE und DELETE, wie viele Zeilen betroffen waren. Bei 0 hat dein WHERE nichts getroffen (zum Beispiel falsche Nummer).
Syntax-Karte 8

Eine Zeile holen: fetchone und der Fall None

import sqlite3

db = sqlite3.connect("fz3.db")
cur = db.cursor()

for nr in (4711, 9999):
    cur.execute("SELECT teil, menge FROM auftraege WHERE nr = ?", (nr,))
    zeile = cur.fetchone()                  # ein Tupel oder None
    print(nr, zeile)
    if zeile is None:
        print("Auftrag nicht gefunden")
    else:
        teil, menge = zeile                 # Tupel entpacken
        print(f"{menge} x {teil}")
db.close()
  • fetchone() liefert ein Tupel (die erste Zeile) oder None, wenn die Abfrage nichts gefunden hat. fetchall() liefert dagegen immer eine Liste, notfalls eine leere.
  • Wer fetchone()[0] schreibt, ohne auf None zu prüfen, bekommt bei einer unbekannten Nummer einen TypeError (None kann man nicht mit [0] ansprechen). Prüfe mit if zeile is None:.
  • Bei einer Abfrage mit COUNT(*) gibt es immer genau eine Zeile, also nie None.

Vorgerechnetes Beispiel: Aufträge der Zelle FZ-3 abfragen

Aufgabe: Die Fertigungszelle FZ-3 bekommt eine Auftragsdatenbank. Das Programm legt eine Tabelle an, trägt fünf Aufträge ein, fragt die offenen Aufträge der Drehmaschine D2 ab, summiert die Stückzahl je Maschine und zeigt, was bei einer böswilligen Eingabe passiert, wenn man sie in den SQL-Text klebt, und wie der Platzhalter dagegen hilft. Lies den Code Zeile für Zeile, dann führe ihn aus. In V17 hast du die Maschinen per HTTP abgefragt, hier fragst du die Aufträge ab.

Beim Ausführen siehst du zwei Aufträge der Drehmaschine, dann die Summen je Maschine als Liste von Tupeln. Danach zeigt das Programm, dass die unsichere Abfrage alle fünf Aufträge liefert, die sichere keinen.

  1. Zeile 4: import sqlite3. Das Modul steckt in Python, du installierst nichts.
  2. Zeilen 6 und 7: connect(":memory:") legt eine Datenbank im Arbeitsspeicher an, nur für dieses Programm (zum Üben). cursor() holt den Zeiger, an dem alle weiteren Befehle hängen.
  3. Zeilen 8 bis 14: CREATE TABLE legt die Tabelle auftraege mit fünf Spalten an. nr ist der Primärschlüssel: Jede Auftragsnummer gibt es nur einmal. Die drei Anführungszeichen erlauben mehrere Zeilen im Text.
  4. Zeilen 16 bis 24: Eine Liste von Tupeln, ein Tupel je Auftrag. executemany führt den INSERT für jedes Tupel aus; die fünf Fragezeichen entsprechen den fünf Spalten. commit() schreibt fest.
  5. Zeilen 26 bis 31: Die Abfrage hat zwei Platzhalter. Das Tupel (maschine, "fertig") liefert die Werte in der Reihenfolge der Fragezeichen: Maschine D2 und Status ungleich „fertig“. fetchall() gibt eine Liste von Tupeln zurück, die Schleife entpackt jedes Tupel in nr, teil, menge (V08). Es erscheinen 4711 (in Arbeit) und 4713 (offen); 4714 fehlt, der ist fertig.
  6. Zeilen 33 bis 35: GROUP BY maschine bildet eine Gruppe je Maschine, SUM(menge) addiert je Gruppe. D2: 500 + 300 + 800 = 1600, F1: 120 + 60 = 180. Das Ergebnis ist [('D2', 1600), ('F1', 180)]: eine Liste von Tupeln.
  7. Zeilen 37 bis 41: Die gefährliche Variante. Die Eingabe x' OR '1'='1 wird per f-String in den SQL-Text geklebt, es entsteht WHERE teil = 'x' OR '1'='1'. Das ' der Eingabe beendet den Text, OR '1'='1' wird zu SQL-Code, und '1'='1' ist für jede Zeile wahr: alle fünf Aufträge kommen zurück. Das ist eine SQL-Injection.
  8. Zeilen 43 und 44: Mit dem Platzhalter bleibt der SQL-Text fest, der Wert geht getrennt als Daten mit. Die Datenbank sucht ein Teil, das wörtlich x' OR '1'='1 heißt, und findet keines: 0 Treffer.
  9. Zeile 45: close() schließt die Verbindung.
  10. Selbsterklärung: Setze in Zeile 38 eingabe = "WELLE_20H6" und führe aus: Wie viele Treffer meldet die unsichere, wie viele die sichere Variante? Ändere dann in Zeile 28 status != ? in status = ?: Welcher Auftrag erscheint?

Ablauf verfolgen

Eine Abfrage liefert eine Liste von Tupeln, und die liest du mit einer Schleife aus. Führe das Programm im Kopf aus, Zeile für Zeile, so wie Python es tut. Die Liste in Zeile 1 steht dort stellvertretend für das Ergebnis von fetchall(). Schreibe Werte ab; Text steht in Anführungszeichen, ein Dictionary in geschweiften Klammern. Zeile 1 legt nur die Liste an und musst du nicht eintragen.

Zweiter Ablauf: Das Ergebnis eines GROUP BY wird in ein Dictionary übernommen.

Zeilen ordnen

Alle Zeilen sind da, aber durcheinander. Bring sie in die richtige Reihenfolge und rücke die Zeilen im Block ein (Pfeil nach rechts oder Mausziehen). Manche Zeilen gehören nicht ins Programm.

Das Programm baut eine Übungs-Datenbank, trägt einen Auftrag ein, schreibt fest und gibt alle Teile mit einer Menge über 100 aus. Der commit steht direkt nach dem Einfügen. Funktion mit fetchone und None-Prüfung

Die Funktion liefert den Teilenamen zu einer Auftragsnummer oder den Text „unbekannt“, wenn es die Nummer nicht gibt. Zwei Zeilen sind Ablenker: eine mit einem Tupel-Fehler und eine, die das ganze Tupel statt seines Inhalts zurückgibt.

Lücken füllen

Jetzt tippst du Teile selbst. Ergänze die vier Lücken, sodass das Programm die Aufträge von F1 mit einem Platzhalter abfragt, die Antwort abholt und die Änderung festschreibt. Das Programm läuft mit der echten Datei fz3.db.

import sqlite3

db = sqlite3.connect("fz3.db")
cur = db.cursor()

maschine = "F1"
cur.execute("SELECT nr, menge FROM auftraege WHERE maschine = @@?@@ AND status != 'fertig'", @@(maschine,)|[maschine]@@)
treffer = cur.@@fetchall@@()
print(treffer)

cur.execute("UPDATE auftraege SET status = 'fertig' WHERE nr = 4712")
db.@@commit@@()
db.close()
  1. Lücke 1: Im SQL-Text steht kein Wert, sondern ein Zeichen, das den Platz für den Wert freihält (Syntax-Karte 4).
  2. Lücke 2: Die Werte stehen in einem Tupel. Bei einem Wert braucht das Tupel ein Komma: die Variable, Komma, in runden Klammern.
  3. Lücke 3: Welche Methode holt alle Zeilen der Antwort als Liste von Tupeln ab? (Mit runden Klammern dahinter, die stehen schon da.)
  4. Lücke 4: Der Befehl, der Änderungen festschreibt (Syntax-Karte 7). Er steht ohne Klammern in der Lücke.

PAP: Eingaben prüfen

Bevor Eingaben in die Datenbank gehen, prüfst du sie. Platzhalter schützen vor SQL-Injection, aber nicht vor Unsinn: Eine Menge von minus 5 oder 90 000 Stück hat in der Auftragsdatenbank nichts verloren. Das ist die zweite Schutzschicht. Du zeichnest den Plan dazu, die Prüfung erzeugt aus deinem PAP Python-Code und testet ihn mit mehreren Eingabefolgen, auch mit den Randwerten. Eine Datenbank brauchst du dafür nicht.

Mengen prüfen, bevor sie in die Datenbank gehen

Zeichne einen PAP, der Mengen für neue Aufträge einliest, bis 0 eingegeben wird. Die 0 beendet nur die Eingabe, sie zählt nicht mit. Eine Menge ist ungültig, wenn sie kleiner als 0 oder größer als 2000 ist. Gültige Mengen werden zur Summe addiert, ungültige nur gezählt. Am Ende gibst du erst die summe und dann die Anzahl ungueltig aus (zwei Ausgabe-Symbole). Die erste Eingabe steht schon da. Tipp zum Muster: Die Eingabe steht vor der Schleife und noch einmal am Ende des Schleifenrumpfs.

  1. Nach der ersten Eingabe legst du zwei Zähler an: summe = 0 und ungueltig = 0 (zwei Operationen).
  2. Die Schleife läuft, solange die Menge nicht 0 ist: menge != 0 (kopfgesteuerte Schleife). Im Rumpf steht zuerst eine Raute, am Ende des Rumpfs die nächste Eingabe von menge.
  3. Die Raute prüft auf ungültig: menge < 0 or menge > 2000. „ja“: ungueltig = ungueltig + 1, „nein“: summe = summe + menge.
  4. Nach der Schleife kommen zwei Ausgaben: summe und ungueltig.

Szenario: Aufträge suchen und Status setzen

Prompt eines Studierenden

Schreib mir zwei Python-Funktionen für die Auftragsdatenbank fz3.db (Tabelle auftraege mit nr, teil, maschine, menge, status). auftrag_suchen(cur, teil) gibt die Nummern aller Aufträge für ein Teil als sortierte Liste zurück. status_setzen(db, nr, status) setzt den Status des Auftrags mit der Nummer nr und gibt den bisherigen Status zurück. Gibt es die Nummer nicht, soll die Funktion nichts ändern und None zurückgeben.

KI-Antwort (Python)

Tipp: Es sind vier Fehler eingebaut, in vier verschiedenen Zeilen. Einer davon betrifft eine Zeile, die zu früh endet: Dort fehlt etwas. Zwei Fehler bringen das Programm zum Absturz oder verfälschen die Daten, ohne dass man es sofort merkt. Nicht jede Zeile ist falsch.

Würdest du das freigeben? Markiere die fehlerhaften Zeilen, dann lass auflösen.

Die vier Fehler

Fehler 1: f-String im SQL-Text (Zeile 6)

Der Teilename wird direkt in den SQL-Text geklebt. Mit einem normalen Teil läuft das. Mit x' OR '1'='1 werden alle Aufträge geliefert (SQL-Injection), und mit O'Brien bricht die Abfrage mit einem Syntaxfehler ab, weil das ' den SQL-Text beendet. Lösung: cur.execute("SELECT nr FROM auftraege WHERE teil = ? ORDER BY nr", (teil,)). Das Tupel mit Komma nicht vergessen.

Fehler 2: fetchone ohne None-Prüfung (Zeile 14)

Der Prompt verlangt: Gibt es die Nummer nicht, soll None zurückkommen. Die KI nimmt aber sofort [0] vom Ergebnis von fetchone(). Bei einer unbekannten Nummer ist das Ergebnis None, und es gibt einen TypeError: 'NoneType' object is not subscriptable. Lösung: erst zeile = cur.fetchone(), dann if zeile is None: return None.

Fehler 3: UPDATE ohne WHERE (Zeile 15)

Das gefährlichste Stück. Die Zeile setzt den Status aller Aufträge, nicht nur den von nr. Es gibt keinen Fehler und keine Warnung: Ein einziger Aufruf macht jeden Auftrag „fertig“. Lösung: WHERE nr = ? und das Tupel (status, nr) (die Reihenfolge der Werte entspricht der Reihenfolge der Fragezeichen).

Fehler 4: kein commit (Zeile 16)

Die Funktion endet mit return alt, ohne die Änderung festzuschreiben. Das Programm läuft, die Änderung ist in derselben Verbindung sogar sichtbar, aber sobald die Verbindung geschlossen wird oder ein anderes Programm die Datei liest, ist sie weg. Lösung: db.commit() nach dem UPDATE und vor dem return.

Die Fehler einzeln zum Ausprobieren

Je ein Aufruf mit fz3.db, damit du siehst, was passiert: die Injection, der Apostroph, das UPDATE ohne WHERE, das fehlende commit und das fetchone ohne Prüfung. Danach schreibst du die Korrektur selbst.

db = sqlite3.connect("fz3.db")
cur = db.cursor()

teil = "x' OR '1'='1"                       # Fehler 1: die Eingabe wird zu SQL-Code
cur.execute(f"SELECT nr FROM auftraege WHERE teil = '{teil}' ORDER BY nr")
print(len(cur.fetchall()), "Treffer statt 0")

teil = "O'Brien"
cur.execute(f"SELECT nr FROM auftraege WHERE teil = '{teil}' ORDER BY nr")   # bricht ab: near "Brien": syntax error
import sqlite3

db = sqlite3.connect("fz3.db")
cur = db.cursor()

cur.execute("UPDATE auftraege SET status = ?", ("fertig",))      # Fehler 3: kein WHERE
cur.execute("SELECT COUNT(*) FROM auftraege WHERE status = ?", ("fertig",))
print(cur.fetchone()[0], "von 12 Aufträgen sind jetzt fertig")

cur.execute("SELECT status FROM auftraege WHERE nr = ?", (4713,))

Merke

Bei KI-Code, der SQL schreibt, prüfst du vier Dinge: Stehen die Werte als Platzhalter im Text, oder steckt ein f-String im SQL? Hat jedes UPDATE und DELETE ein WHERE? Ist nach jeder Änderung ein commit da? Wird bei fetchone auf None geprüft? Ein Programm, das beim ersten Test läuft, ist noch nicht richtig. Und: Kopiere nie echte Kundendaten oder Auftragsnummern aus einer Produktivdatenbank in den Prompt.

Jetzt korrigieren

Auch wer die vier Stellen gesehen hat, schreibt sie noch einmal selbst: Das ist der Unterschied zwischen Lesen und Können.

Schreibe beide Funktionen korrigiert, aufbauend auf dem KI-Code im Editor. auftrag_suchen(cur, teil) gibt die sortierte Liste der Nummern zurück und liefert auch für x' OR '1'='1 keinen Treffer. status_setzen(db, nr, status) ändert nur den einen Auftrag, schreibt fest und gibt den bisherigen Status zurück; für eine unbekannte Nummer gibt sie None zurück und ändert nichts. Die Tests bauen eigene Datenbanken, auch mit einem Teil O'Brien.

Erwartet
auftrag_suchen(cur, "WELLE_20H6") -> [4711, 4713, 4715]
status_setzen(db, 4713, "fertig") -> "offen" (bisheriger Status), nur 4713 ist jetzt fertig
status_setzen(db, 9999, "fertig") -> None
  1. Ersetze den f-String durch einen Platzhalter: ... WHERE teil = ? ORDER BY nr", (teil,)). Das Komma im Tupel nicht vergessen.
  2. Hole die Zeile erst in eine Variable: zeile = cur.fetchone(). Ist sie None, return None, bevor etwas geändert wird.
  3. Das UPDATE braucht WHERE nr = ? und das Tupel (status, nr). Danach db.commit(), dann return zeile[0].

Typische Fehlermeldungen

Mit SQL kommen neue Fehlermeldungen. Diese acht siehst du garantiert. Jedes Beispiel lässt sich ausführen: Schau dir die echte Meldung an und lies sie von unten nach oben (zuerst die letzte Zeile). Außerhalb des Labors steht vor dem Fehlernamen noch sqlite3., zum Beispiel sqlite3.OperationalError.

no such table: Tabelle gibt es nicht

Meldung: OperationalError: no such table: auftrag. Der Tabellenname im SQL stimmt nicht (hier fehlt das „e“ am Ende). Prüfe die Schreibweise; welche Tabellen es gibt, siehst du mit SELECT name FROM sqlite_master WHERE type = 'table' (Syntax-Karte 1). Bei :memory: fehlt die Tabelle auch, wenn du das CREATE TABLE vergessen hast.

no such column: Spalte gibt es nicht

Meldung: OperationalError: no such column: nummer. Die Tabelle ist da, aber die Spalte heißt anders. Ein Blick auf SELECT * FROM auftraege LIMIT 1 zeigt die Daten; die Spaltennamen stehen im CREATE TABLE. KI-Code erfindet Spaltennamen gern, wie in V17 die JSON-Schlüssel.

syntax error: Tippfehler im SQL-Wort

Meldung: OperationalError: near "SELEC": syntax error. Die Meldung nennt die Stelle (near), an der die Datenbank nicht mehr weiterkam. Meist ist es das Wort an dieser Stelle oder das davor: Tippfehler, fehlendes Komma, ein Wort zu viel. SQL-Fehler sind zur Laufzeit da, denn Python prüft den SQL-Text nicht, es ist für Python nur ein String.

syntax error: Anführungszeichen in den Daten (f-String)

Meldung: OperationalError: near "Brien": syntax error. Der SQL-Text lautet jetzt WHERE teil = 'O'Brien': Das ' im Namen beendet den Text, und Brien ist plötzlich SQL-Code. Dasselbe passiert bei der Injection, nur mit Absicht. Abhilfe: Wert als Platzhalter, cur.execute("SELECT nr FROM auftraege WHERE teil = ?", (teil,)). Damit geht O'Brien problemlos.

Incorrect number of bindings: Tupel ohne Komma

Meldung: ProgrammingError: Incorrect number of bindings supplied. The current statement uses 1, and there are 2 supplied. Ohne Komma ist ("D2") kein Tupel, sondern nur der Text „D2“, und der hat zwei Zeichen: Die Datenbank sieht zwei Werte für einen Platzhalter. Abhilfe: (maschine,) mit Komma. Dieselbe Meldung kommt, wenn Platzhalter und Werte schlicht nicht zusammenpassen: Zähle die Fragezeichen und die Werte.

UNIQUE constraint failed: Primärschlüssel doppelt

Meldung: IntegrityError: UNIQUE constraint failed: auftraege.nr. Die Auftragsnummer ist der Primärschlüssel und darf nur einmal vorkommen. Das ist kein Fehler der Datenbank, sondern ihr Schutz. In eigenem Code fängst du ihn gezielt ab: except sqlite3.IntegrityError: (V09: nie ein leeres except). Das üben wir im Klausur-Modus.

table … has 5 columns: zu wenige Werte

Meldung: OperationalError: table auftraege has 5 columns but 3 values were supplied. INSERT INTO tabelle VALUES verlangt für jede Spalte einen Wert. Ergänze die fehlenden (Menge und Status) oder nenne die Spalten ausdrücklich: INSERT INTO auftraege (nr, teil, maschine) VALUES (?, ?, ?); die übrigen Spalten bleiben dann leer.

You can only execute one statement: zwei Befehle in einem

Meldung: ProgrammingError: You can only execute one statement at a time. execute führt eine Anweisung aus. Das stoppt die berühmte Injection mit '; DROP TABLE …; --, aber nicht die Variante mit OR '1'='1 aus dem Beispiel. Andere Schnittstellen und Datenbanken erlauben mehrere Anweisungen auf einmal. Verlass dich nicht auf diesen Zufall: Der Schutz sind die Platzhalter.

Menge je Maschine

Gib die Gesamtmenge je Maschine aus, berechnet von der Datenbank (GROUP BY mit SUM), sortiert nach der Maschine (ORDER BY). Je Maschine eine Zeile im Format D2: 3900 Stück. Alle Aufträge zählen mit, egal welchen Status sie haben. Die Tests ändern die Aufträge; ein fest hingeschriebenes Ergebnis besteht nicht.

Erwartet

F1: 710 Stück

  2. Hänge ORDER BY maschine an, damit die Reihenfolge feststeht.

Auftrag fertig melden

Die Zelle meldet einen fertigen Auftrag. Das Programm liest die Auftragsnummer mit input(), setzt den Status dieses Auftrags in fz3.db auf fertig (UPDATE mit WHERE und Platzhaltern), schreibt mit commit fest und liest den Status mit SELECT und fetchone zurück. Ausgabe: Auftrag 4713: fertig. Gibt es die Nummer nicht, lautet die Ausgabe Auftrag nicht gefunden. Die Tests öffnen die Datei danach selbst und prüfen, ob nur dieser eine Auftrag geändert ist.

Erwartet
Eingabe: 4713
Ausgabe: Auftrag 4713: fertig

Eingabe: 9999
Ausgabe: Auftrag nicht gefunden
  1. cur.execute("UPDATE auftraege SET status = ? WHERE nr = ?", ("fertig", nr)): Die Werte im Tupel stehen in der Reihenfolge der Fragezeichen. Danach db.commit().
  2. Zurücklesen: cur.execute("SELECT status FROM auftraege WHERE nr = ?", (nr,)) und zeile = cur.fetchone(). Das Komma im Tupel!
  3. if zeile is None: gibt es die Nummer nicht (das UPDATE hat dann nichts getroffen). Sonst steht der Status in zeile[0].

Aufträge je Maschine und Status

Schreibe die Funktion auftraege_fuer(cur, maschine, status). Sie fragt mit dem übergebenen Cursor ab und gibt eine Liste der Auftragsnummern zurück, die zu dieser Maschine und diesem Status passen, aufsteigend sortiert. Die Werte kommen als Platzhalter in die Abfrage. Die Tests rufen die Funktion auch mit Eingaben wie x' OR '1'='1 und mit Namen mit Apostroph auf.

Erwartet
auftraege_fuer(cur, "D2", "offen") -> [4713, 4717, 4719, 4720]
auftraege_fuer(cur, "x' OR '1'='1", "offen") -> []
  1. Zwei Platzhalter, zwei Werte im Tupel: ... WHERE maschine = ? AND status = ? ORDER BY nr", (maschine, status)).

  3. Gibt die Funktion nichts zurück, bekommst du None. Der Rückgabewert steht hinter return.
