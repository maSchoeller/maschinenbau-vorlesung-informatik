Werkzeugkasten

Heute neu in Python: String-Methoden (lower, upper, replace, split, join, count, startswith, endswith, in bei Texten) und die List Comprehension mit und ohne if. Alle Befehle des Kurses stehen außerdem rechts in der Befehls-Bibliothek. Führe jede Karte aus. Bei den Karten mit Comprehension und Schleife hilft „Schritt für Schritt“.

Syntax-Karte 1

Texte umwandeln: strip, lower, upper, replace

text = "  Die Welle trägt das Zahnrad.  "
sauber = text.strip()                       # Leerzeichen an beiden Enden weg
print(sauber.lower())                       # alles klein
print(sauber.upper())                       # alles groß
print(sauber.replace("Welle", "Achse"))     # ersetzen
print(sauber.replace(".", " . "))           # Punkt mit Leerzeichen: wird ein eigenes Wort
print(text)                                 # das Original ist unverändert
  • Eine Methode steht hinter dem Punkt: text.lower(). Das Ergebnis ist ein neuer Text. Ein String ist unveränderlich, text.lower() allein ändert text nicht. Du brauchst eine Zuweisung: text = text.lower().
  • strip() entfernt Leerzeichen und Zeilenumbrüche am Anfang und Ende, replace(alt, neu) ersetzt alle Vorkommen, auch replace(" ", "") (ohne Leerzeichen) ist möglich.
  • Methoden lassen sich verketten: text.strip().lower().replace(".", "") arbeitet von links nach rechts.
  • Ein Wert wie text[0] = "d" ist ein TypeError: Einzelne Zeichen eines Strings lassen sich nicht ersetzen.
Syntax-Karte 2

Zerlegen und zusammenfügen: split und join

satz = "das lager stützt die welle"
woerter = satz.split(" ")                  # Text -> Liste
print(woerter, len(woerter))
print(" ".join(woerter))                   # Liste -> Text, Leerzeichen dazwischen
print("-".join(woerter))                   # anderes Trennzeichen
print(", ".join(woerter[:2]))
zeile = "12.004;11.998;12.019"
print(zeile.split(";"))                    # Strings, noch keine Zahlen
zahlen = [12.004, 11.998]
print(" ".join(zahlen))                    # Fehler: join braucht Strings
  • text.split(trenner) liefert eine Liste von Strings. Mit dem Trennzeichen " " trennt es an jedem Leerzeichen: Zwei Leerzeichen hintereinander ergeben ein leeres Stück "". Das filterst du mit einer Comprehension heraus (Karte 5).
  • trenner.join(liste) setzt eine Liste aus Strings zu einem Text zusammen. Der Trenner steht vor dem Punkt. Enthält die Liste Zahlen, gibt es einen TypeError (zweites Beispiel). Erst umwandeln: [str(x) for x in zahlen].
  • split und join sind Gegenstücke: " ".join(text.split(" ")) ergibt wieder den Ursprungstext.
Syntax-Karte 3

Suchen und zählen: count, startswith, endswith, in

satz = "Die Welle trägt das Zahnrad. Die Welle treibt die Schraube."
print(satz.count("Welle"))                 # wie oft kommt der Text vor?
print(satz.count("die"), satz.lower().count("die"))   # Groß- und Kleinschreibung zählt!
print(satz.startswith("Die"), satz.endswith("Schraube."))
print("Zahnrad" in satz, "Kupplung" in satz)
wort = "welle"
print(len(wort), wort.upper() == "WELLE")
woerter = ["die", "welle", "die", "schraube"]
print(woerter.count("die"))                # count gibt es auch bei Listen: ganze Elemente
  • text.count(stück) zählt, wie oft das Stück im Text vorkommt, auch mitten in einem Wort: "diesel".count("die") ist 1. Bei einer Liste zählt liste.count(x) dagegen nur ganze, gleiche Elemente.
  • startswith(anfang) und endswith(ende) liefern True oder False. in prüft, ob ein Teilstück irgendwo im Text steht.
  • Groß- und Kleinschreibung zählen immer: „Die“ und „die“ sind verschiedene Texte. Vor dem Zählen oder Vergleichen darum lower().
Syntax-Karte 4

List Comprehension: die Kurzform der append-Schleife

zahlen = [1, 2, 3, 4]

quadrate = []                      # Langform
for x in zahlen:
    quadrate.append(x * x)
print(quadrate)

print([x * x for x in zahlen])     # Kurzform: dasselbe in einer Zeile

woerter = ["welle", "lager"]
print([w.upper() for w in woerter])
print([len(w) for w in woerter])
  • Lies sie wie einen Satz: [x * x for x in zahlen] heißt „gib mir x mal x für jedes x in zahlen“. Vorn steht, was in die neue Liste kommt, hinten, woher die Elemente kommen.
  • Das Ergebnis ist immer eine neue Liste. Die alte bleibt unverändert.
  • Mit „Schritt für Schritt“ siehst du den Unterschied zur Langform: Die Kurzform ist eine Zeile, aber der Rechner läuft trotzdem Element für Element durch.
Syntax-Karte 5

List Comprehension mit Filter

messungen = [12.004, 11.998, 12.019, 12.011]

ausserhalb = []                    # Langform: Filter-Muster
for d in messungen:
    if d < 12.000 or d > 12.018:
        ausserhalb.append(d)
print(ausserhalb)

print([d for d in messungen if d < 12.000 or d > 12.018])   # Kurzform

woerter = ["das", "", "lager", ""]
print([w for w in woerter if w != ""])     # leere Stücke entfernen
print([w.upper() for w in woerter if w != ""])
  • Am Ende steht ein if als Filter: Nur Elemente, für die die Bedingung wahr ist, kommen in die neue Liste. Die Bedingung wird vor dem Ausdruck ausgewertet.
  • Ein else gibt es in dieser Form nicht. Wer Elemente umwandeln und weglassen will, filtert mit if und rechnet vorn: [w.upper() for w in woerter if w != ""].
  • Wird die Zeile länger als eine Bildschirmzeile oder schwer lesbar, schreib die Schleife. Lesbar vor kurz.
Syntax-Karte 6

Ein Tokenizer in Python

def tokenisiere(text):
    """Zerlegt Text in Kleinbuchstaben-Wörter; der Punkt wird ein eigenes Token."""
    text = text.lower().replace(".", " . ").replace("\n", " ")
    return [wort for wort in text.split(" ") if wort != ""]

tokens = tokenisiere("Die Welle trägt das Zahnrad.\nDas Lager  stützt die Welle.")
print(tokens)
print(len(tokens), tokens.count("welle"))
  • Vier Schritte in dieser Reihenfolge: klein schreiben (sonst sind „Die“ und „die“ zwei Wörter), Satzzeichen abtrennen (sonst ist „Zahnrad.“ ein anderes Wort als „Zahnrad“), zerlegen mit split, leere Stücke entfernen (doppelte Leerzeichen).
  • "\n" steht für einen Zeilenumbruch. Er wird durch ein Leerzeichen ersetzt, damit er ein Wort nicht festklebt.
  • Das ist ein sehr einfacher Tokenizer: Er kennt nur den Punkt. Für Kommas, Klammern und Zahlen mit Einheiten müsstest du ihn erweitern.
Syntax-Karte 7

Training, Wahrscheinlichkeit und Zufall

import random

tokens = ["die", "welle", "trägt", "das", "zahnrad", ".", "die", "welle", "braucht", "fett", "."]
nachfolger = {}                              # Training: Wort -> Liste der Nachfolger
for i in range(len(tokens) - 1):
    wort = tokens[i]
    if wort not in nachfolger:
        nachfolger[wort] = []
    nachfolger[wort].append(tokens[i + 1])
print(nachfolger["welle"])

liste = nachfolger["welle"]
print(liste.count("trägt") / len(liste))     # Wahrscheinlichkeit: Anteil an der Liste

random.seed(1)                               # Startwert: gleicher Seed, gleiche Zahlen
print(random.choice(liste), random.choice(liste))
  • Training = zählen, was auf welches Wort folgte. Das Dictionary bildet jedes Wort auf die Liste seiner Nachfolger ab. Kommt ein Nachfolger mehrfach vor, steht er mehrfach in der Liste.
  • Die Wahrscheinlichkeit eines Nachfolgers ist sein Anteil: liste.count(x) / len(liste). Die Summe aller Anteile ist 1.
  • import random lädt das Zufallsmodul (wie math in V03). random.choice(liste) zieht ein zufälliges Element: Häufige kommen öfter dran. random.seed(zahl) macht den Zufall wiederholbar.
  • Ein Wort, das im Training nie vorne stand, gibt beim Nachschlagen einen KeyError. Prüfe vorher mit in (V08).

Vorgerechnetes Beispiel: ein Mini-Sprachmodell

Aufgabe: Aus sechs Sätzen über Welle, Zahnrad und Lager lernt das Programm ein Bigramm-Modell: Es zerlegt den Text in Tokens, sammelt zu jedem Wort die Nachfolger, berechnet die Wahrscheinlichkeiten für „die“ und würfelt danach mit festem Seed einen Satz. Es ist dasselbe Modell wie das Explorable in der Lerneinheit, nur als Python-Programm. Lies den Code Zeile für Zeile, dann führe ihn aus. Drück danach auf „Schritt für Schritt“ und beobachte, wie das Dictionary nachfolger wächst und wie satz Wort für Wort entsteht.

Der Programmablaufplan zu Teil 3 (Zeilen 40 bis 48) zeigt die Schleife, die den Text erzeugt: Die Raute fragt vor jedem Durchlauf, ob schon ein Punkt gezogen wurde oder die Höchstlänge erreicht ist. Im Code steht dieselbe Logik als for mit break.

  1. Zeilen 4 bis 8: import random lädt das Zufallsmodul, wie import math in V03. text ist ein mehrzeiliger String in drei Anführungszeichen. Das ist unser Trainingstext, der Korpus.
  2. Zeilen 11 bis 14: Der Tokenizer als Funktion (V07). Zeile 13 verkettet drei String-Methoden: lower() macht alles klein, replace(".", " . ") gibt dem Punkt Leerzeichen, replace("\n", " ") ersetzt die Zeilenumbrüche. Zeile 14 ist eine List Comprehension mit Filter: text.split(" ") liefert die Stücke, das if wirft die leeren weg. Die Langform wäre eine leere Liste, eine Schleife und ein append.
  3. Zeilen 17 und 18: Der Aufruf liefert die Token-Liste. len(tokens) ist 36, tokens[:8] sind die ersten acht (Slicing, V08). Das Modell sieht später nur diese Tokens.
  4. Zeilen 21 bis 26: Das Training. Das Dictionary nachfolger bildet jedes Wort auf die Liste seiner Nachfolger ab. Die Schleife läuft über die Indizes bis zum vorletzten Token (len(tokens) - 1), denn das letzte hat keinen Nachfolger. Kommt ein Wort zum ersten Mal vor (not in), bekommt es eine leere Liste, danach hängt append das Wort an, das darauf folgt (tokens[i + 1]). Der Plan zum Training steht im Video.
  5. Zeile 28: Nach „die“ kam fünfmal ein Wort: ['welle', 'welle', 'welle', 'schraube', 'welle']. Wer das Modell „lernt“, hat nur diese Listen gezählt.
  6. Zeilen 31 bis 37: Die Wahrscheinlichkeit ist der Anteil jedes Nachfolgers an der Liste: liste.count(kandidat) / len(liste). Die Liste gezaehlt sorgt dafür, dass jeder Kandidat nur einmal ausgegeben wird. Ergebnis: P(welle | die) = 4/5 = 0,80, P(schraube | die) = 1/5 = 0,20. Das sind dieselben Zahlen wie im Explorable.
  7. Zeilen 40 bis 48: Das Erzeugen. random.seed(4) legt den Startwert des Zufalls fest, damit bei jedem Lauf derselbe Satz herauskommt. Dann: Startwort „das“, Liste satz, und bis zu acht Mal random.choice(nachfolger[wort]). Weil „welle“ in der Liste viermal steht, wird es viermal so oft gezogen wie „schraube“. Das break beendet die Schleife, sobald der Punkt gezogen ist. " ".join(satz) setzt den Satz wieder zusammen.
  8. Selbsterklärung: Das Ergebnis „das zahnrad treibt die schraube hält das zahnrad .“ ist grammatisch und sinnlos. Warum? Jedes Wortpaar kam im Text so vor, aber nicht die Kette. Ändere in Zeile 40 den Seed auf 1, 2 und 3 und lies die Sätze. Dann ändere in Zeile 8 den Text, zum Beispiel um den Satz „Die Schraube braucht Fett.“, und schau, wie sich P(schraube | die) verändert.

Ablauf verfolgen

Bevor du String-Methoden und Comprehensions schreibst, musst du sie lesen können. Führe das Programm im Kopf aus, Zeile für Zeile, so wie Python es tut. Trage ein, was danach in den hervorgehobenen Variablen steht. Texte schreibst du mit Anführungszeichen, Listen so, wie Python sie ausgibt, zum Beispiel ['das', 'lager']. Die Zeile mit for ist ein Schritt je Durchlauf (die Laufvariable ändert sich), eine if-Zeile bekommt keinen eigenen Schritt. Wenn du unsicher bist, lass den Code vorher im „Vorgerechneten Beispiel“ oder in einer Karte mit „Schritt für Schritt“ laufen.

Zweiter Ablauf: dasselbe Muster wie eine List Comprehension, aber als Schleife mit append geschrieben. Das zweite Wort ist ein leerer Text '' (zwei Leerzeichen hintereinander). Die Zeile mit for ist ein Schritt je Durchlauf; die if-Zeile hat keinen eigenen Schritt, aber append läuft nur, wenn die Bedingung wahr ist.

Zeilen ordnen

Alle Zeilen sind da, aber durcheinander. Bring sie in die richtige Reihenfolge und rücke die Zeilen im Rumpf ein (Pfeil nach rechts oder Mausziehen). Manche Zeilen sind Ablenker: Sie gehören nicht ins Programm.

Tokenizer-Funktion

Die Funktion bekommt einen Text und gibt die Liste der Tokens zurück: klein geschrieben, der Punkt als eigenes Token, ohne leere Stücke. Überlege vorher: Was muss zuerst passieren, und wo steht das return?

Training: Nachfolger sammeln

Das Programm legt ein leeres Dictionary an und sammelt zu jedem Wort die Liste seiner Nachfolger. Achte auf die Einrückung: Die Schleife läuft nur bis zum vorletzten Token, und die leere Liste wird nur beim ersten Auftreten angelegt.

Erste eigene Aufgabe: Satz auswerten

Jetzt schreibst du die Auswertung selbst, mit Tests als Sicherheitsnetz. Die Tests laufen mit mehreren Eingaben, auch mit solchen, die du nicht siehst.

Das Programm liest einen Satz ein und gibt drei Zeilen aus: die Zahl der Wörter, die langen Wörter (mehr als 5 Buchstaben, als Liste, in der Reihenfolge im Satz) und wie oft das Wort „die“ vorkommt. Dabei sollen Groß- und Kleinschreibung und der Punkt am Satzende keine Rolle spielen. Benutze für die langen Wörter eine List Comprehension mit Filter.

Ausgabe genau so (Eingabe „Die Welle treibt das Zahnrad an.“):
Wörter: 6
Lange Wörter: ['treibt', 'zahnrad']
Anzahl 'die': 1

Gegenprobe von Hand: die, welle, treibt, das, zahnrad, an sind sechs Wörter. Mehr als fünf Buchstaben haben „treibt“ (6) und „zahnrad“ (7); „welle“ hat genau fünf.

  1. Erst aufräumen: satz.lower().replace(".", "").split(" "). So werden Groß-/Kleinschreibung und der Punkt unwichtig.
  2. Die langen Wörter: [w for w in woerter if len(w) > 5] (Syntax-Karte 5). „Mehr als 5“ heißt >, nicht >=.
  3. Die Anzahl von „die“ zählst du in der Liste mit woerter.count("die"): So zählt „diesel“ nicht mit. Die Ausgabe der Liste ist print("Lange Wörter:", lange).

Code-Review: KI-Antworten prüfen

Phase 2 beginnt: Die KI erzeugt, du prüfst. Zwei Szenarien. Erst ein Programm mit einem typischen Tokenizer-Fehler, dann eine Text-Antwort mit einem falschen Zahlenwert und einer erfundenen Norm. Klick die Zeilen an, die du für fehlerhaft hältst, dann lass auflösen.

Szenario 1: Wörter zählen und filtern

Prompt eines Studierenden

Schreib mir ein kleines Python-Programm für den Text „Die Welle trägt das Zahnrad. Das Zahnrad treibt die Welle.“ (1) Zerlege den Text in Wörter (Tokens) und zähle, wie oft „welle“ vorkommt. (2) Gib alle Wörter mit mehr als 5 Buchstaben aus. (3) Zähle, wie oft jedes Wort vorkommt, in einem Dictionary.

KI-Antwort (Python)

Tipp: Es sind drei Fehler eingebaut, einer je Teilaufgabe. Nicht jede Zeile ist falsch.

Würdest du das freigeben? Markiere die fehlerhaften Zeilen, dann lass auflösen.

Die drei Fehler

Fehler 1: der Tokenizer lässt Satzzeichen und Großschreibung stehen (Zeile 4)

text.split(" ") trennt nur an Leerzeichen. „Welle.“ mit Punkt, „Welle“ mit großem W und „welle“ sind drei verschiedene Tokens, und der Punkt ist gar kein eigenes Token. Das Programm läuft ohne Fehlermeldung, zählt aber 0 statt 2 Mal „welle“. Lösung: erst lower(), den Punkt mit replace(".", " . ") abtrennen, dann split, dann leere Stücke herausfiltern, genau wie tokenisiere im vorgerechneten Beispiel.

Fehler 2: der Filter ist umgedreht (Zeile 8)

Gefragt waren Wörter mit mehr als 5 Buchstaben, der Filter len(t) < 5 sammelt die kurzen. Das Programm gibt ohne Fehlermeldung eine plausibel aussehende Liste aus, nur die falsche. Lösung: len(t) > 5. Gegenprobe von Hand: „zahnrad“ (7 Buchstaben) muss in der Liste stehen.

Fehler 3: zählt nicht hoch, sondern setzt auf 1 zurück (Zeile 15)

Zeile 15 setzt den Zähler bei jedem Vorkommen eines Wortes wieder auf 1. Selbst bei richtigem Tokenizer hätten am Ende alle Wörter den Zähler 1, auch „welle“, das zweimal vorkommt. Wieder keine Fehlermeldung. Lösung: haeufig[t] = haeufig[t] + 1. Gegenprobe: Die Summe aller Zähler muss gleich der Zahl der Tokens sein.

Die KI-Version zum Ausprobieren

Die Ausgaben sind alle falsch: 10 statt 12 Tokens, „welle“ 0 statt 2 Mal, die langen Wörter sind in Wahrheit die kurzen, und alle Zähler stehen auf 1.

text = "Die Welle trägt das Zahnrad. Das Zahnrad treibt die Welle."

def tokenisiere(text):
    return text.split(" ")

tokens = tokenisiere(text)
print(len(tokens), "Tokens, welle kommt", tokens.count("welle"), "mal vor")
lange = [t for t in tokens if len(t) < 5]
print("Lange Wörter:", lange)

haeufig = {}
for t in tokens:
    if t not in haeufig:
        haeufig[t] = 0
    haeufig[t] = 1
print(haeufig)

Korrigierte Version

text = "Die Welle trägt das Zahnrad. Das Zahnrad treibt die Welle."

def tokenisiere(text):
    text = text.lower().replace(".", " . ").replace("\n", " ")
    return [w for w in text.split(" ") if w != ""]

tokens = tokenisiere(text)
print(len(tokens), "Tokens, welle kommt", tokens.count("welle"), "mal vor")
lange = [t for t in tokens if len(t) > 5]
print("Lange Wörter:", lange)

haeufig = {}
for t in tokens:
    if t not in haeufig:
        haeufig[t] = 0
    haeufig[t] = haeufig[t] + 1
print(haeufig)
Merke

Bei Text-Code fragst du: „Groß oder klein? Satzzeichen am Wort? Leere Stücke?“ und prüfst jeden Filter mit einem Wort, das drin sein muss, und einem, das draußen sein muss. Zähler gegenrechnen: Die Summe der Häufigkeiten ist die Zahl der Tokens. Deine Testfälle schreibst du vorher von Hand auf, und die KI liefert den Fall aus ihrem Beispiel, nicht den aus deiner Anlage.

Szenario 2: Auslegung einer Schraubenverbindung (reine Text-Antwort)

Prompt eines Studierenden

Ich lege die Schraubenverbindung am Lagerdeckel aus (Schraube M10, Festigkeitsklasse 8.8) und die Passfeder der Welle. Welches Anzugsdrehmoment gilt, und in welcher Norm stehen die Maße von Schraube und Passfeder? Bitte mit Quellen.

KI-Antwort (Text, die Normverweise sind im Szenario teilweise erfunden)

Tipp: Es sind vier Fehler eingebaut. Nicht jede Zeile ist falsch. Die Sprache klingt überall gleich sicher.

Würdest du das freigeben? Markiere die fehlerhaften Zeilen, dann lass auflösen.

Die vier Fehler

Fehler 1: falscher Zahlenwert (Zeile 1)

Der Tabellenwert für M10 (8.8, Gesamtreibungszahl 0,14) ist rund 49 Nm. Die 86 Nm gehören zu M12. Der falsche Wert hat die richtige Form: Zahl, Einheit, passende Größenordnung. Das ist genau die Stelle, an der ein Sprachmodell „wahrscheinlichen“ Text erzeugt. Prüfen: Originaltabelle oder Herstellerangabe, und ein Überschlag (M10 muss weniger brauchen als M12).

Fehler 2: Zusage ohne Randbedingungen (Zeile 2)

Ein Anzugsdrehmoment hängt von Reibungszahl, Schmierung, Anziehverfahren und Bauteil ab und gilt nur unter Annahmen. „Ohne weitere Prüfung verwenden“ ist eine Aussage, die ein Modell nicht verantworten kann. Wer so etwas ungeprüft übernimmt, trägt trotzdem allein die Verantwortung.

Fehler 3: erfundene Norm (Zeile 4)

DIN 6885 regelt Passfedern, aber „Teil 12, Ausgabe 2019“ ist in diesem Szenario erfunden. Teilnummer und Jahr sehen echt aus, weil ein Normverweis eine typische Form hat. Prüfen: Die Nummer im Normenportal oder in der Hausbibliothek öffnen. Eine Norm, die du nicht aufrufen kannst, ist nicht belegt.

Fehler 4: eine Behauptung, die das Modell nicht leisten kann (Zeile 6)

Ein Sprachmodell schlägt nichts nach und prüft nichts gegen aktuelle Normen. Der Satz „wurde geprüft“ ist selbst nur wahrscheinlicher Text. Auch „mit Quellen“ im Prompt ändert daran nichts: Die Quellen können erfunden sein. Die Zeilen 3 und 5 sind unauffällig: DIN 933 ist die frühere Sechskantschraube (heute DIN EN ISO 4017), und VDI 2230 Blatt 1 ist die Berechnungsrichtlinie für hochbeanspruchte Schraubenverbindungen. Auch sie prüfst du aber selbst, bevor du sie zitierst.

Merke

Fünf Prüffragen an jede KI-Antwort mit Zahlen und Normen: Stimmt der Wert (Tabelle, Überschlag)? Stimmt die Einheit? Kann ich die Norm öffnen? Gilt die Aussage nur unter Bedingungen, die fehlen? Behauptet die Antwort etwas, das ein Sprachmodell gar nicht tun kann (prüfen, nachschlagen)? Dann ist die KI ein schneller Entwurf, nicht die Quelle.

Typische Fehlermeldungen

Fehlermeldungen sind keine Strafe, sondern ein Wegweiser. Bei Texten gibt es allerdings auch Fehler, die keine Meldung auslösen. Diese fünf siehst du garantiert. Jedes Beispiel lässt sich ausführen: Schau dir die echte Meldung an und lies sie von unten nach oben (zuerst die letzte Zeile).

AttributeError: Methode am falschen Objekt

Meldung: AttributeError: 'list' object has no attribute 'lower'. lower() gehört zu Texten, nicht zu Listen. Du hast die Methode an der Liste aufgerufen. Gemeint war vermutlich jedes Wort der Liste: [w.lower() for w in woerter]. Die Meldung nennt den Typ (list) und den Namen, den es dort nicht gibt.

TypeError: join mit Zahlen

Meldung: TypeError: sequence item 0: expected str instance, float found. join setzt nur Texte zusammen, hier sind es Kommazahlen. Wandle erst um: " ".join([str(m) for m in messungen]).

KeyError: Wort nicht im Modell

Meldung: KeyError: 'kupplung'. Das Modell kennt das Wort nicht, weil es im Trainingstext nie vorkam. Ein Sprachmodell kann nur fortsetzen, was es gesehen hat. Prüfe vorher mit if wort in nachfolger: und gib eine Meldung aus oder nimm ein Startwort aus dem Vokabular.

TypeError: einzelnes Zeichen ändern

Meldung: TypeError: 'str' object does not support item assignment. Ein String ist unveränderlich, einzelne Zeichen lassen sich nicht ersetzen. Du baust einen neuen Text: name = "W" + name[1:] oder name = name.capitalize() (erster Buchstabe groß).

Falsches Ergebnis ohne Meldung: das Ergebnis weggeworfen

Ausgabe: 0 und eine Liste mit „Die“ und „Zahnrad.“. Python meldet nichts, denn text.lower() ist ein gültiger Ausdruck, dessen Ergebnis nur nirgends gespeichert wird. Strings sind unveränderlich: Der Text in text ist immer noch der alte. Richtig ist text = text.lower(). Solche Fehler fängst du nur mit einer Gegenprobe: Stimmt der Zähler?

Fehler finden: Wörter zählen

Eine KI hat die Funktion zaehle(text, wort) geschrieben, die zählt, wie oft ein ganzes Wort im Text vorkommt, ohne Rücksicht auf Groß- und Kleinschreibung und den Punkt am Satzende. Sie liefert falsche Werte. Finde die Fehler und repariere die Funktion (sie soll den Wert zurückgeben, nicht ausgeben).

Erwartet (Rückgabewerte):
zaehle("Die Welle dreht die Welle.", "welle")   ->  2
zaehle("Die Welle dreht diese Scheibe, diese Scheibe dreht die Nabe.", "die")  ->  2

Schau dir zuerst die Ausgabe des Programms an: Welche beiden Beispiele stimmen nicht, und warum?

  1. text.count(wort) zählt Teilstücke im Text: „die“ steckt auch in „Diese“. Ganze Wörter zählst du in einer Liste von Wörtern: erst zerlegen, dann liste.count(wort).
  2. Vor dem Zerlegen alles klein schreiben (lower()), und zwar auch das gesuchte Wort. Den Punkt ersetzt du durch ein Leerzeichen.
  3. Leere Stücke stören beim Zählen eines normalen Wortes nicht. Für den leeren Text kommt 0 heraus, weil das Wort nicht in der Liste steht.

PAP zeichnen: Text erzeugen

Text erzeugen mit dem häufigsten Nachfolger

Dieses Mini-Modell hat Temperatur 0: Es nimmt immer den häufigsten Nachfolger, das Wörterbuch naechstes ist schon fertig (Start-Symbol im Plan). Zeichne den Programmablaufplan, der erst die Höchstlänge n (ganze Zahl) einliest, dann mit dem Startwort „das“ beginnt und so lange den nächsten Wert nachschlägt und an die Liste satz hängt, bis der Punkt erreicht ist oder die Liste n Wörter lang ist. Danach gibt der Plan den Satz aus, die Wörter mit Leerzeichen verbunden (" ".join(satz)).

Beispiele:
n = 3   ->  das zahnrad treibt
n = 10  ->  das zahnrad treibt die welle .

Tipp: Eine Schleife mit zwei Abbruchbedingungen ist eine Raute: „kein Punkt UND weniger als n Wörter?“. Die Raute fragt vor jedem Durchlauf, ob weitergemacht wird. Im Rumpf stehen zwei Rechtecke.

  1. Reihenfolge der Symbole: das Wörterbuch (steht schon da), Eingabe n, Startwort, Liste satz mit dem Startwort, dann die Schleife, dann die Ausgabe.
  2. Die Schleifenbedingung muss beides prüfen: wort != '.' and len(satz) < n. Bei „ja“ geht es in den Rumpf, bei „nein“ zur Ausgabe.
  3. Im Rumpf: erst wort = naechstes[wort], dann satz.append(wort). Die Ausgabe ist ' '.join(satz) (das Symbol „Ausgabe“ setzt das print drumherum).

Bigramm-Modell trainieren

Schreibe zwei Funktionen. trainiere(tokens) bekommt eine Liste von Tokens und gibt ein Dictionary zurück: Jedes Wort steht für die Liste seiner Nachfolger (in der Reihenfolge des Auftretens, Wiederholungen bleiben). wahrscheinlichkeit(nachfolger, wort, kandidat) gibt den Anteil von kandidat an den Nachfolgern von wort zurück (eine Zahl zwischen 0 und 1). Kommt wort nicht im Dictionary vor oder folgt kandidat nie darauf, ist das Ergebnis 0.

Erwartet (Rückgabewerte), mit tokens = ['die', 'welle', 'trägt', 'die', 'schraube', 'hält']:
trainiere(tokens)["die"]                                   ->  ['welle', 'schraube']
wahrscheinlichkeit(trainiere(tokens), "die", "welle")      ->  0.5
wahrscheinlichkeit(trainiere(tokens), "kupplung", "die")   ->  0
  1. trainiere ist die Trainingsschleife aus dem vorgerechneten Beispiel (Zeilen 21 bis 26), nur als Funktion mit return nachfolger am Ende.
  2. Die Schleife läuft über range(len(tokens) - 1): Das letzte Token hat keinen Nachfolger.
  3. wahrscheinlichkeit: Erst mit in prüfen, ob das Wort ein Schlüssel ist (sonst return 0). Dann liste.count(kandidat) / len(liste).

Knobelaufgabe: Temperatur selbst rechnen

Im Explorable hast du an der Temperatur T gedreht. Rechne sie jetzt selbst. Schreibe die Funktion mit_temperatur(p, t): Sie bekommt eine Liste von Wahrscheinlichkeiten p (Summe 1) und die Temperatur t (größer als 0) und gibt eine neue Liste zurück. Jede Wahrscheinlichkeit wird zu p ** (1 / t), danach werden alle durch die Summe der neuen Werte geteilt, damit sie wieder 1 ergeben. Die Eingabeliste bleibt unverändert.

Erwartet (Rückgabewerte, gerundet):
mit_temperatur([0.8, 0.2], 1)    ->  [0.8, 0.2]
mit_temperatur([0.8, 0.2], 2)    ->  [0.6667, 0.3333]
mit_temperatur([0.8, 0.2], 0.5)  ->  [0.9412, 0.0588]

Gegenprobe von Hand für t = 2: √0,8 ≈ 0,894 und √0,2 ≈ 0,447, zusammen 1,342. Geteilt: 0,667 und 0,333. Vergleiche mit dem Explorable.

  1. Zwei Schritte: erst jede Wahrscheinlichkeit potenzieren (x ** (1 / t), V02), dann alle durch die Summe teilen. Beides sind List Comprehensions.
  2. Die Summe der neuen Werte brauchst du erst nach dem ersten Schritt: neu = [...], summe = sum(neu).
  3. Klammern bei 1 / t nicht vergessen: x ** 1 / t wäre etwas ganz anderes.
