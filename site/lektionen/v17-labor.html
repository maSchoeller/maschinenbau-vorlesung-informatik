Syntax-Karte 1

JSON-Text und Python-Daten: loads und dumps

import json

text = '{"id": "D2", "drehzahl_1_min": 1450, "laeuft": true, "fehler": null}'
d = json.loads(text)                 # JSON-Text -> Dictionary
print(type(d), d["id"], d["drehzahl_1_min"])
print(d["laeuft"], d["fehler"])      # True None

zurueck = json.dumps(d)              # Dictionary -> JSON-Text
print(zurueck)
print(json.dumps(d, indent=2))       # mit Einrückung, gut lesbar

  • json.loads(text) macht aus JSON-Text ein Dictionary oder eine Liste (das s steht für „string“). json.dumps(obj) macht den Rückweg und liefert wieder Text.
  • JSON verlangt doppelte Anführungszeichen und kein Komma nach dem letzten Eintrag. Ein Python-Dictionary mit einfachen Anführungszeichen ist kein gültiges JSON: json.loads wirft einen JSONDecodeError.
  • Die Tabelle zeigt, was aus welchem JSON-Baustein wird. Das null wird zu None, true zu True (groß geschrieben).
Syntax-Karte 2

Verschachtelte Daten lesen

zelle = {
    "zelle": "FZ-3",
    "maschinen": [
        {"id": "D2", "status": "laeuft"},
        {"id": "R1", "status": "gestoert"},
    ],
    "verschleiss": {"T1": 22, "T4": 83},
}

print(zelle["maschinen"][1]["id"])         # Liste: Index; Dict: Schlüssel -> R1
for m in zelle["maschinen"]:               # Liste von Dicts durchlaufen
    print(m["id"], m["status"])
print(zelle["verschleiss"]["T4"])          # Dict im Dict: zwei Schlüssel -> 83
print(zelle["verschleiss"].get("T9", 0))   # fehlt der Schlüssel: Ersatzwert, kein Fehler
  • Daten aus dem Netz sind fast immer verschachtelt: ein Dictionary enthält eine Liste, die Liste enthält Dictionaries. Du liest von außen nach innen, ein Zugriff pro Ebene: zelle["maschinen"][1]["id"].
  • Liste = Nummer in eckigen Klammern ([1]), Dictionary = Schlüssel (["id"]). Verwechselst du beides, kommt ein TypeError.
  • .get("T9", 0) (bekannt aus V08) liefert den Ersatzwert, wenn der Schlüssel fehlt. Mit ["T9"] gäbe es einen KeyError.
  • In der Fabrik fehlen Schlüssel öfter, als man denkt: Nicht jedes Gerät meldet alles (die SPS hat keine Stückzahl).
Syntax-Karte 3

JSON-Datei schreiben und lesen: dump und load

import json

meldung = {"maschine": "D2", "werkzeug": "T4", "aktion": "wechseln"}

with open("meldung.json", "w", encoding="utf-8") as datei:
    json.dump(meldung, datei, indent=2)        # Objekt -> Datei

with open("meldung.json", encoding="utf-8") as datei:
    gelesen = json.load(datei)                 # Datei -> Objekt

print(gelesen)
print(gelesen == meldung)
  • json.dump(obj, datei) schreibt in eine geöffnete Datei, json.load(datei) liest aus einer. Beide ohne s: Sie arbeiten mit einer Datei, nicht mit einem Text.
  • Die Merkregel: mit s = String (loads, dumps), ohne s = Datei (load, dump). Das with open kennst du aus V09.
  • json.load(antwort) mit einer requests-Antwort ist ein typischer Fehler: Eine Antwort ist keine Datei. Dafür gibt es antwort.json() (nächste Karte).
Syntax-Karte 4

HTTP mit requests: get, status_code, json

import requests

URL = "../assets/data/v17/api/"        # Adresse der "API" (relativ zu dieser Seite)

antwort = requests.get(URL + "D2.json")
print(antwort.status_code)             # 200 = alles in Ordnung
daten = antwort.json()                 # JSON-Antwort -> Dictionary
print(daten["programm"], daten["stueckzahl_schicht"])
print(antwort.text[:40])               # derselbe Inhalt als roher Text
import requests

antwort = requests.get("../assets/data/v17/api/D9.json")    # diese Maschine gibt es nicht
print(antwort.status_code)             # 404 = nicht gefunden
if antwort.status_code == 200:
    print(antwort.json())
else:
    print("Anfrage fehlgeschlagen, Status", antwort.status_code)
  • requests.get(url) schickt eine Anfrage und liefert die Antwort (ein Objekt). Daran hängen .status_code (Zahl), .text (Text) und .json() (fertig als Dictionary).
  • Prüfe den Status, bevor du .json() aufrufst. Bei 404 ist der Inhalt eine Fehlerseite und kein JSON; .json() bricht dann mit einem Fehler ab.
  • Hier im Labor sind die „Maschinen“ statische Dateien dieser Website. In der Fabrik antwortet ein Server am Leitrechner, aber dein Code sieht genauso aus. Nur GET (lesen) kommt vor, kein Schreiben.
  • Läuft ein Programm außerhalb des Browsers (Codespace), schreibst du die volle Adresse hin, z. B. https://…/assets/data/v17/api/.
Syntax-Karte 5

Fehler abfangen: ValueError und Status prüfen

import json
import requests

# 1. kaputtes JSON abfangen
try:
    daten = json.loads("{'id': 'D2'}")             # einfache Anführungszeichen: kein JSON
except ValueError as fehler:
    print("Kein gültiges JSON:", fehler)
    daten = {}

# 2. Status prüfen statt blind .json() aufzurufen
antwort = requests.get("../assets/data/v17/api/D9.json")
if antwort.status_code != 200:
    print("Maschine nicht erreichbar, Status", antwort.status_code)
else:
    print(antwort.json())
  • Der JSONDecodeError ist eine Unterart des ValueError. Darum fängt except ValueError kaputtes JSON ab (V09: gezielt abfangen, nie ein leeres except:).
  • Ein Netzwerkproblem meldet sich oft nicht als Fehler, sondern als Statuscode (404, 500). Deshalb gehört if antwort.status_code == 200 vor jede Auswertung.
  • Beides zusammen ist das Muster für alles, was von außen kommt: Daten nie ungeprüft glauben.
Syntax-Karte 6

IP-Adressen mit ipaddress

import ipaddress

netz = ipaddress.ip_network("192.168.30.0/24")
print(netz.netmask, netz.network_address, netz.broadcast_address)
print(netz.num_addresses - 2, "nutzbare Adressen")

ip = ipaddress.ip_address("192.168.31.20")        # R1 nach dem Steuerungstausch
print(ip in netz)                                 # liegt die Adresse im Netz?
print(ipaddress.ip_address("192.168.30.11") in netz)

ip_text = "192.168.30.11"
print(f"{ip_text:15}|")                           # Breite 15: mit Leerzeichen aufgefüllt
  • ip_network("…/24") baut ein Netz, ip_address("…") eine einzelne Adresse. Der Operator in fragt, ob die Adresse im Netz liegt (der Rechner macht das UND aus der Lerneinheit).
  • num_addresses zählt alle Adressen des Netzes. Zwei sind nicht für Geräte: die Netzadresse (ganz unten) und die Broadcast-Adresse (ganz oben). Darum num_addresses - 2.
  • Ist der Text keine Adresse ("192.168.30.300"), gibt es einen ValueError.
  • Neu im f-String: {m['id']:4} heißt „mindestens 4 Zeichen breit, links bündig, mit Leerzeichen aufgefüllt“. So stehen Tabellenspalten untereinander. Die Zahl hinter dem Doppelpunkt ist die Spaltenbreite.
  • Ohne diese Bibliothek: Text-Vergleiche wie startswith("192.168.3") sehen richtig aus und sind falsch (siehe Code-Review).

PAP: Adresse prüfen

Bevor du die Prüfung programmierst, zeichnest du den Plan. Das ist ein Teil der Zellenprüfung aus dem Beispiel, nur ohne Bibliothek: Zwei Zahlen rein, ein Urteil raus. Die Prüfung erzeugt aus deinem PAP Python-Code und testet ihn mit mehreren Adressen, auch mit den Randwerten.

Adresse im Zellennetz prüfen

Zeichne einen PAP. Die Adresse hat die Form 192.168.dritte.vierte. Das Zellennetz ist 192.168.30.0/24. Eingaben sind das dritte und das vierte Oktett als ganze Zahlen (stehen schon da). Zuerst prüfst du den Hostanteil: Ist das vierte Oktett 0 (Netzadresse) oder 255 (Broadcast), gibst du "keine Geräteadresse" aus. Sonst liegt die Adresse im Netz, wenn das dritte Oktett 30 ist: Ausgabe "im Netz", andernfalls "falsches Netz". Texte stehen in Anführungszeichen, die Bedingungen schreibst du als Python-Ausdruck, zum Beispiel vierte == 0 or vierte == 255.

  1. Nach den zwei Eingaben kommt eine Raute mit der Bedingung für den Hostanteil: vierte == 0 or vierte == 255. Im „ja“-Zweig steht die Ausgabe "keine Geräteadresse" (mit Anführungszeichen).
  2. Im „nein“-Zweig kommt die zweite Raute: dritte == 30. „ja“: Ausgabe "im Netz", „nein“: Ausgabe "falsches Netz".
  3. Die Prüfung auf 0 und 255 steht vorn: Eine Broadcast-Adresse ist in keinem Netz ein Gerät, auch nicht im richtigen.

Die vier Fehler

Fehler 1: Text-Vergleich statt Netz-Prüfung (Zeile 10)

Die Zeile fragt, ob die Adresse mit "192.168.3" beginnt. Das gilt für 192.168.30.x, aber auch für 192.168.31.20, den Roboter R1 mit der falschen Adresse, und für 192.168.39.x. Das Programm meldet also „im Netz“ und lässt genau den Fehler durch, den es finden soll. Es gibt keine Fehlermeldung, nur ein falsches Ergebnis. Lösung: ipaddress.ip_address(m["ip"]) in ipaddress.ip_network(zelle["netz"]). Eine Bibliothek, die Netzmasken versteht, ist besser als ein Textvergleich.

Fehler 2: keine Statusprüfung (Zeile 7)

Der Prompt verlangt, vor dem Auswerten zu prüfen, ob die Anfrage geklappt hat. Die KI ruft sofort .json() auf. Bei Status 404 oder 500 steht in der Antwort eine Fehlerseite statt JSON, und das Programm bricht mit einem JSONDecodeError ab, ohne dass man den Grund sieht. Lösung: if antwort.status_code != 200: mit einer verständlichen Meldung und Abbruch, erst danach .json().

Fehler 3: json.load statt .json() (Zeile 17)

json.load erwartet eine Datei, d2 ist aber eine requests-Antwort. Das gibt einen AttributeError (die Antwort hat keine Methode read). Lösung: daten = d2.json(). Merke: load/dump für Dateien, loads/dumps für Text, antwort.json() für eine HTTP-Antwort.

Fehler 4: erfundener Schlüssel (Zeile 18)

In D2.json heißt der Schlüssel "temperatur_spindel_c", nicht "temperatur_c". Die KI hat den Namen geraten und nie in die Daten geschaut. Es gibt einen KeyError. Lösung: daten["temperatur_spindel_c"]. Bei KI-Code zu Daten gilt: Jeder Schlüssel muss in den echten Daten vorkommen.

Typische Fehlermeldungen

Mit Daten aus dem Netz kommen neue Fehlermeldungen. Diese sechs siehst du garantiert. Jedes Beispiel lässt sich ausführen: Schau dir die echte Meldung an und lies sie von unten nach oben (zuerst die letzte Zeile).

KeyError: Schlüssel fehlt

Meldung: KeyError: 'temperatur_c'. Das Dictionary hat diesen Schlüssel nicht (es heißt temperatur_spindel_c). Schau in die echten Daten, ob der Name stimmt (print(d2.keys())), oder nimm .get("temperatur_c", 0), wenn das Fehlen normal ist.

TypeError: Liste mit Text-Schlüssel angesprochen

Meldung: TypeError: list indices must be integers or slices, not str. zelle["maschinen"] ist eine Liste, und eine Liste kennt nur Nummern, keine Namen. Entweder mit Nummer ([0]) oder mit einer Schleife über die Liste und dann m["id"]. Die Meldung sagt dir, was du hast (Liste) und was du übergeben hast (Text).

json.JSONDecodeError: kein gültiges JSON

Meldung: JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 2 (char 1). JSON will doppelte Anführungszeichen. Ebenso gibt es einen Fehler bei einem Komma nach dem letzten Eintrag ({"a": 1,}). Der Fehler ist ein ValueError, also mit except ValueError abfangbar. Die Zahlen am Ende zeigen die Stelle.

TypeError: loads bekommt kein Text

Meldung: TypeError: the JSON object must be str, bytes or bytearray, not dict. loads macht aus Text ein Dictionary; hier ist es schon eines. Typisch nach antwort.json(): Das Ergebnis ist bereits ein Dictionary, ein zweites loads ist falsch.

ValueError: keine IP-Adresse

Meldung: ValueError: '192.168.30.300' does not appear to be an IPv4 or IPv6 address. Jeder der vier Blöcke ist ein Byte (0 bis 255, V02). Dasselbe passiert bei drei statt vier Blöcken oder mit einem Tippfehler.

.json() auf einer 404-Antwort

Meldung: ein JSONDecodeError: Expecting value: line 1 column 1 (char 0), bei requests je nach Version unter dem Namen requests.exceptions.JSONDecodeError. Die Zeile davor hat schon gezeigt, was los ist: Status 404. Die Antwort ist eine Fehlerseite, kein JSON. Die Meldung von .json() klingt nach „kaputtes JSON“, die Ursache liegt aber in der Adresse. Darum erst den Status prüfen.

Wartungsmeldung als JSON bauen

Die Instandhaltung bekommt Wartungsmeldungen als JSON-Text (auf dem Topic fz3/D2/wartung). Erwartet

Liegt die Adresse im Netz?

Schreibe die Funktion im_netz(ip, netz). Beide Parameter sind Text ("192.168.31.20", "192.168.30.0/24"). Die Funktion gibt True zurück, wenn die Adresse im Netz liegt, sonst False. Verwende die Bibliothek ipaddress. Die Tests probieren verschiedene Präfixe aus (/8, /16, /24, /26).

Erwartet
im_netz("192.168.30.11", "192.168.30.0/24") -> True
im_netz("192.168.31.20", "192.168.30.0/24") -> False
  1. Beide Eingaben sind Text. Mach aus dem Text eine Adresse (ipaddress.ip_address(ip)) und aus dem Netz-Text ein Netz (ipaddress.ip_network(netz)).
  2. Der Operator in liefert schon True oder False: adresse in netz.
  3. Also genügt eine Zeile: return ipaddress.ip_address(ip) in ipaddress.ip_network(netz). Ein Textvergleich mit startswith besteht die Tests mit /26 und /8 nicht.

Wartungsliste aus verschachtelten Daten

Die Instandhaltung will wissen, welche Werkzeuge über der Verschleißgrenze liegen. details ist ein Dictionary: Schlüssel ist die Maschinen-ID, Wert das Detail-Dictionary wie aus D2.json (mit "werkzeugverschleiss_prozent", einem Dictionary Werkzeug zu Prozent). Schreibe wartungsliste(details, grenze=80): Sie gibt eine Liste von Tupeln (maschine, werkzeug, prozent) zurück für jedes Werkzeug mit Verschleiß über der Grenze, in der Reihenfolge der Daten. Maschinen ohne diesen Schlüssel (der Roboter, die Messmaschine) werden übersprungen.

Erwartet
wartungsliste(details) -> [("D2", "T4", 83)]
wartungsliste(details, 40) -> [("D2", "T4", 83), ("F1", "T1", 47)]
  1. Zwei Schleifen ineinander: außen über die Maschinen (for maschine, daten in details.items():), innen über die Werkzeuge der Maschine (for werkzeug, prozent in ….items():).
  2. Das innere Dictionary holst du mit daten.get("werkzeugverschleiss_prozent", {}). Fehlt der Schlüssel, bekommst du ein leeres Dictionary, die innere Schleife läuft nullmal, und es gibt keinen KeyError.
  3. Gesammelt wird mit liste.append((maschine, werkzeug, prozent)): Die doppelten Klammern bauen ein Tupel. Bedingung: prozent > grenze (nicht >=).

Zellenbericht: Stückzahl der Schicht

Schreibe schichtsumme(url): Die Funktion holt url + "maschinen.json", dann für jedes Gerät die Datei url + id + ".json" und addiert deren stueckzahl_schicht. Hat ein Gerät keinen solchen Schlüssel, zählt es als 0. Für die Zelle FZ-3 kommt 546 heraus. Die Tests rufen die Funktion auch mit der Adresse einer zweiten, kleineren Zelle auf.

Erwartet
schichtsumme("../assets/data/v17/api/") -> 546
  1. Die Geräteliste: zelle = requests.get(url + "maschinen.json").json(), dann for m in zelle["maschinen"]:.
