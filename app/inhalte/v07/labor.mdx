<span class="a-syntax__label">Syntax-Karte 1</span>

<h4 id="sk-def">def und Aufruf: eine Funktion anlegen und benutzen</h4>

```python
import math

def widerstandsmoment(d):
    return math.pi * d ** 3 / 16

w = widerstandsmoment(30)
print(w)
print(widerstandsmoment(40) / widerstandsmoment(20))
```

- Der **Kopf**: `def`, der Name, die Parameter in Klammern und ein **Doppelpunkt**. Der <Begriff e="Der Rumpf ist der eingerückte Block unter def. Er läuft erst, wenn die Funktion aufgerufen wird.">Rumpf</Begriff> steht **eingerückt** (4 Leerzeichen). Was nicht mehr eingerückt ist, gehört zum Hauptprogramm.
- `def` führt nichts aus, es legt die Funktion nur an. Probiere es: Lösche die drei Zeilen darunter, dann gibt es keine Ausgabe. Der Rumpf läuft erst beim <Begriff e="Ein Aufruf führt eine Funktion aus: Name und in Klammern die Argumente, zum Beispiel tau(98.8, 30).">Aufruf</Begriff> `widerstandsmoment(30)`.
- Der Aufruf ist ein Ausdruck: Sein Wert steht dort, wo du ihn schreibst, in einer Zuweisung (`w = ...`), in `print` oder mitten in einer Rechnung. Die letzte Zeile zeigt das: doppelter Durchmesser, achtfaches Widerstandsmoment (d hoch drei).
- Die Funktion muss **vor** dem Aufruf definiert sein. Namen wählst du wie bei Variablen (V01): klein, mit Unterstrich, am besten eine Größe oder ein Verb.

</article>

<article class="a-syntax" aria-labelledby="sk-param">

<span class="a-syntax__label">Syntax-Karte 2</span>

<h4 id="sk-param">Parameter und Argumente: positionell und mit Namen</h4>

```python
def tau(T, d):
    return T * 1000 / (3.1416 * d ** 3 / 16)

print(tau(98.8, 30))
print(tau(d=30, T=98.8))
print(tau(98.8, d=30))
print(tau(30, 98.8))
```

- Ein <Begriff e="Ein Parameter ist ein Platzhalter-Name in der Klammer der Funktion, zum Beispiel d in def widerstandsmoment(d).">Parameter</Begriff> steht in der Klammer bei `def` (`T`, `d`), ein <Begriff e="Ein Argument ist der konkrete Wert beim Aufruf, zum Beispiel 30 in widerstandsmoment(30). Er landet im Parameter.">Argument</Begriff> ist der Wert beim Aufruf (`98.8`, `30`).
- **Positionell**: Das erste Argument geht an den ersten Parameter, das zweite an den zweiten. **Mit Namen**: `d=30` sagt selbst, wohin der Wert gehört, die Reihenfolge ist dann egal. Beides darf gemischt werden, die positionellen kommen zuerst.
- Die letzte Zeile hat die Argumente vertauscht: `T = 30` und `d = 98.8`. Python meldet **nichts**, es sind ja zwei Zahlen. Das Ergebnis ist trotzdem falsch (0.16 MPa statt 18.6, schon ein Überschlag zeigt, dass das nicht stimmen kann). Bei mehreren Parametern lohnt sich der Aufruf mit Namen.
- Zu wenige oder zu viele Argumente gibt einen `TypeError` (siehe „Typische Fehlermeldungen“).

</article>

<article class="a-syntax" aria-labelledby="sk-return">

<span class="a-syntax__label">Syntax-Karte 3</span>

<h4 id="sk-return">return und print: zurückgeben oder nur anzeigen</h4>

```python
def verdopple_a(x):
    print(2 * x)

def verdopple_b(x):
    return 2 * x

a = verdopple_a(5)
b = verdopple_b(5)
print("a =", a, " b =", b)
print(b + 1)
```

- `return` gibt den Wert an den Aufrufer zurück und **beendet die Funktion sofort**. Zeilen danach im Rumpf laufen nicht mehr. `print` zeigt den Wert nur auf dem Bildschirm an.
- Die erste Funktion zeigt 10 an, gibt aber nichts zurück. Darum ist `a` gleich <Begriff e="None ist der Python-Wert für „nichts“. Eine Funktion ohne return gibt None zurück.">None</Begriff>, der Python-Wert für „nichts“. Rechne mit `a + 1`, dann kommt ein `TypeError`. Das ist der häufigste Anfängerfehler und ein klassischer KI-Fehler.
- Faustregel: **Funktionen rechnen und geben zurück, das Hauptprogramm gibt aus.** Dann kannst du jede Funktion in anderen Rechnungen weiterverwenden.
- Mit `if` und `else` braucht **jeder Weg** ein `return`. Läuft eine Funktion ans Ende, ohne dass ein `return` erreicht wurde, gibt sie still `None` zurück.

</article>

<article class="a-syntax" aria-labelledby="sk-default">

<span class="a-syntax__label">Syntax-Karte 4</span>

<h4 id="sk-default">Default-Werte: Standardwert für einen Parameter</h4>

```python
def pruefe(tau_vorh, tau_zul=40.0):
    if tau_vorh <= tau_zul:
        return "ok"
    else:
        return "zu hoch"

print(pruefe(30))
print(pruefe(30, 25.0))
print(pruefe(30, tau_zul=35.0))
```

- Mit `tau_zul=40.0` im Kopf legst du einen <Begriff e="Ein Default-Wert ist ein Standardwert für einen Parameter. Wird beim Aufruf nichts angegeben, gilt er.">Default-Wert</Begriff> fest. Beim Aufruf `pruefe(30)` fehlt das zweite Argument, dann gilt 40.0. Wer es angibt, überschreibt den Standard, nur für diesen Aufruf.
- Parameter **mit** Default-Wert stehen immer **hinter** den Parametern ohne: `def f(a, b=1)` geht, `def f(a=1, b)` ist ein `SyntaxError`.
- Sinnvoll sind Defaults für Werte, die fast immer gleich sind: ein Grenzwert, eine Dichte, ein Sicherheitsbeiwert. Wer sie ändern will, nennt den Parameter beim Aufruf: `tau_zul=35.0`.
- Default-Werte sind Zahlen, Texte oder Wahrheitswerte. Listen als Default kommen nicht vor (Listen lernst du in V08).

</article>

<article class="a-syntax" aria-labelledby="sk-doc">

<span class="a-syntax__label">Syntax-Karte 5</span>

<h4 id="sk-doc">Docstring und Typ-Hinweise: das Datenblatt (Hinweise nur lesen)</h4>

```python
def tau(T: float, d: float) -> float:
    """Torsionsspannung in MPa aus Moment T in N·m und Durchmesser d in mm."""
    return T * 1000 / (3.14159 * d ** 3 / 16)

help(tau)
print(tau(98.8, 30))
```

- Der <Begriff e="Ein Docstring ist ein Text in dreifachen Anführungszeichen direkt unter der def-Zeile: das Datenblatt der Funktion mit Einheiten.">Docstring</Begriff> steht direkt unter dem `def` in dreifachen Anführungszeichen. Er sagt, **was** die Funktion tut und in **welchen Einheiten**. Einheitenfehler (kW statt W) fallen so früher auf. `help(tau)` zeigt ihn an.
- Die Zeichen `T: float` und `-> float` heißen **Typ-Hinweise**: T und d sind Kommazahlen, das Ergebnis auch. Python prüft sie beim Ausführen **nicht**. Du musst sie nur **lesen** können: KI-Code ist voll davon. In den Aufgaben schreibst du sie nicht.
- Ein Kommentar mit `#` erklärt eine Zeile, ein Docstring beschreibt die ganze Funktion.

</article>

<article class="a-syntax" aria-labelledby="sk-lokal">

<span class="a-syntax__label">Syntax-Karte 6</span>

<h4 id="sk-lokal">Lokale Variablen und Gültigkeitsbereich</h4>

```python
def quadrat(x):
    ergebnis = x * x
    return ergebnis

x = 3
a = quadrat(7)
print(a, x)
print(ergebnis)
```

- `x` und `ergebnis` in der Funktion sind <Begriff e="Lokal heißt: nur innerhalb der Funktion bekannt. Nach dem Aufruf sind lokale Variablen weg.">lokal</Begriff>: Sie entstehen beim Aufruf und sind danach weg. Das `x = 3` im Hauptprogramm ist eine *andere* Variable mit demselben Namen: `print(a, x)` zeigt 49 und 3.
- Die letzte Zeile gibt einen `NameError`, denn das Hauptprogramm kennt `ergebnis` nicht. Wer den Wert braucht, nimmt den Rückgabewert (`a`).
- Gewöhnung: Eine Funktion bekommt **alles, was sie braucht, als Parameter** und gibt **ihr Ergebnis mit return** ab. Dann kannst du sie ohne Nebenwirkungen überall benutzen und einzeln prüfen.
- Der Visualisierer („Schritt für Schritt“) zeigt jeden Aufruf als eigenen Frame mit seinen Variablen. Beobachte, wie die Frames beim `return` verschwinden.

</article>

<article class="a-syntax" aria-labelledby="sk-stapel">

<span class="a-syntax__label">Syntax-Karte 7</span>

<h4 id="sk-stapel">Funktion ruft Funktion: der Aufrufstapel</h4>

```python
import math

def widerstandsmoment(d):
    return math.pi * d ** 3 / 16

def tau(T, d):
    return T * 1000 / widerstandsmoment(d)

spannung = tau(98.8, 30)
print(f"{spannung:.1f} MPa")
```

- `tau` ruft `widerstandsmoment` auf. Beim Aufruf von `tau` liegt ein Frame auf dem <Begriff e="Der Aufrufstapel merkt sich, welche Funktion gerade läuft und von wem sie aufgerufen wurde.">Aufrufstapel</Begriff>, beim Aufruf von `widerstandsmoment` ein zweiter darauf. Mit „Schritt für Schritt“ siehst du den Stapel wachsen und schrumpfen.
- So baust du große Programme aus kleinen Bausteinen: Jede Funktion hat eine Aufgabe, die übergeordnete verknüpft sie. Das Hauptprogramm erzählt dann die Geschichte in wenigen Zeilen.
- Jede Funktion prüfst du **einzeln** mit einem Wert, den du von Hand nachrechnen kannst: `widerstandsmoment(30)` muss 5301.4 sein, `tau(98.8, 30)` muss 18.6 sein. Erst dann vertraust du dem Zusammenspiel.

</article>

### Die drei Fehler

#### Fehler 1: kW statt W, es fehlt \* 1000 (Zeile 5)

`return P / omega` teilt die Leistung in *Kilowatt* durch die Winkelgeschwindigkeit. Das Moment in N·m braucht aber Watt: `P * 1000 / omega`. Ohne den Faktor ist das Moment um den Faktor 1000 zu klein (0.1 statt 98.8 N·m). Das Programm läuft fehlerfrei: Einheitenfehler findest du nur durch Überschlag und mit dem Docstring (Einheiten hineinschreiben!).

#### Fehler 2: Argumente vertauscht (Zeile 21)

`tau(d, T)` übergibt den Durchmesser als Moment und das Moment als Durchmesser, denn die Funktion erwartet `tau(T, d)`. Beides sind Zahlen, Python meldet nichts. Heraus kommen absurde Spannungen. Gegenmittel: Aufruf mit Namen (`tau(T=T, d=d)`) und den Überschlag im Kopf. Hier hängen die zwei Fehler zusammen: Weil beide Werte falsch sind, sehen die Ergebnisse noch unsinniger aus, und trotzdem läuft alles durch.

#### Fehler 3: Zweig ohne return (Zeilen 16 und 17)

Die Funktion `bewerte` kennt „ok“ und „kritisch“, aber für alles darüber (also „zu hoch“) gibt es keinen Zweig. Python erreicht das Ende der Funktion ohne `return` und gibt still `None` zurück: In der Ausgabe steht „-\> None“. Lösung: ein `else:` mit `return "zu hoch"`. Jeder Weg durch die Funktion braucht ein `return`.

### Die KI-Version zum Ausprobieren

<p class="k-small k-muted">Alle drei Ausgaben sind falsch: Spannungen im Bereich von 1e8 MPa und „None“ statt eines Urteils.</p>

```python
import math

def torsionsmoment(P, n):
    omega = 2 * math.pi * n / 60
    return P / omega

def widerstandsmoment(d):
    return math.pi * d ** 3 / 16

def tau(T, d):
    return T * 1000 / widerstandsmoment(d)

def bewerte(tau_vorh, tau_zul=40.0):
    if tau_vorh <= tau_zul:
        return "ok"
    elif tau_vorh <= 1.2 * tau_zul:
```
